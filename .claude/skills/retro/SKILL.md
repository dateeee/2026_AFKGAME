# 振り返り（retro）

効率メモに蓄積された「非効率だったやり取り」を原因別に整理し、
再発を防ぐ改善としてスキル・プロファイル・成果物へ反映する。
**メモを消化する唯一の出口**であり、エントリは反映と同時に削除して溜め込まない。

## 0. 最初に読む

| 順 | ファイル | 内容 |
|----|---------|------|
| 1 | `.claude/project/profile.md` | コスト規律・ディレクトリ |
| 2 | `.claude/project/retro.md` | 効率メモのパス・検出しきい値・反映先マップ・削除ルール |

## 1. エントリの整理

1. プロファイルが指す効率メモを読む（引数があれば該当エントリに絞る。**他の仕様書・コードはまだ読まない**）
2. エントリを原因の型で分類する

| 原因の型 | 反映先 |
|---------|-------|
| 手順の欠落・曖昧さ（どのプロジェクトでも起きる） | `.claude/skills/**`（一般手順のまま直す。固有値を混ぜない） |
| プロジェクト固有の値・参照先の欠落 | `.claude/project/**` |
| 成果物（仕様書・コード）自体の欠陥 | 該当する工程スキルを起動して修正 |
| フックの誤検出（正当な作業だった） | しきい値の調整、または対応不要 |

## 2. 改善の適用

1. エントリごとに「反映先ファイル + 修正案の要旨」を一覧で提示し、ユーザーの承認を得る
2. 承認されたものだけ適用する。1回の振り返りでは**効果の大きい原因から数件に絞る**
3. 大きな改稿・成果物の修正になる場合は本スキルで直さず、対象工程のスキルへ委譲する

## 3. 後始末

- 反映済み・対応不要のエントリを効率メモから**削除**する（履歴は Git が持つ）
- ドキュメントを改稿した場合は変更履歴へ1行追記し、プロファイル記載のドキュメント検査を実行する

## 注意事項

- サブエージェントを使わない（読むのはメモと改稿対象のみ）
- 同じ原因のエントリが繰り返し溜まる場合は、しきい値ではなく手順側（スキル・プロファイル）を疑う
- スキルの改稿は他プロジェクトへ無改造でコピーできる範囲に保つ（固有値はプロファイルへ）
