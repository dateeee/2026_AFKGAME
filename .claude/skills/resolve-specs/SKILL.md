# 未確定仕様の確定（resolve-specs）

未確定仕様を**ユーザーとの対話で1つずつ確定**し、仕様書へ反映する。要件定義（工程1）の一部。
確定後の整合性チェックは `requirements` スキル §5 の手順に従う。

## 0. 最初に読む

| 順 | ファイル | 内容 |
|----|---------|------|
| 1 | `.claude/project/profile.md` | ディレクトリ・不変条件（§5）・コスト規律 |
| 2 | `.claude/project/requirements.md` §4 | 進め方の固有ルール・カテゴリ別参照先・確定後の反映先 |

出力テンプレートは、**該当ステップに到達してから**プロファイルが指すテンプレート集を読む。

## 1. スコープの特定

引数で対象を絞る（Phase指定 / カテゴリ指定 / 個別項目名）。
引数が無い場合は未確定項目の一覧を提示して選んでもらう。**一覧表示の時点では仕様書を読まない。**

1回の実行で扱う件数はプロファイル §4 の上限に従う。超える場合は「続きは再実行してください」と案内して終了する。

## 2. 現状把握

対象項目ごとに、プロファイル §4 のカテゴリ対応表から参照先を特定し、**関連セクションのみ**読む。

1. 項目の文面・カテゴリから関連仕様書を推定する
2. Grep で見出し・キーワードを検索して行番号を特定する
3. Read の offset/limit で該当セクション周辺（100行程度）のみ読む

**全文Readは禁止。** 確定済み仕様から生じる制約を整理してから対話に入る。

## 3. 対話による確定

項目を1つずつ（密接に関連するものはグループで）提示する。

| # | ルール |
|---|-------|
| 1 | **必ず推奨案を明示する**。選択肢を並べるだけで終わらせない |
| 2 | ジャンル慣習・バランス・実装複雑度を判断材料として添える |
| 3 | 既存仕様と矛盾が生じる場合は**その場で明示**して判断を仰ぐ |
| 4 | 実装難易度が高い案は、その旨を伝えたうえで簡素な代替案も出す |
| 5 | 「後回し」「保留」はスキップして次へ進む |

数値バランスは**仮置きでも確定**し、実測での調整を前提に進める（「仮置き」と明記する）。

## 4. 仕様書への反映

反映前に「この内容で反映してよいですか？」と確認を取る。承認後、プロファイル §4「確定後の反映先」の順に実行する。

1. 該当仕様書へ反映（数値・計算式・分岐条件を**一意に**書く）
2. 変更履歴の集約ファイルへ追記（**仕様書側には書かない**）
3. 未確定管理ファイルから該当項目を**削除**する（チェック済みのまま残さない）
4. 数値のみ未定になったものは、調整待ち管理へ移す

## 5. 反映後の確認

| 対象 | 検証内容 |
|------|---------|
| 規約 | ドキュメント規約チェックが exit 0 か |
| 重複 | 確定した数値が複数ファイルへ二重に書かれていないか |
| 取りこぼし | 反映した内容に関連する他の未確定項目が残っていないか |

矛盾が見つかったら `requirements` スキル §5.3 の対応表に従う。**どちらが正か判断できないものは勝手に決めない。**

## 6. 完了報告

プロファイルが指すテンプレートに従い、確定した項目・反映先ファイル・残件数・次に扱うべき項目を報告する。

## 注意事項

- **サブエージェントを使わない**。すべてメインコンテキストで処理する
- ユーザーが選んでいない案を「確定」として書かない
- 全項目が確定したら、未確定管理ファイルの扱いはプロファイル §4 の指示に従う
