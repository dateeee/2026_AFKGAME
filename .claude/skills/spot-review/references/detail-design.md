# 詳細設計のレビュー観点（一般）

> 工程3「詳細設計（ローレベル設計）」の成果物（処理フロー・アルゴリズム・計算式・数値・分岐一覧・マスターデータ定義）に当てる**プロジェクト非依存**の観点。
> 固有の対象ファイル・上乗せ観点は `.claude/project/review/spot.md`。使い方は [SKILL.md](../SKILL.md) §2。

**この工程の問いは「読んだ人が同じ実装に到達するか」**。1つの記述から2通りの実装が生まれるなら指摘。

## 1. 観点表

| 分類 | # | 観点 | 典型的な兆候 |
|------|---|------|------------|
| 一意性 | 1 | 計算式が**一意に読める**か（演算順序・優先順位・括弧） | `a + b * c` の意図が文章と食い違う |
| 一意性 | 2 | **丸め**（切り捨て / 切り上げ / 四捨五入）の**方式・桁・回数・タイミング**が決まっているか | 「小数は丸める」だけ。途中で丸めるか最後かで結果が変わる |
| 一意性 | 3 | 数値の**型**（整数 / 小数）と単位が明示されているか | 秒とミリ秒が混在 |
| 一意性 | 4 | 境界の向き（以上 / 超過、以下 / 未満）が明記されているか | 「上限に達したら」の「達した」が両義 |
| 一意性 | 5 | 処理の**順序依存**が明示されているか | 加算と倍率適用の順が節ごとに違う |
| 網羅 | 6 | **分岐一覧が条件の両側**を持つか（真だけでなく偽の経路） | 「条件を満たす場合」だけが書かれている |
| 網羅 | 7 | 複数条件の**どれにも当たらない場合**が定義されているか | else が無く、素通り時の挙動が未定義 |
| 網羅 | 8 | **到達不能な分岐**が無いか | 前段のガードで排除済みの条件を再判定している |
| 網羅 | 9 | 0件・1件・複数件、0・負値・上限値の扱いが決まっているか | 空コレクション時の戻り値が未定義 |
| 網羅 | 10 | **null / 未設定 / 空文字 / 特別値**の意味が定義されているか | `null` が「無制限」なのか「未取得」なのか読めない |
| 例外 | 11 | 失敗時の**エラー種別・コード・応答**が決まっているか | 「エラーとする」だけ |
| 例外 | 12 | **部分的失敗**の扱い（どこまで確定し、どこから戻すか）が決まっているか | ループ途中の失敗で状態が中途半端に残る |
| 例外 | 13 | 再実行・重複実行時の**冪等性**が定義されているか | 二重実行で二重加算される |
| 外部要因 | 14 | 乱数・時刻・外部入力の**取得方法と消費回数**が決まっているか（再現性） | 分岐によって乱数消費数が変わり、再現できない |
| 外部要因 | 15 | 経過時間の計算に**基準時刻・端数の繰り越し**が定義されているか | 端数が毎回切り捨てられ、累積でずれる |
| 外部要因 | 16 | クランプ（上限打ち切り）・飽和・オーバーフロー時の挙動が決まっているか | 桁あふれを例外にするか飽和させるか未定 |
| データ | 17 | 定数・係数の**出所**が示されているか（マスターデータか実装定数か） | 同じ値が複数箇所に別々に書かれている |
| データ | 18 | マスターデータの**制約**（合計・一意・必須列・参照先の実在）が定義されているか | 重み合計が1にならないケースの扱いが無い |
| データ | 19 | 上位設計（工程2）の**データ構造・API 契約と矛盾**しないか | 詳細側だけで項目が増えている |
| 実装可能性 | 20 | 実装者が**追加判断なしに書ける**粒度か | 「適切に補正する」で終わっている |
| 実装可能性 | 21 | 計算量・処理件数の見積もりがあり、明らかな非効率が無いか | 全件×全件の二重ループが前提 |
| 実装可能性 | 22 | 排他・ロックの**粒度と取得順序**が決まっているか | 取得順が定義されずデッドロックしうる |

## 2. 見落とされやすいもの

| # | 内容 |
|---|------|
| 1 | **丸めの回数**。式ごとに丸めるか、最終結果で1回かで結果が変わる。「途中で丸めない」を明記させる |
| 2 | **境界そのもの**。`>=` と `>` の差が仕様で語られず、テストでも境界値が拾われない |
| 3 | **上限に達した後**。レベル上限・在庫上限に達した状態での加算・減算の扱い |
| 4 | **同時刻・同値のタイブレーク**。並び順・行動順が同値のときの決定規則 |
| 5 | **未実装として残す範囲**。「後続で実装する」と書いた箇所の解消条件と担当工程 |
| 6 | **分岐一覧とテストリストの対応**。一覧の行が増減したのにテスト側が追随していない |

## 3. 機械的に検証できる項目

| 対象 | 検証内容 |
|------|---------|
| 分岐一覧 | 各行に対応するテストが存在するか（ID突き合わせ） |
| 構造化データ | 重み・確率の合計、ID重複、参照先の実在、必須列の欠落 |
| 数値の重複定義 | 同じ定数が複数ファイルに書かれていないか（値の抽出と比較） |
| 計算例 | 設計書に載る計算例を実際に計算して一致するか |
| 相対リンク・節番号 | 参照先が実在するか |
