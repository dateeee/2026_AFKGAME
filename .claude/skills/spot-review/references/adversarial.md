# 敵対的検証（反証）の手順（一般）

> 一次レビューで挙げた指摘候補を、**反証を任務とする独立のエージェント**にかけて偽陽性を落とす手順。
> `spot-review` が [SKILL.md](../SKILL.md) §4 から使う。プロジェクト非依存。

**目的は指摘を減らすことではなく、「読んだ人が確認し直さなくてよい指摘」だけを残すこと。**
偽陽性は修正適用工程で手戻りを生み、レポート全体の信頼を落とす。**疑わしきは棄却**とする。

## 1. 対象と単位

| # | ルール |
|---|-------|
| 1 | 指摘候補は**重要度を問わず全件**かける（重要度が高いものだけ、にしない） |
| 2 | 1体のエージェントに**同じファイル群を根拠とする指摘をまとめて**割り当てる（読み込みの重複を避ける） |
| 3 | 同時実行数は**プロジェクト固有プロファイルのコスト規律**（`.claude/project/profile.md`）に従う。上限を超える件数は順に回す |
| 4 | モデルは `sonnet`。反証は原文照合が主体で、生成能力を要さない |
| 5 | 候補が0件なら反証は行わない |

## 2. 反証エージェントへ渡すもの

| 渡す | 渡さない |
|------|---------|
| 指摘候補の全文（タイトル・該当箇所・引用・修正案・重要度） | 一次レビューの思考過程・確信度 |
| 読んでよいファイルの**完全な列挙**（指摘の根拠と照合先） | 「この指摘は正しいはずだ」という前置き |
| 適用した観点の該当行（どの観点から出た指摘か） | 他の指摘の内容（相互補強を防ぐ） |

プロンプトには次を明記する。

- **任務は反証**。指摘を成立させないことを目指し、成立させる根拠は探さない
- **原文は自分で読んで確かめる**。指摘に書かれた引用を根拠として採用しない（引用自体の誤りを疑う）
- 列挙されたファイル以外は読まない
- 戻り値は §4 の判定と根拠のみ。原文引用は1〜3行

## 3. 反証の切り口

| # | 切り口 | 確かめること |
|---|-------|------------|
| 1 | **事実誤認** | 引用が原文と一致するか。行番号・節番号が指す先が本当にその内容か |
| 2 | **既出** | 別の箇所・別ファイルに既に規定・実装・ガード・バリデーションがあり、問題が成立しないのではないか |
| 3 | **前提の不成立** | 問題が起きる前提（その入力・その状態・そのコードパス）に実際に到達しうるか |
| 4 | **規約の実在** | 「規約違反」なら、根拠となる条文が実在し、対象へ適用される範囲か。解釈が拡大されていないか |
| 5 | **意図的な設計** | 逸脱に見える記述が、明文化された設計判断・例外規定によるものではないか |
| 6 | **担当違い** | 別スキル・別工程の担当範囲で、ここで挙げるべきでないのではないか |
| 7 | **修正案の副作用** | 修正案が新たな不整合・別の違反を生まないか。既存の呼び出し元・テスト・常設チェックを壊さないか |
| 8 | **重要度の過大** | 実害の有無・発生条件の希少さに照らして重要度が過大でないか |
| 9 | **一般論** | 対象に即した具体がなく、どのコード・どの文書にも当てはまる一般論になっていないか |

## 4. 判定

| 判定 | 条件 | 扱い |
|------|------|------|
| **棄却** | §3 のいずれかで指摘が崩れる。または崩れるとも成立するとも確かめられない | レポートへ載せない。件数のみ記録 |
| **要検討** | 指摘は成立するが、前提・影響範囲・修正案のいずれかを確認しきれない | 残す。ISSUE へ `（確度: 要検討）` と**未確認の点**を書く |
| **確証** | §3 の全切り口を通り、根拠を原文で確認できた | そのまま残す |
| **重要度の修正** | 指摘は成立するが重要度が過大 | 判定を下げて残す（理由をレポートへ1行） |

**既定は棄却**。判断が割れた場合・情報が足りない場合は棄却か「要検討」へ寄せ、「確証」へは寄せない。

## 5. 集約と記録

| # | 手順 |
|---|------|
| 1 | 生存した指摘だけを ISSUE として採番する（棄却分に番号を使わない） |
| 2 | サマリー表の下へ1行記す: `> 敵対的検証: 候補N件 → 生存M件（棄却K件・要検討L件）` |
| 3 | 反証で重要度を下げたものは、その ISSUE の説明末尾へ「反証: 〜のため重要度を下げた」と1行残す |
| 4 | **棄却率が高い（目安として半数超）場合**、一次レビューの観点の当て方が緩い。報告の最後に観点表・手順の改善案を添える |
| 5 | 棄却の理由に同じ切り口（§3 の番号）が集中する場合、その切り口を一次レビュー時の自己確認へ前倒しすることを提案する |

## 6. やってはいけないこと

| # | 内容 |
|---|------|
| 1 | 反証を**メインコンテキストの自己点検で代替**する（自分の指摘への確証バイアスが落ちない） |
| 2 | 反証エージェントに**指摘の正しさを説明させる**（任務が反転する） |
| 3 | 反証結果を受けて**指摘を言い換えて生き残らせる**（棄却は棄却として扱う。書き直したいなら次回の一次レビューで挙げ直す） |
| 4 | 棄却された指摘を**「低」に落として残す**（重要度は実害の大小であり、確からしさの逃げ場ではない） |
| 5 | 反証にかけずにレポートへ載せる（時間が無い場合は**対象を狭める**。反証を省かない） |
