# テストリスト作成のレビュー観点（一般）

> 工程4「テストリスト作成」の成果物（実装前の失敗するテスト＝TDDのRed・フィクスチャ・テスト対応表）に当てる**プロジェクト非依存**の観点。
> 固有の記述規約・上乗せ観点は `.claude/project/review/spot.md`。使い方は [SKILL.md](../SKILL.md) §2。

**この工程の問いは「このテストが通れば仕様を満たしたと言えるか」**。カバレッジの数値は工程6の担当。

## 1. 観点表

| 分類 | # | 観点 | 典型的な兆候 |
|------|---|------|------------|
| 網羅 | 1 | **分岐一覧の各行にテストが対応**しているか（欠落・余剰） | 一覧に行があるのにテストが無い |
| 網羅 | 2 | 正常系だけでなく**異常系・境界値・例外**がテスト化されているか | ハッピーパスのみ |
| 網羅 | 3 | 境界は**境界そのもの**を別ケースにしているか | 「上限-1」と「上限+1」だけで、上限ちょうどが無い |
| 網羅 | 4 | 0件・1件・複数件、null / 空の入力が含まれるか | 常に要素2件の固定データ |
| 網羅 | 5 | 対象範囲外の機能のテストを先取りしていないか | 後続フェーズの仕様をテストが要求している |
| 検証の質 | 6 | **期待値が仕様書の数値から導かれ**ているか（実装からの逆算でないか） | 「実行結果がこうなったので期待値にした」 |
| 検証の質 | 7 | アサーションが**結果の本質**を検証しているか | 例外が出ないことだけを確認している |
| 検証の質 | 8 | 例外は型だけでなく**コード・メッセージ・状態**まで検証しているか | `assertThrows` の型一致のみ |
| 検証の質 | 9 | **1テスト1検証**になっているか | 1メソッドで無関係な3つの振る舞いを確認 |
| 検証の質 | 10 | 副作用（永続化・呼び出し）の検証があるか | 戻り値だけ見て、保存されたかを見ていない |
| Red | 11 | **実際に失敗する**ことを確認したか（Red の実測） | 空実装でも通ってしまうテスト |
| Red | 12 | 失敗理由が「未実装」であり、テスト自身のバグでないか | 記述ミスで落ちているのをRedと呼んでいる |
| Red | 13 | スキップ・無効化されたテストが放置されていないか | `@Disabled` に理由と解消条件が無い |
| 独立性 | 14 | テスト間に**実行順序依存・共有状態**が無いか | 前のテストが作ったデータに依存する |
| 独立性 | 15 | 時刻・乱数・環境に依存せず**再現**するか | 実時刻・実乱数をそのまま使う |
| 独立性 | 16 | 後片付け（生成データの削除・状態の復元）があるか | 実行のたびにデータが増える |
| 記述 | 17 | テスト名が**仕様上の意味**で書かれているか（実装表現でない） | 「フラグがtrueの場合」 |
| 記述 | 18 | 対応する仕様の節番号・分岐IDが記録されているか | どの仕様を守るテストか読めない |
| 記述 | 19 | 準備・実行・検証の構造が読み取れるか | 準備と検証が混ざり、何を試したか不明 |
| フィクスチャ | 20 | フィクスチャが**最小**で、テストの意図に関係する値だけが目立つか | 無関係な項目まで埋めて差分が読めない |
| フィクスチャ | 21 | モックが**外部境界に限定**されているか（過剰モックでないか） | 検証対象自身をモックして仕様を検証していない |
| フィクスチャ | 22 | モックの戻り値が**現実に起こりうる値**か | 実装が返さない組み合わせを前提にしている |

## 2. 見落とされやすいもの

| # | 内容 |
|---|------|
| 1 | **「起きないはず」の経路**。ガードで弾かれる入力のテストが無く、ガードが消えても気づけない |
| 2 | **期待値の逆算**。実装後にテストを直した痕跡（期待値だけが変わったコミット） |
| 3 | **同値クラスの取りこぼし**。同じ分岐でも意味の違う入力（未知ID・削除済み・権限違い）が1つにまとめられる |
| 4 | **順序・重複**。同じ操作を2回した場合、順序を入れ替えた場合のテスト |
| 5 | **テストのためだけの本番コード**。テスト用フラグ・可視性の緩和が本番側に入る |

## 3. 機械的に検証できる項目

| 対象 | 検証内容 |
|------|---------|
| 分岐一覧との対応 | 一覧のIDとテストの参照IDを突き合わせ、欠落・余剰を列挙する |
| Red の実測 | テストを実行し、失敗件数と失敗理由の内訳を取り込む（目視で判断しない） |
| スキップ | 無効化されたテストの件数と理由の有無を列挙する |
| 命名規約 | テスト名・クラス名の規約違反を正規表現で列挙する |
| 重複 | 同一の入力・期待値を持つテストの重複を検出する |
