# 結合テストのレビュー観点（一般）

> 工程7「結合テスト」の成果物（API統合テスト・E2Eテスト・シナリオ定義）に当てる**プロジェクト非依存**の観点。
> 固有のレイヤ構成・必須シナリオは `.claude/project/review/spot.md`。使い方は [SKILL.md](../SKILL.md) §2。

**この工程の問いは「単体では検出できない連結部分を検証しているか」**。
単体で足りる検証を結合で重ねるのは無駄、逆に境界の不一致を単体で見たつもりになるのは危険。

## 1. 観点表

| 分類 | # | 観点 | 典型的な兆候 |
|------|---|------|------------|
| 連結 | 1 | コンポーネント境界の**型・必須性・命名の不一致**を検出できるか | 送信側と受信側の項目名が違っても緑になる |
| 連結 | 2 | 設計どおりの**状態コード・エラー応答形式**を検証しているか | 成功時の本文しか見ていない |
| 連結 | 3 | 認証・認可が**実際の経路で**効くことを検証しているか | 認証をモックで無効化している |
| 連結 | 4 | 設定・DI の結線（Bean・依存注入・ルーティング）が起動時に成立するか | 起動できることを誰も確かめていない |
| 連結 | 5 | 永続化層の**制約が実際に効く**か（一意・外部キー・NOT NULL） | インメモリ実装で制約が無視される |
| 連結 | 6 | スキーマ移行の適用結果とコードの期待が一致するか | 移行未適用のスキーマで通っている |
| シナリオ | 7 | **主要ユースケースが端から端まで**通っているか | 個別エンドポイントの単発呼び出しのみ |
| シナリオ | 8 | 状態遷移をまたぐ流れ（作成→更新→削除、再開・再実行）を検証しているか | 作成だけで終わる |
| シナリオ | 9 | **異常系シナリオ**（不正入力・権限不足・期限切れ・存在しないID）があるか | 正常系のみ |
| シナリオ | 10 | 外部依存の**失敗・遅延・タイムアウト**時の挙動を検証しているか | 外部は常に成功する前提 |
| シナリオ | 11 | 同時実行・重複送信・順序逆転のシナリオがあるか | 逐次実行しか試していない |
| シナリオ | 12 | 単体テストとの**重複が過剰でない**か（結合でしか見えないものに絞れているか） | 計算式の網羅を結合で繰り返す |
| データ | 13 | テストデータが**テストごとに独立**しているか | 前のテストの残骸に依存する |
| データ | 14 | 実行後の**後片付け**があり、繰り返し実行できるか | 2回目から一意制約で落ちる |
| データ | 15 | 初期データ（マスターデータ）が本番と同じ供給元から来ているか | テスト専用の別データで通している |
| データ | 16 | 検証が**永続化された結果**まで見ているか | 応答だけ見て保存内容を見ない |
| 安定性 | 17 | 待機が**条件待ち**になっているか（固定待機に頼っていないか） | `sleep` でタイミングを合わせている |
| 安定性 | 18 | 時刻・タイムゾーン・ロケール・文字コードに依存しないか | 実行環境が変わると落ちる |
| 安定性 | 19 | ポート・DB・一時ファイルが他の実行と衝突しないか | 並行実行できない |
| 安定性 | 20 | 失敗時に原因を特定できる情報（ログ・スクリーンショット・応答本文）が残るか | 「アサーション失敗」だけ |
| 保守 | 21 | 画面操作の指定が壊れにくい方法か（表示文言・レイアウト依存でないか） | 文言変更で全E2Eが落ちる |
| 保守 | 22 | シナリオが仕様のどの節に対応するか記録されているか | 何を守っているか読めない |

## 2. 見落とされやすいもの

| # | 内容 |
|---|------|
| 1 | **境界のモック化で検証が消える**。結合テストなのに境界をモックし、単体テストと同じものを見ている |
| 2 | **成功時しか見ない永続化**。エラー時にロールバックされたことを確認していない |
| 3 | **再実行不能**。CI で1回目だけ通り、ローカルの2回目で落ちる |
| 4 | **設定差**。テスト用設定でだけ有効な緩和（認証無効・制約無効）が本番の問題を隠す |
| 5 | **長すぎるシナリオ**。1本に詰め込みすぎて、落ちた箇所から原因を特定できない |
| 6 | **削除・失効の経路**。作成と参照は試されるが、削除後の参照・期限切れ後の利用が抜ける |

## 3. 機械的に検証できる項目

| 対象 | 検証内容 |
|------|---------|
| 実行結果 | テスト実行の成功・失敗・スキップ件数と失敗内訳を取り込む |
| 契約 | API 定義（スキーマ）と実際の応答を突き合わせる |
| シナリオ網羅 | 設計書のユースケース一覧とテストの対応表を突き合わせ、欠落を列挙する |
| 固定待機 | 固定時間待機の使用箇所を静的に列挙する |
| 独立性 | テストの実行順序を入れ替えて結果が変わらないか確認する |
| 環境依存 | 実行環境の設定（TZ・ロケール）を変えて再実行し、差が出ないか確認する |
