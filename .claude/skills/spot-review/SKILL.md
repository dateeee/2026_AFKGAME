# 対象指定レビュー（spot-review）

指定された**ファイル・フォルダ・工程**を、その工程の**一般観点**でレビューする。
指摘は**すべて敵対的検証（反証）にかけ**、生き残ったものだけをレポートへ載せる。**修正は行わない**（指摘のみ）。

ゲート（製造完了・Phase完了）に紐づく定型レビューは既存の5スキルが担当する。本スキルは**対象を毎回指定する**点が違う（§5）。

## 0. 最初に読む

| 順 | ファイル | 内容 |
|----|---------|------|
| 1 | `.claude/references/review-procedure.md` | 準備スクリプト・機械的検証・指摘の書き方・出力 |
| 2 | `.claude/project/profile.md` | 技術スタック（§3）・不変条件（§5）・コスト規律（§6） |
| 3 | `.claude/project/review.md` | 共通パラメータ（§1）・重要度の共通軸（§2） |
| 4 | `.claude/project/review/spot.md` | パラメータ（§0）・対象↔工程の対応（§1）・上乗せする固有観点（§2）・重要度（§3） |
| 5 | `references/<工程>.md` | **§2 で確定した工程の観点のみ**。複数工程にまたがる場合だけ複数読む |
| 6 | `references/adversarial.md` | 敵対的検証の手順。**§4 に入る直前**に読む |

観点ファイル名は**工程スキル名と同じ**。`requirements` / `basic-design` / `detail-design` / `test-list` / `dev` / `unit-test` / `integration-test`。

## 1. 引数

| 引数 | 動作 |
|------|------|
| パス（ファイル / フォルダ） | そのパスを対象にする。複数指定可 |
| 工程名（`要件定義` `基本設計` `詳細設計` `テストリスト` `製造` `単体テスト` `結合テスト`） | review/spot.md §1 の対応表からパスを引いて対象にする |
| なし | **対象が不明。パスか工程名を尋ねて終了する**（既定の対象を勝手に決めない） |
| `full` | 指定対象の全量（既定） |
| `diff` | 指定対象のうち、前回 spot-review 以降に変更されたファイルのみ |
| その他 | 追加観点・スコープ指定として扱う（例: `境界値重点`） |

## 2. 手順

| 順 | 手順 |
|----|------|
| 1 | **対象の確定**。引数のパス・工程名を review/spot.md §1 の対応表で突き合わせ、**対象工程**と**対象ファイル一覧**を確定する。1つの対象が複数工程に当たる場合は当たった工程をすべて採る |
| 2 | **確定内容をユーザーへ1行で提示してから進む**（例: 「対象: `docs/tech/detail/` 12ファイル / 工程: 詳細設計 / モード: 全量」）。ファイル数が20を超える場合は絞り込みを提案する |
| 3 | **準備**。review/spot.md §0 のコマンドで `review_prep.py` を実行する（`--paths` は §1 で確定した対象、既定は `--full`、引数 `diff` のときだけ外す）。`ISSUE_START` `REPORT_PATH` `MODE_LINE` を取り込む |
| 4 | **機械的検証を先に走らせる**（review-procedure.md §5）。常設スクリプトの出力をそのまま取り込み、そこで判定済みの項目は目視で重ねて探さない |
| 5 | **観点の読み込み**。§0 の 5 に従い、確定した工程の `references/<工程>.md` を読む。加えて review/spot.md §2 の固有観点を上乗せする |
| 6 | **一次レビュー**。観点表を1行ずつ対象へ当て、指摘候補を作る。書き方は review-procedure.md §6 |
| 7 | **敵対的検証**（§4）。指摘候補を反証にかけ、生存したものだけを残す |
| 8 | **出力**（§3）。review-format.md の形式で `REPORT_PATH` へ保存し、ローテーションを実行して報告する |

## 3. 出力

review-format.md の形式に従い、以下を上乗せする。

- モード行の**直下**へ対象行を1行足す（`> 対象: <パス...> / 工程: <工程名>`）。モード行自体は `MODE_LINE` をそのまま貼り、書き換えない
- サマリー表の下へ**反証の結果**を1行記す（`> 敵対的検証: 候補N件 → 生存M件（棄却K件・要検討L件）`）
- 反証で「要検討」となった指摘は、ISSUE表の重要度の後ろへ `（確度: 要検討）` を付ける
- 棄却された指摘は**レポートへ載せない**（件数のみ上記の行に残す）

## 4. 敵対的検証

`references/adversarial.md` に従う。要点のみ再掲する。

- 指摘候補は**重要度を問わず全件**反証にかける。反証エージェントの既定判定は「棄却」
- 反証は `model: sonnet` のサブエージェントで行う。同時実行数の上限は profile.md §6 規律1 に従う
- 反証は「分担」ではないため、review-procedure.md §1 規律2（分担は全量モードのみ）の対象外。差分モードでも実施する
- 反証エージェントには**担当する指摘の全文**と**読んでよいファイルの列挙**だけを渡す。原文は自分で読ませ、指摘の根拠を鵜呑みにさせない
- 候補が0件なら反証は行わず、「指摘なし」でレポートを保存する

## 5. 注意事項

- **既存レビュー系5スキルと重複計上しない**。ゲートで動く定型レビュー（`doc-review` `diagrams-review` `backend-review` `frontend-review` `full-review`）が担当する範囲は review-procedure.md §7 が正。本スキルはその**範囲外・またはゲート外のタイミング**で使う。同じ対象を直近で定型レビュー済みなら、その旨を伝えて実施可否をユーザーへ確認する
- 設計図（Mermaid）が絡む照合は `diagrams-review` の担当。本スキルでは扱わない
- 観点ファイル（`references/**`）は**プロジェクト非依存**に保つ。固有の値・固有の観点は `.claude/project/review/spot.md` へ書く
- 観点表に無い問題を見つけた場合は指摘として挙げたうえで、**観点表への追加案**を報告の最後に添える（観点を育てる）
- **修正を自動適用しない**。レポートを保存して終了する
