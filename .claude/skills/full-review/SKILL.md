# フルスタック統合レビュー（full-review）

**仕様書↔コード**と**フロント↔バック**にまたがる乖離を検出する。**修正は行わない**（指摘のみ）。
片側だけで閉じるコード品質の問題は `backend-review` / `frontend-review` の担当。

## 0. 最初に読む

| 順 | ファイル | 内容 |
|----|---------|------|
| 1 | `.claude/references/review-procedure.md` | 準備スクリプト・モード判定・機械的検証・指摘の書き方・出力 |
| 2 | `.claude/project/profile.md` | ディレクトリ・技術規約（§3）・**不変条件（§5）**・コスト規律 |
| 3 | `.claude/project/review-fullstack.md` | パラメータ・対象・照合先・観点・機械的検証・重要度基準 |

索引 + 個別ファイル構成のため、**照合に必要な個別ファイルのみ**読む。

## 1. 引数

| 引数 | 動作 |
|------|------|
| なし | **差分モード**（既定） |
| `full` | 全量モード（サブエージェントは最大3体・`sonnet`） |
| その他 | スコープまたは追加観点として扱う |

## 2. 手順

review-procedure.md を §2 準備（`review_prep.py` 実行）→ §3 差分モードの対象特定 / §4 全量モードの分担 → §5 機械的検証 → §6 指摘の書き方 → §8 出力と報告 の順に実行する。

| 項目 | 参照先 |
|------|-------|
| 差分モードの照合先 | review-fullstack.md §2 |
| 適用する観点 | review-fullstack.md §3（仕様書-コード / 統合整合性 / アーキテクチャ） |
| 機械的検証 | review-fullstack.md §4（型・エンドポイント・数値・ルート定義の突き合わせ） |
| 重要度の基準 | review-fullstack.md §5 |

型・エンドポイント・ルート定義の突き合わせは**目視しない**。スクラッチパッドの使い捨てスクリプトで抽出・差分を取り、その出力だけを取り込む。

## 3. 注意事項

- **統合整合性の指摘を最優先で記述する**（片側だけの問題より、両方にまたがる問題を重視する）
- 指摘はフロント・バック両側のコードと仕様書の記述を**引用して対比**する。修正案は両側それぞれ書く
- 境界が曖昧な指摘は本スキルへ寄せる（review-procedure.md §7）
- 検出した乖離は「仕様書を実装に合わせる」か「実装を修正する」かの判断が必要。**勝手に決めず**、判断材料を添えて提示する
- **修正を自動適用しない**。レポートを保存して終了する
