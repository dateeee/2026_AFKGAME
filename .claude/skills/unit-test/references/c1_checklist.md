# C1（分岐網羅）観点チェックリスト

C1 は「すべての分岐の**両方の枝**を最低1回通す」こと。行網羅（C0）100%でも C1 は未達になりうる。

## レポートの読み方

JaCoCo は行ごとに菱形マークで分岐の充足を示す（HTML は `target/site/jacoco/index.html`）。

| 表記 | 意味 | 対処 |
|------|------|------|
| 行が赤（`All N branches missed`） | その行が**一度も実行されていない**（C0未達） | その経路を通すテストを追加 |
| 行が黄（`1 of 2 branches missed`） | 条件の**片側だけ**が未実行（C1未達） | 条件がもう一方になるケースを追加 |
| ループ行が黄 | **再入する分岐**または**一度も回らない分岐**が未実行 | 要素0件と2件以上のケースを追加 |
| `switch` 行が黄 | 未実行の `case` または `default` がある | 各ラベルを通すケースを追加 |

`BRANCH` カウンタの `missed` が 0 になって初めて C1 100%（`mvn verify` の `jacoco:check` が判定する）。

## 構文別チェックリスト

| 構文 | 必要なケース | 見落としやすい点 |
|------|------------|----------------|
| `if` | 真・偽の両方 | `else` が無くても「条件が偽で素通り」するケースが必要 |
| `else if` 連鎖 | 各枝 + **どれにも当たらない**場合 | 最後の `else if` が偽になるケース |
| ガード節・早期 `return` | 抜ける / 抜けない | 「抜けない」側を忘れがち |
| `for` / `while` | 0回（空）・1回・**2回以上** | 空コレクションと、ループが再入する分岐 |
| `break` / `continue` | する / せず最後まで回る | `break` せず自然終了するケース |
| `&&` / `\|\|` | 左で短絡する / 右まで評価する | `a && b` は「左が偽」「左真右偽」「両方真」 |
| `try/catch/finally` | 正常系 + **各 catch** | 複数の例外型を1つの `catch` にまとめている場合は型ごとに |
| 三項 `c ? a : b` | 両側 | 1行なので C0 では見えない |
| `switch` / switch式 | 各 `case` + `default` | 到達しない `default` は設計の見直し対象 |
| Stream の `.filter()` | 通る要素と弾かれる要素を**同じ入力に混在**させる | 全件通過するデータだけだと片側未達 |
| `Optional` | `isPresent` / `isEmpty` の両方 | `orElse` のフォールバック側 |
| null 許容の引数・フィールド | `null` / 非 `null` | `x != null ? x : default` の両側 |
| `map.getOrDefault(k, d)` | キーあり / なし | マスターデータの未知ID |
| `Math.min()` / `Math.max()` / クランプ | クランプが効く / 効かない | 境界ちょうどの値 |
| `throw` | 送出される / されない | 正常系だけで終わらせない |

## プロジェクト固有の観点

構文別チェックリストだけでは足りない。**ドメイン固有の分岐観点は、プロジェクト固有プロファイル**（`.claude/project/unit-test.md`）の「固有の分岐観点」表を必ず併用すること。

典型的には以下が固有観点になる。プロファイル側に該当表が無い場合は、この分類で洗い出して追記する。

| 分類 | 洗い出す軸 |
|------|----------|
| 外部要因 | 乱数の当たり/外れ（確率比較は**しきい値の両側**）、時刻の経過0 / 1単位 / 大量 |
| 参照データ | 既知ID / **未知ID**、空、上限値・無限を表す `null` などの特別値 |
| 永続状態 | レコードなし（初回） / あり、絞り込み条件が効く / 効かない |
| 認証・権限 | 認証あり / なし、期限切れ、権限不足 |
| 境界 | `>=` と `>` の境界そのもの、0、負値、上限クランプ |
| 入出力層 | 正常系 + **エラー種別ごと**の異常系、入力バリデーション違反 |

## 観点の言語化

分岐は「真/偽」ではなく**仕様上の意味**で書く。`@DisplayName` と Javadoc がそのまま設計の説明になる。

```
✗ @DisplayName("value > 0 が true")   … 実装表現。何を保証するのか読み取れない
✓ @DisplayName("残量があれば処理を継続する")   … 仕様上の意味
✓ @DisplayName("残量が0ちょうどなら打ち切る")   … 境界そのものを別テストにする
```

テストクラスの Javadoc には**対応する仕様書と分岐観点**を明記する。書式は
[test-list スキルの実装パターン](../../test-list/references/patterns.md)「クラスの骨格」に従う。
