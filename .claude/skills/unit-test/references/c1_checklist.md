# C1（分岐網羅）観点チェックリスト

C1 は「すべての分岐の**両方の枝**を最低1回通す」こと。行網羅（C0）100%でも C1 は未達になりうる。

## レポートの読み方

`--cov-branch --cov-report=term-missing` の Missing 列は2種類の表記が混在する。

| 表記 | 意味 | 対処 |
|------|------|------|
| `35-40` | 35〜40行目が**一度も実行されていない**（C0未達） | その経路を通すテストを追加 |
| `181->189` | 181行目から189行目への**分岐だけ**が未実行（C1未達） | 181の条件がもう一方になるケースを追加 |
| `263->233` | 後方ジャンプ = **ループが再び回る分岐**が未実行 | 要素2件以上／2周以上するケースを追加 |
| `429->exit` | その行から**関数を抜ける分岐**が未実行 | 条件に入らずそのまま末尾へ抜けるケースを追加 |

`BrPart` 列は「片側だけ通った分岐」の数。ここが 0 になって初めて C1 100%。

## 構文別チェックリスト

| 構文 | 必要なケース | 見落としやすい点 |
|------|------------|----------------|
| `if` | 真・偽の両方 | `else` が無くても「条件が偽で素通り」するケースが必要 |
| `elif` 連鎖 | 各枝 + **どれにも当たらない**場合 | 最後の `elif` が偽になるケース |
| ガード節・早期 `return` | 抜ける / 抜けない | 「抜けない」側を忘れがち |
| `for` / `while` | 0回（空）・1回・**2回以上** | 空リストと、ループが再入する `X->Y` 分岐 |
| `break` / `continue` | する / せず最後まで回る | `break` せず自然終了するケース |
| `for ... else` | `break` した場合 / しなかった場合 | `else` 節の実行/非実行が分岐 |
| `and` / `or` | 左で短絡する / 右まで評価する | `a and b` は「左が偽」「左真右偽」「両方真」 |
| `try/except/else/finally` | 正常系 + **各 except** | 複数の例外型を1つの `except` にまとめている場合は型ごとに |
| 三項 `A if C else B` | 両側 | 1行なので C0 では見えない |
| 内包表記の `if` | 通る要素と弾かれる要素を**同じ入力に混在**させる | 全件通過するデータだけだと片側未達 |
| `match` | 各 `case` + ワイルドカード `_` | 到達しない `_` は設計の見直し対象 |
| デフォルト引数 / `Optional` | 省略時 / 明示時、`None` / 非`None` | `x = x or default` の両側 |
| `dict.get(k, default)` | キーあり / なし | マスターデータの未知ID |
| `min()` / `max()` / クランプ | クランプが効く / 効かない | 境界ちょうどの値 |
| `raise` | 送出される / されない | 正常系だけで終わらせない |

## プロジェクト固有の観点

| 領域 | 押さえる分岐 |
|------|------------|
| 乱数 | ダメージ分散の上振れ/下振れ/中央、クリティカル発生/非発生、ドロップ有/無、エンカウント抽選。`random.random() < rate` は **rate 未満と rate 以上の両方**を固定して通す |
| 境界値 | `>=` と `>` の境界そのものの値、0、負値、上限クランプ（例: `target_floor_cap` の `highest == total_floors`） |
| マスターデータ | 既知ID / **未知ID**（`None` またはフォールバック）、空リスト、有限塔 `total_floors=int` と無限塔 `None` |
| DB状態 | レコードなし（初回） / あり、塔別に独立していること、複数レコードでの絞り込み |
| 認証 | ゲスト / 正規ユーザー、トークンなし / 期限切れ / 署名不正 |
| tick・オフライン | `TURNS_PER_TICK` 内で決着 / 決着せず持ち越し、経過0tick / 1tick / 大量tick、上限クランプ |
| 戦闘 | 先攻/後攻（SPD比較の同値含む）、HP がちょうど0、最低ダメージのクランプ（プレイヤー1 / 敵0）、全滅、ボス/通常敵 |
| 回復・在庫 | ポーション閾値の境界（`hp/max == threshold`）、在庫あり / 0個 |
| 経済 | gold 不足 / ちょうど / 十分、インベントリ上限、自動売却 有効/無効 |
| ルーター | 正常系 200 + **各エラーコードごと**の 4xx、Pydantic バリデーションエラー、権限違反 |

## 観点の言語化

分岐は「真/偽」ではなく**仕様上の意味**で書く。テスト名と docstring がそのまま設計の説明になる。

```
✗ test_if_hp_gt_0_true
✓ test_HPが残っていれば戦闘を継続する
✓ test_HPが0ちょうどなら全滅と判定する
```

モジュール docstring には対応する仕様書と分岐観点を明記する。

```python
"""単体テスト: 目標階の選択上限と上限追従

仕様: design/systems/battle.md「目標階設定」、tech/tech_api.md `/api/tower/select`
分岐観点:
  - 上限 = min(到達済み最高階 + 1, 総階数)、無限塔（total_floors=None）は +1 のみ
  - 上限追従は「目標階 == 旧上限」かつ「新しい階をクリアした」場合のみ発生
"""
```
