# ドキュメント文字数の是正（doc-size）

計測 → 判断（分割か圧縮か）→ 適用 → 検証。
目的は **情報を消さずに上限へ収める**こと。削除は最後の手段であり、まず移管を試みる。

## 0. 最初に読む

| 順 | ファイル | 内容 |
|----|---------|------|
| 1 | `.claude/project/profile.md` | コスト規律・ディレクトリ |
| 2 | `.claude/project/doc-size.md` | チェッカーのコマンド・区分と上限・台帳・分割の標準形・索引の更新先 |

## 1. 計測

1. 全体判定コマンドを実行し、超過（ERROR）・台帳登録（WARN）・残量WARN を把握する
2. 下表で対象を確定する（引数でファイル指定があればそれを対象にする）
3. 対象ごとにセクション別の測定コマンドを実行し、H2の内訳を得る（**本文はまだ読まない**）

| 順 | 状態 | 扱い |
|----|------|------|
| 1 | 常時読込・エージェント定義の区分が超過 | 読込回数に比例して放置コストが増えるため最優先。同一セッション内に是正 |
| 2 | 台帳に登録済みの超過 | 一括是正の本体。Phase完了ゲートまでに空にする |
| 3 | 新規の超過（仕様・設計の区分） | 台帳へ是正方針つきで登録し、本タスクで併せて処理してよい |
| — | 残量WARN（上限の90%超） | **是正しない**。次に追記する側が分割候補として扱う早期警戒 |
| — | H2の上限超過のみ（ファイルは上限内） | 単独では是正しない。分割・圧縮のついでに解消する |

`--check` 指定時は計測と判断（§2）までを報告し、適用しない。

## 2. 判断（分割か圧縮か）

**先に削減率を出す**（超過字数 ÷ 上限）。10%未満なら圧縮で届く。30%以上は圧縮では届かず分割が要る。
そのうえでH2の内訳から判断する。

| 状態 | 判断 |
|------|------|
| 独立して読めるテーマが2つ以上ある／削減率30%以上 | **分割**（§3-A） |
| 単一テーマで、散文・重複・冗長な例示が目立つ | **圧縮**（§3-B） |
| 単一テーマかつ既に表主体で、削れるのが固有の事実だけ | 他ファイルへの**移管**を再検討。それでも無理なら削除内容を明記して圧縮 |
| 図1枚でH2が構成され、分割すると可読性が下がる | 許容してWARNのまま残す（判断理由を記録する） |

判断とその根拠（削減率・H2内訳・分割単位）を一覧で提示し、ユーザーの承認を得てから適用する。

## 3. 適用

### A. 分割

親を索引にし、詳細を子ファイルへ移す。構成はプロファイルの標準形に従う。

1. 切り出す単位は**H2**。節番号は分割後も維持する（既存のリンク・レビュー指摘の参照が生き残る）
2. 親には子への**リンク表**を残し、移した本文は親から**削除**する（重複させない）
3. 子のヘッダに親へのリンクと担当節を明記する
4. 相対パスを移動先基準で張り直す
5. プロファイルが指す索引・エージェント定義の対象ファイル一覧を更新する

### B. 圧縮

削る順序を守る。**1〜2で足りない場合のみ3、3で足りない場合のみ4**。

1. 列挙・パラメータ・条件分岐を**表へ置き換える**
2. 他ファイルと重複する記述を削り、正となるファイルへリンクする（正の宣言先はプロファイル）
3. 前置き・導入文・冗長なコード例を削る（数値・条件・固有名は残す）
4. やむを得ず固有の事実を削る場合は、**削除内容を変更履歴へ1行明記する**

## 4. 検証と記録

1. チェッカーを再実行し、対象が上限内かつ新たな違反が出ていないことを確認する
2. リンク・索引の機械検証を実行する（分割時は必須）
3. 解消したファイルを台帳から削除する
4. 変更履歴へ1行追記する（分割は「A を B へ分割」、圧縮は「A を N字へ圧縮」と削除内容）

## 注意事項

- **上限内のファイルを予防的に縮めない**。差分が増えるだけで読込コストは変わらない
- 圧縮で「詳細は別途」「後述」に置き換えない。参照先のないリンク切れと同じく情報の喪失になる
- 分割の判断はH2の内訳で行う。全文を読むのは編集対象のファイルだけ
- 1ファイルごとに検証まで通す（複数ファイルを同時に崩さない）
- サブエージェントは対象が3ファイル以上のときのみ（1ファイル1体・担当ファイルを列挙）
