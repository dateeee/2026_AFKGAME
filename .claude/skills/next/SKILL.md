# 次タスクの開始（next）

前セッションが書き残した引き継ぎから次のタスクを特定し、工程スキルへ委譲する。
**タスクを特定しないまま作業を始めないための入口**であり、本スキル自身は作業をしない。

## 0. 最初に読む

| 順 | ファイル | 内容 |
|----|---------|------|
| 1 | `.claude/project/profile.md` | コスト規律・ディレクトリ |
| 2 | `.claude/project/next.md` | 引き継ぎファイルのパス・開始プロンプトの定型・更新ルール |

## 1. タスクの特定

1. プロファイルが指す引き継ぎファイルを読む（**この時点では他の仕様書・コードを読まない**）
2. 引数なし → 「次回」ブロックを対象にする。引数あり → 候補キューの該当行を対象にし、プロファイルの定型に沿ったプロンプトへ組み立てる
3. 「次回」がユーザー判断待ちの場合 → 候補キューを提示して選んでもらう。**選ばれるまで作業を開始しない**
4. 対象が1セッションで閉じない規模（複数ファイル・複数領域）と分かったら、**着手前にセグメントへ割る**。先頭セグメントだけを今回の対象にし、残りは候補キューへ行として戻す

## 2. 鮮度の確認

「前提」のコミットIDと git log 最新5件程度を突合し、次のいずれかに該当したら**開始せず**、状況と選択肢を提示してユーザーの判断を仰ぐ。

| # | 陳腐化の兆候 |
|---|------------|
| 1 | 対象タスクが完了済みに見える（コミットメッセージ・成果物と一致する） |
| 2 | 「前提」のコミットより後に、対象領域へ別の大きな変更が入っている |
| 3 | 引き継ぎファイルの最終更新・対応コミットが git log と食い違う |

## 3. 工程スキルへの委譲

1. 「次回」プロンプトを**ユーザーの依頼文として扱い**、冒頭に書かれた工程スキルを起動する
2. 「参照」は読み始めの**起点**。追加で必要なファイルはそこから索引経由で特定する（全文読みをしない）
3. 以降の進め方・完了基準・報告は**委譲先スキルに従う**

## 4. 引き継ぎの更新（セッション終了時）

委譲先のタスクが完了したら、**コミット前に**引き継ぎファイルを更新する。

- 「次回」を次のタスクの完成形プロンプト（定型5要素）へ書き換え、最終更新・対応コミットを更新する
- **候補キューの1行 = 1セッションで閉じる規模**。対象が複数ファイル・複数領域に及ぶタスクは、キューへ書く時点でセグメントへ割って行を分ける（1行にまとめない）
- 完了した行を候補キューへ残さない
- 次タスクを確定できない場合は「次回」を「ユーザー判断待ち」とし、候補キューに選択肢を残す

## 注意事項

- **サブエージェントを使わない**。読むのは引き継ぎファイルとプロファイルのみ
- 引き継ぎファイルに無いタスクを推測で開始しない
- 依頼文でタスクが特定されている場合は本スキルを経由せず、該当する工程スキルを直接使う
