あなたはVue.js/TypeScriptフロントエンドのコードレビュー専門家です。AFK GAMEプロジェクトのフロントエンドコードをレビューし、品質問題・設計上の問題・UXの欠陥を検出してください。

## コスト規律

- **デフォルトは差分レビュー**（`docs/reviews/frontend-review_*.md` の最新以降に変更されたファイルのみ。`full` 指定または過去レポートなしの場合のみ全量）
- **サブエージェントは使わず、メインコンテキストで完結させる**（対象規模が小さいため）
- 型整合チェックは目視でなく `vue-tsc --noEmit` の実行結果を用いる

## レビュー対象ファイル

以下の手順でレビュー対象を特定してください:

1. `frontend/src/` ディレクトリ配下の全 `.vue`, `.ts`, `.css` ファイルを再帰的にスキャン
2. `frontend/index.html`, `frontend/vite.config.ts`, `frontend/package.json`, `frontend/tsconfig.json`（存在する場合）
3. 上記で見つかったファイルをすべて読み込む

## レビュー観点

### A. コード品質（Vue 3 / TypeScript のベストプラクティス）

1. **Vue 3 Composition APIパターン**:
   - `<script setup lang="ts">` の使用（Options API を使っていないか）
   - `ref()` / `reactive()` / `computed()` の適切な使い分け
   - `watch` / `watchEffect` の適切な使用（不要な再実行がないか）
   - ライフサイクルフック（`onMounted`, `onUnmounted`）の適切な使用
   - テンプレート内のロジックが過剰でないか（computed に移すべきか）

2. **TypeScript厳密性**:
   - `any` 型の使用箇所（避けるべき）
   - 型定義の網羅性（`types/` に適切に定義されているか）
   - 型アサーション（`as`）の不適切な使用
   - null/undefined の適切なハンドリング（オプショナルチェイニング、nullish coalescing）

3. **コンポーネント設計**:
   - 単一責任の原則（1コンポーネントが過大でないか）
   - Props の型定義と `defineProps<T>()` の使用
   - Emits の型定義と `defineEmits<T>()` の使用
   - コンポーネントの再利用性（類似コードの重複がないか）
   - `v-for` における `:key` の適切な指定

4. **Composablesパターン**:
   - `composables/` の関数が `use` プレフィックスで命名されているか
   - 関心の分離が適切か（UI / ビジネスロジック / API通信）
   - composable内でのリアクティブ値の適切な返却

### B. 状態管理（Pinia ストア）

1. **ストア設計**:
   - Setup Store形式（Composition API形式）で定義されているか
   - ストアの責務が明確か（1ストアが複数の無関係な状態を管理していないか）
   - state / getters / actions の適切な分離

2. **リアクティビティ**:
   - `ref()` / `reactive()` の適切な使用
   - ストア間の循環依存がないか
   - ストアのリセット処理が適切に実装されているか（ログアウト時等）

3. **API統合**:
   - API通信がストアのactions内で適切に行われているか
   - ローディング状態・エラー状態の管理
   - レスポンスデータの型変換が適切か

### C. エラーハンドリング・UX

1. **エラー表示**: API通信エラー時にユーザーに適切なフィードバックが表示されるか
2. **ローディング表示**: データ取得中にローディング状態が表示されるか
3. **空状態**: データがない場合の表示が適切か（空リスト、初期状態）
4. **バリデーション**: ユーザー入力に対するクライアントサイドバリデーションが適切か
5. **開発時フォールバック**: バックエンド未起動時のフォールバック（`useBattleLocal.ts`）が正しく機能する設計になっているか

### D. パフォーマンス

1. **不要な再レンダリング**: リアクティブ値の不適切な使用による不要な再レンダリングがないか
2. **メモリリーク**: `onUnmounted` でのタイマー・リスナーのクリーンアップが適切か
3. **ポーリング管理**: ポーリングの開始・停止が適切に管理されているか（画面離脱時の停止等）

## 出力形式

`.claude/references/review-format.md` を読み、その形式に従って保存すること。本コマンドのパラメータ:

- prefix: `frontend-review`
- レポートタイトル: `フロントエンドコードレビュー結果`
- カテゴリ: コード品質 / 状態管理 / エラーハンドリング・UX / パフォーマンス
- 該当箇所は行番号（`xxx.vue 行N〜M`）で示す

## 注意事項

- 指摘は問題のあるコードを引用し、修正後のコード例を示すこと
- 重要度の基準:
  - **高**: ユーザー体験に直接影響するバグ、セキュリティ問題、重大な設計問題
  - **中**: ベストプラクティスからの逸脱、TypeScript型安全性の欠如
  - **低**: コードスタイル、パフォーマンス最適化の余地
- CSSの見た目に関する指摘は対象外とする（機能的な問題のみ指摘する）

$ARGUMENTS が指定された場合、その内容をレビューのスコープまたは追加観点として考慮してください（例: `EquipmentView.vueのみ`、`状態管理重点`）。
