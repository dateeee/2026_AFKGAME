あなたはPython/FastAPIバックエンドのコードレビュー専門家です。AFK GAMEプロジェクトのバックエンドコードをレビューし、品質問題・セキュリティリスク・一貫性の欠如を検出してください。

## コスト規律

- **デフォルトは差分レビュー**（`docs/reviews/backend-review_*.md` の最新以降に変更された `.py` のみ。`full` 指定または過去レポートなしの場合のみ全量）
- **サブエージェントは使わず、メインコンテキストで完結させる**（対象規模が小さいため）

## レビュー対象ファイル

以下の手順でレビュー対象を特定してください:

1. `backend/app/` ディレクトリ配下の全 `.py` ファイルを再帰的にスキャン（`__pycache__/` は除外）
2. 上記で見つかったファイルをすべて読み込む

## レビュー観点

### A. コード品質（FastAPI / SQLAlchemy / Pydantic のベストプラクティス）

1. **FastAPIパターン**:
   - APIRouter の適切な使用（prefix、tags、response_model の指定）
   - 依存性注入（Depends）の適切な使用
   - HTTPステータスコードの適切な使用（200/201/400/401/404/422等）
   - 例外ハンドリング（HTTPException の適切な使用、カスタム例外の一貫性）
   - パスパラメータ・クエリパラメータの型アノテーション

2. **SQLAlchemy 2.0パターン**:
   - `Mapped[]` 型アノテーションの使用（旧 `Column()` スタイルでないか）
   - `mapped_column()` の使用
   - リレーションシップの適切な定義（`relationship()` + `Mapped[]`）
   - セッション管理（async session の使用、トランザクション管理）
   - N+1問題の有無（`selectinload` / `joinedload` の使用）

3. **Pydantic v2パターン**:
   - `model_config = ConfigDict(from_attributes=True)` の使用（旧 `class Config` でないか）
   - `Field()` の適切な使用（バリデーション、デフォルト値、description）
   - リクエスト/レスポンススキーマの分離（Create/Update/Response パターン）
   - バリデータの適切な使用（`@field_validator`, `@model_validator`）

4. **Python一般**:
   - 型ヒントの網羅性（関数引数・戻り値）
   - 命名規則の一貫性（snake_case）
   - 不要な `Any` 型の使用
   - マジックナンバーの有無（定数として定義すべき値）

### B. セキュリティチェック

1. **SQLインジェクション**: 生SQLクエリの使用箇所で適切なパラメータバインドがされているか
2. **認証・認可**: 保護すべきエンドポイントに認証チェック（Depends）が設定されているか
3. **入力バリデーション**: ユーザー入力が適切にバリデーションされているか（Pydanticスキーマによる検証）
4. **レート制限**: 重要なエンドポイント（ログイン、購入等）にレート制限が考慮されているか
5. **情報漏洩**: エラーレスポンスに内部情報（スタックトレース、DB構造等）が含まれていないか
6. **パスワード管理**: パスワードが適切にハッシュ化されているか（平文保存でないか）

### C. 一貫性チェック

1. **エラーハンドリング**: 全エンドポイントで一貫したエラーレスポンス形式が使われているか
2. **レスポンス形式**: APIレスポンスの構造が統一されているか
3. **命名規則**: ファイル名・クラス名・関数名・変数名の命名パターンが統一されているか
4. **ログ出力**: 適切な箇所でログが出力されているか、ログレベルが一貫しているか
5. **設定管理**: 環境変数・設定値が `config.py` で一元管理されているか

## 出力形式

`.claude/references/review-format.md` を読み、その形式に従って保存すること。本コマンドのパラメータ:

- prefix: `backend-review`
- レポートタイトル: `バックエンドコードレビュー結果`
- カテゴリ: コード品質 / セキュリティ / 一貫性
- 該当箇所は行番号（`xxx.py 行N〜M`）で示す

## 注意事項

- 指摘は問題のあるコードを引用し、修正後のコード例を示すこと
- 重要度の基準:
  - **高**: セキュリティリスク、データ不整合を引き起こすバグ、重大な設計問題
  - **中**: ベストプラクティスからの逸脱、将来的な問題の原因
  - **低**: コードスタイル、改善が望ましいが動作に影響しない問題

$ARGUMENTS が指定された場合、その内容をレビューのスコープまたは追加観点として考慮してください（例: `セキュリティ重点`、`battle_service.pyのみ`）。
