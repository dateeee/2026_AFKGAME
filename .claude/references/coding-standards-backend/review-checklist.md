## 5. レビュー チェックリスト

機械的に見えるもの（①〜④）から先に潰す。**該当箇所は `ファイル名 行N〜M` で示す**。

| # | 見るもの | 逸脱の例 |
|---|---------|---------|
| 1 | import | ワイルドカード、未使用、グループ順の乱れ |
| 2 | DI | フィールド `@Autowired`、`final` でない依存 |
| 3 | SQL | `${}` による文字列組み立て（インジェクション）、N+1 |
| 4 | 定数 | 直書きの数値・文字列、バランス値のハードコード |
| 5 | 層 | コントローラの業務分岐、Entity のロジック、ドメイン層の HTTP 型依存、コントローラからのリポジトリ直呼び、サービスへの永続化技術の露出 |
| 6 | トランザクション | 境界がサービスの public メソッドにあるか、複数更新が1メソッドに閉じているか、伝播属性が明示されているか、自己呼び出しで境界が抜けていないか |
| 6a | サービス間呼び出し | 共有サービス以外を呼んでいないか、共有サービスがさらに他のサービスを呼んでいないか |
| 7 | 例外 | 3分類のどれか判別できない送出、独自例外の乱立、空 `catch`、内部情報の露出、コントローラの `try-catch` |
| 8 | ログ | ロガー名が体系外、連結メッセージ、機微情報の出力、START / END の片側落ち、業務コードでの境界ログ手書き、想定内の失敗を ERROR で出す |
| 8a | ログ | 機密フィールドを持つ Entity・DTO を追加・改修したのに `toString()` から除外していない（AOP が引数・戻り値を出すため漏れる） |
| 6b | サービスの構成 | インタフェースと実装（`Impl`）に分かれているか、`@Service` と `@Transactional` が実装側に付いているか、呼び出し側が実装型を直接参照していないか、Javadoc がインタフェース側にあるか |
| 9 | 命名 | 層ごとの接尾辞、リポジトリメソッドの `find/findAll/exists/save/update/delete + By<条件>`（永続化技術や SQL 種別を名前に出さない） |
| 10 | Javadoc | `public` の欠落、仕様参照の欠落、`@throws` のコード欠落 |
| 11 | スコープ | 対象Phase外の機能、定義書に無い列・テーブル |
| 12 | 横断処理 | フィルタ／インターセプタの選び分けの理由が無い、業務ロジックの混入、フィルタでの応答未組み立て（共通ハンドラを通らない）、インターセプタの `false` + `sendError`・フィールド保持・`handler` の無検査キャスト、登録順・対象パスの表が実装と食い違う |

テストコードの記述規約（命名・グループ化・分岐マーカー）と、テストまわりのガイドライン差分は**本書の対象外**。正の側のテスト分冊が持つ。
