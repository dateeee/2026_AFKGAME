# バックエンドコーディング規約 — 例外・ログ・Javadoc

> 親: [coding-standards-backend.md](../coding-standards-backend.md)。本書は同 **§4** を担当する。
> 層の責務は §2 [layering.md](layering.md)、記述は §3 [writing.md](writing.md)。正はプロジェクト側のコーディング規約ドキュメント。

## 4. 例外・ログ・Javadoc

| 区分 | # | 規約 |
|------|---|------|
| 例外 | 1 | **3分類で扱う**（対処者で決める）: ①ビジネス例外（ルール違反の検知 / 利用者が再操作で解消 / 4xx + コード / WARN）②システム例外（あってはならない状態の検知 / 運用者が対処 / 500 / ERROR）③予期しないエラー（バグ・基盤障害 / 開発者が解析 / 500 / ERROR） |
| 例外 | 2 | ①②とも**フレームワークが提供する例外クラス**を使い、**例外クラスを自作しない**。①は例外にコードだけを載せ（コード体系はログ設計の仕様書が正）HTTP ステータスは変換層の対応表が決める、②は**コードをログにだけ**出す。③は**投げない・捕まえない**。ライブラリ例外は捕捉して①〜③へ振り直す |
| 例外 | 2a | 変換層の「コード→ステータス」対応表は仕様書の写しなので、**一致をスクリプトで機械照合**する |
| 例外 | 3 | ①②とも非検査例外にする（検査例外を新設しない）。空の `catch` を書かない。到達しない `catch` は理由コメント + `IllegalStateException`（＝③扱い） |
| 例外 | 4 | 応答への変換は `@RestControllerAdvice` へ集約。②③の応答は同じ定型にし、内部情報（SQL・スタックトレース）を載せない。認証失敗の理由は出し分けない |
| 例外 | 5 | ロールバックさせたくない副作用は `@Transactional(noRollbackFor = ...)` を明示し、理由を Javadoc に書く |
| Tx | 5a | 境界は**サービスの public メソッド**。リポジトリ・コントローラ・フィルタに `@Transactional` を付けない。複数の更新は1メソッドに閉じる |
| Tx | 5b | 参照だけの境界は `readOnly = true`。呼び出し元の境界に含める共有サービスは `MANDATORY`、独立させるなら `REQUIRES_NEW`（親を中断させるので理由を Javadoc に書く） |
| Tx | 5c | 同一クラス内の自己呼び出しはプロキシを通らず境界が効かない。境界の要るメソッドを内部から呼ばない |
| ログ | 6 | SLF4J。ロガーは**仕様のロガー名体系の名前**で取得する（`getLogger(Xxx.class)` にしない） |
| ログ | 6a | ログは**用途で3種別に分け、別ファイルへ出す**（通信 / アプリケーション / エラー）。振り分けは**ロガー名とレベルだけ**で決め、appender 名・ファイルパスをコードに書かない |
| ログ | 7 | メッセージはプレースホルダ `{}` で組む（連結・`String.format` を使わない） |
| ログ | 8 | 資格情報・トークン生値・個人情報をそのまま出さない。横断項目は MDC に任せ、各所で詰め直さない |
| ログ | 8a | 通信の START / END と層をまたぐ呼び出しの START / END は、**フィルタと AOP が出す**（業務コードで手書きしない）。例外で抜ける経路でも**必ず対で**出す |
| ログ | 8b | AOP が引数・戻り値を出すなら**マスクは AOP 側で完結**させる（`toString()` 任せにしない）。コレクションは件数だけ、長い値は打ち切る |
| ログ | 9 | `System.out.println`・`printStackTrace` 禁止 |
| ログ | 9a | ERROR はエラーログ（アラート）へ集約される。**定常的に出る ERROR を作らない**（利用者の操作で解消するものは WARN + 理由）。同じ例外を各層で二重に ERROR しない |
| Javadoc | 10 | `public` のクラス・メソッドに日本語 Javadoc。1行目は「〜する。」の要約1文 |
| Javadoc | 11 | クラス Javadoc に**仕様書の参照先**（ファイル + 節番号）を書く |
| Javadoc | 12 | `@param`・`@return`・`@throws`（例外にはエラーコード）を書く。段落は `<p>`、識別子は `{@code ...}` |
| Javadoc | 13 | 未実装・仮実装は**理由と解消時期**を Javadoc に書く（`TODO` だけにしない）。コメントは「なぜ」を書く |
