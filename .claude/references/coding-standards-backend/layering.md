# バックエンドコーディング規約 — 層の責務

> 親: [coding-standards-backend.md](../coding-standards-backend.md)。本書は同 **§2** を担当する。
> 記述は §3 [writing.md](writing.md)、例外・ログは §4 [exception-logging.md](exception-logging.md)。正はプロジェクト側のコーディング規約ドキュメント。

## 2. 層の責務（越えたら指摘）

| 層 | 書いてよいこと | 書いてはいけないこと |
|----|--------------|-------------------|
| コントローラ | マッピング、入力検証、DTO 変換 | 業務分岐、計算、DB アクセス、`try-catch` |
| サービス | ビジネスロジック、トランザクション境界（`@Transactional`） | HTTP・サーブレットの型への依存 |
| リポジトリ・Entity | SQL、永続化の器 | 導出ロジック、業務判断 |
| DTO（リクエスト/レスポンス） | フィールド定義、Bean Validation、変換用の `static from(...)` | 業務ロジック、リクエスト用とレスポンス用の兼用 |
| 設定・フィルタ | 設定バインド、横断処理 | 個別機能の業務ロジック |

**コンポーネント間の呼び出し可否**（抽象化層を挟まない構成なら「リポジトリ」を「O/R Mapper」と読み替える）。

| 呼ぶ側 \ 呼ばれる側 | コントローラ | サービス | リポジトリ |
|---|---|---|---|
| コントローラ | × | ○ | **×** |
| サービス | × | **△** | ○ |

- コントローラからリポジトリを直接呼ぶと**境界が Web 層へ漏れる**。参照系でも必ずサービスを通す
- **サービス間の呼び出しは原則禁止（△）**。共有する必要があるものだけを「共有サービス」として明示し、**呼び出しは1段まで**（共有サービスは他のサービスを呼ばない）。共有サービスは**伝播属性を明示**する
- **サービスはインタフェース + 実装クラス**（実装は `〜Impl`・同パッケージ）。`@Service`・`@Transactional` は**実装側**、公開 Javadoc と参照する型は**インタフェース側**
- **依存方向は Web → ドメイン → 環境設定の一方向**。逆流・循環を作らない。ドメイン層は Web の型を扱わない（**入力チェックと DTO 変換は Web 層、ビジネスルールはドメイン層**）
- **DI はコンストラクタ注入**（依存は `private final`）。フィールド `@Autowired`・setter 注入は使わない
- 現在時刻・乱数は**外から受ける**。例外は暗号用途の `SecureRandom`（`private static final` で共有可。ゲーム乱数の生成器をトークン生成に使うと予測可能になる）
- 定義書に無い列・テーブルが要るなら、実装で先行せず**基本設計へ差し戻す**

**横断処理（フィルタ / インターセプタ）**。個別機能の業務ロジックはどちらにも置かない。

| # | 規約 |
|---|------|
| 1 | 選び分け: ストリームを触る／全リクエストに効かせる／認証チェーンと順序を組む → **フィルタ**。ハンドラで挙動を変える → **インターセプタ**。どちらでも成り立つなら**インターセプタ**（対象を絞れ、例外が共通ハンドラへそろう）。選んだ理由を Javadoc に書く |
| 2 | **フィルタ内の例外は共通の例外ハンドラ（`@RestControllerAdvice`）を通らない**。応答をフィルタ側で統一エラー形式に組む（投げっぱなしでは形式が崩れる）。インターセプタは通るので**拒否は例外を投げて表す**（`false` + `sendError` は使わない） |
| 3 | フィルタは二重実行を防ぐ基底クラスを継承し、リクエストボディを読まない（下流が読めなくなる）。MDC へ入れた項目は `finally` で捨てる |
| 4 | インターセプタは**状態をフィールドに持たない**。`preHandle` の `handler` はハンドラメソッドとは限らず型検査が要る。`postHandle` では応答本文を変えられない（`@ResponseBody`）ので使わない |
| 5 | 登録の**順序と対象パス**は動作に直結する。増減したら正の側の一覧表を同じ変更で直す |
