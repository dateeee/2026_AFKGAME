# フロントエンドコーディング規約 — 状態と API

> 親: [coding-standards-frontend.md](../coding-standards-frontend.md)。本書は同 **§4** を担当する。
> 層の責務は §2 [layering.md](layering.md)、記述は §3 [writing.md](writing.md)。正はプロジェクト側のコーディング規約ドキュメント。

## 4. 状態と API

**リアクティビティ**。

| # | 規約 |
|---|------|
| 1 | 状態は `ref()` に統一（`reactive()` 禁止）。派生値は `computed()`（getter に副作用を書かない） |
| 2 | `watch` は対象明示。`watchEffect` は使わない（依存が暗黙になる） |
| 3 | タイマー・リスナー・監視は登録した側が `onUnmounted`（または解除関数）で必ず解除する |
| 4 | 増え続ける配列（ログ・履歴）は上限を決めて古いものから捨てる（上限値の正は設計書） |
| 5 | `document` / `window` の直接操作は composable か UI プリミティブに閉じる |

**ストア（Pinia）**。

| # | 規約 |
|---|------|
| 1 | Setup Store 形式のみ（Options Store 禁止）。state = `ref`、getter = `computed`、action = `function` |
| 2 | state の `ref` はすべて `return` する。内部専用関数は `return` せず `_` 接頭辞 |
| 3 | ストアは「画面を跨ぐ状態」だけ。1画面で完結する UI 状態はコンポーネントの `ref` に置く |
| 4 | 非同期 action は `loading` / `error` を持ち、エラーは表示用文字列に変換して保持する |
| 5 | 楽観更新しない（更新はサーバー応答で上書き）。全ストアに `reset()` を実装しログアウトで呼ぶ |
| 6 | ストアの state を分割代入するときは `storeToRefs()`（素の分割代入は反応性を失う） |

**API 通信とエラー処理**。

| # | 規約 |
|---|------|
| 1 | エンドポイント関数は「HTTP メソッド + 対象」命名。共通処理（認証・エラー変換・リトライ）は基盤へ集約する |
| 2 | リクエスト / レスポンス型はサーバーの DTO と1対1で共有型ファイルに置き、同じ変更で同期する |
| 3 | エラーは**コードで分岐**する（メッセージ文字列で分岐しない）。通信断・セッション失効・業務エラーを型・判定関数で区別する |
| 4 | 自動リトライは「ネットワークエラー × 冪等メソッド」だけ。更新系はリトライしない |
| 5 | 想定外エラー（描画エラー・未処理 Promise 拒否）はグローバル捕捉して汎用表示に倒す。空 `catch` を作らない（意図的な無視は理由コメント） |
| 6 | 一覧・非同期表示はローディング・空・エラーの3状態を明示的に描画する |
