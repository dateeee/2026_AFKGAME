# バックエンドコーディング規約 チェックリスト（Java / Spring Boot・MyBatis3）

`dev`（製造）・`backend-review`・`unit-test` が、Java のコードを**書く前・レビューする前**に読む要約。
**本書は派生**。規約の正はプロジェクト側のコーディング規約ドキュメント（工程定義の基本設計工程が指す成果物）にあり、
モジュール名・パッケージ・ロガー名・エラーコードなどの**固有値は本書に書かない**（正の側とプロファイルを参照する）。
食い違ったら**正の側が勝つ**。フロントエンドは別書。

## 1. 使い方

| 場面 | すること |
|------|---------|
| 実装前 | §2〜§4 に目を通す。固有値（パッケージ・ロガー名・設定キー）は正の規約ドキュメントで確認する |
| レビュー時 | §5 のチェックリストを観点に足す。**指摘は正の規約ドキュメントの節番号で示す** |
| 規約に無い判断 | 近傍の既存コードに倣う。迷ったら正の規約ドキュメントの改訂を提案する（勝手に新流儀を作らない） |

## 2. 層の責務（越えたら指摘）

| 層 | 書いてよいこと | 書いてはいけないこと |
|----|--------------|-------------------|
| コントローラ | マッピング、入力検証、DTO 変換 | 業務分岐、計算、DB アクセス、`try-catch` |
| サービス | ビジネスロジック、トランザクション境界（`@Transactional`） | HTTP・サーブレットの型への依存 |
| Mapper・Entity | SQL、永続化の器 | 導出ロジック、業務判断 |
| DTO（リクエスト/レスポンス） | フィールド定義、Bean Validation、変換用の `static from(...)` | 業務ロジック、リクエスト用とレスポンス用の兼用 |
| 設定・フィルタ | 設定バインド、横断処理 | 個別機能の業務ロジック |

- **依存方向は Web → ドメイン → 環境設定の一方向**。逆流・循環を作らない
- **DI はコンストラクタ注入**（依存は `private final`）。フィールド `@Autowired`・setter 注入は使わない
- 現在時刻・乱数は**外から受ける**（引数・注入）。静的な共有インスタンスを持たない
- テーブル定義書に無い列・テーブルが要るなら、実装で先行せず**基本設計へ差し戻す**

## 3. 記述

| # | 規約 |
|---|------|
| 1 | インデント半角スペース4（継続行8）、タブ禁止、1行120字目安、UTF-8 / LF |
| 2 | `import` は `java` → `javax` → `org` → `com` → その他の順、グループ間に空行1つ。ワイルドカード・未使用 import 禁止 |
| 3 | フィールドは原則 `private final`。可変が許されるのは ORM がマッピングする Entity のみ |
| 4 | 不変データは `record`、getter/setter を持つ class は Entity に限る |
| 5 | `null` を返しうるメソッドは Javadoc に明記。`Optional` は戻り値専用（フィールド・引数に使わない） |
| 6 | 日時は `java.time`（既定は `Instant`）。`java.util.Date`・`Calendar` 禁止 |
| 7 | 整数値は `long` を既定にし、通貨・カウンタを浮動小数で持たない |
| 8 | **マジックナンバー禁止**。技術定数は `private static final` + Javadoc、運用値は設定ファイル、バランス値はマスターデータ |
| 9 | 早期 return でネストを浅く（3段以上ネストさせない）。ループ内の文字列 `+` 連結をしない |
| 10 | 可視性は最小に。`@Override` を省略せず、`@SuppressWarnings` には理由コメントを添える |

## 4. 例外・ログ・Javadoc

| 区分 | # | 規約 |
|------|---|------|
| 例外 | 1 | クライアントへ返す業務エラーは**コード付きの単一の業務例外クラス**だけを投げる。コード体系はログ設計の仕様書が正 |
| 例外 | 2 | 応答への変換は `@RestControllerAdvice` へ集約。コントローラで捕まえない |
| 例外 | 3 | 検査例外を新設しない。空の `catch` を書かない。到達しない `catch` は理由コメント + `IllegalStateException` |
| 例外 | 4 | 応答に内部情報（SQL・スタックトレース・スキーマ）を載せない。認証失敗の理由は出し分けない |
| 例外 | 5 | ロールバックさせたくない副作用は `@Transactional(noRollbackFor = ...)` を明示し、理由を Javadoc に書く |
| ログ | 6 | SLF4J。ロガーは**仕様のロガー名体系の名前**で取得する（`getLogger(Xxx.class)` にしない） |
| ログ | 7 | メッセージはプレースホルダ `{}` で組む（連結・`String.format` を使わない） |
| ログ | 8 | 資格情報・トークン生値・個人情報をそのまま出さない。横断項目は MDC に任せ、各所で詰め直さない |
| ログ | 9 | `System.out.println`・`printStackTrace` 禁止 |
| Javadoc | 10 | `public` のクラス・メソッドに日本語 Javadoc。1行目は「〜する。」の要約1文 |
| Javadoc | 11 | クラス Javadoc に**仕様書の参照先**（ファイル + 節番号）を書く |
| Javadoc | 12 | `@param`・`@return`・`@throws`（例外にはエラーコード）を書く。段落は `<p>`、識別子は `{@code ...}` |
| Javadoc | 13 | 未実装・仮実装は**理由と解消時期**を Javadoc に書く（`TODO` だけを残さない）。コメントは「なぜ」を書く |

## 5. レビュー チェックリスト

機械的に見えるもの（①〜④）から先に潰す。**該当箇所は `ファイル名 行N〜M` で示す**。

| # | 見るもの | 逸脱の例 |
|---|---------|---------|
| 1 | import | ワイルドカード、未使用、グループ順の乱れ |
| 2 | DI | フィールド `@Autowired`、`final` でない依存 |
| 3 | SQL | `${}` による文字列組み立て（インジェクション）、N+1 |
| 4 | 定数 | 直書きの数値・文字列、バランス値のハードコード |
| 5 | 層 | コントローラの業務分岐、Entity のロジック、ドメイン層の HTTP 型依存 |
| 6 | トランザクション | 境界がサービスの public メソッドにあるか、複数更新が1メソッドに閉じているか |
| 7 | 例外 | 独自例外の乱立、空 `catch`、内部情報の露出、コントローラの `try-catch` |
| 8 | ログ | ロガー名が体系外、連結メッセージ、機微情報の出力 |
| 9 | 命名 | 層ごとの接尾辞、Mapper メソッドの `select/insert/update/delete + By<条件>` |
| 10 | Javadoc | `public` の欠落、仕様参照の欠落、`@throws` のコード欠落 |
| 11 | スコープ | 対象Phase外の機能、定義書に無い列・テーブル |

テストコードの記述規約（命名・グループ化・分岐マーカー）は**本書の対象外**。テスト系プロファイルが正。
