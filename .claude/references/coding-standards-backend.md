# バックエンドコーディング規約 チェックリスト（Java / Terasoluna・MyBatis3）

`dev`（製造）・`backend-review`・`unit-test` が、Java のコードを**書く前・レビューする前**に読む要約の索引。
**本書は派生**。正はプロジェクト側のコーディング規約ドキュメントで、そのベースである**フレームワークの公式開発ガイドライン**（版・URL は正の側 §1）が最上位の拠り所。本書に無い判断はガイドラインへ当たる。食い違ったら**正の側が勝つ**。フロントエンドは別書。

## 1. 使い方

| 場面 | すること |
|------|---------|
| 実装前 | §2〜§4 の分冊に目を通す。正が層別に分冊されていれば**共通ぶん + いま書く層の分冊**も読む |
| 固有値が要る | モジュール名・パッケージ・ロガー名・エラーコードは**本書に書かない**。正の側とプロファイルで確認する |
| レビュー時 | §5 を観点に足す。**指摘は正の節番号で示す** |
| 規約に無い判断 | 近傍の既存コードに倣う。迷ったら正の改訂を提案する |
| ガイドラインと違う実装 | 層の分冊に**明記済みの差分**（ガイドラインの章番号・決定・理由）として書かれていないか先に確認する。あれば指摘しない |
