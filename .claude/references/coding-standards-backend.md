# バックエンドコーディング規約 チェックリスト（Java / Terasoluna・MyBatis3）

`dev`（製造）・`backend-review`・`unit-test` が、Java のコードを**書く前・レビューする前**に読む要約。
**本書は派生**。正はプロジェクト側のコーディング規約ドキュメント（基本設計工程が指す成果物）で、そのベースである**フレームワークの公式開発ガイドライン**（版・URL は正の側 §1）が最上位の拠り所。本書に無い判断はガイドラインへ当たる。食い違ったら**正の側が勝つ**。フロントエンドは別書。

## 1. 使い方

| 場面 | すること |
|------|---------|
| 実装前 | §2〜§4 に目を通す。正が層別に分冊されていれば**共通ぶん + いま書く層の分冊**も読む |
| 固有値が要る | モジュール名・パッケージ・ロガー名・エラーコードは**本書に書かない**。正の側とプロファイルで確認する |
| レビュー時 | §5（[review-checklist.md](coding-standards-backend/review-checklist.md)）を観点に足す。**指摘は正の規約ドキュメントの節番号で示す** |
| 規約に無い判断 | 近傍の既存コードに倣う。迷ったら正の改訂を提案する（勝手に新流儀を作らない） |
| ガイドラインと違う実装 | 層の分冊に**明記済みの差分**（ガイドラインの章番号・決定・理由）として書かれていないか先に確認する。あれば指摘しない |

## 2. 層の責務（越えたら指摘）

| 層 | 書いてよいこと | 書いてはいけないこと |
|----|--------------|-------------------|
| コントローラ | マッピング、入力検証、DTO 変換 | 業務分岐、計算、DB アクセス、`try-catch` |
| サービス | ビジネスロジック、トランザクション境界（`@Transactional`） | HTTP・サーブレットの型への依存 |
| リポジトリ・Entity | SQL、永続化の器 | 導出ロジック、業務判断 |
| DTO（リクエスト/レスポンス） | フィールド定義、Bean Validation、変換用の `static from(...)` | 業務ロジック、リクエスト用とレスポンス用の兼用 |
| 設定・フィルタ | 設定バインド、横断処理 | 個別機能の業務ロジック |

**コンポーネント間の呼び出し可否**（データアクセスを抽象化する層を挟む構成の場合。挟まない構成なら「リポジトリ」を「O/R Mapper」に読み替える）。

| 呼ぶ側 \ 呼ばれる側 | コントローラ | サービス | リポジトリ |
|---|---|---|---|
| コントローラ | × | ○ | **×** |
| サービス | × | **△** | ○ |

- コントローラからリポジトリを直接呼ぶと**トランザクション境界が Web 層へ漏れる**。参照系でも必ずサービスを通す
- **サービス間の呼び出しは原則禁止（△）**。共有する必要があるものだけを「共有サービス」として明示し、**呼び出しは1段まで**（共有サービスは他のサービスを呼ばない）。共有サービスは**伝播属性を明示**する
- **依存方向は Web → ドメイン → 環境設定の一方向**。逆流・循環を作らない。ドメイン層は Web の型（Form・リクエスト・HTTP ステータス）を扱わない（**入力チェックと DTO 変換は Web 層、ビジネスルールはドメイン層**）
- **DI はコンストラクタ注入**（依存は `private final`）。フィールド `@Autowired`・setter 注入は使わない
- 現在時刻・乱数は**外から受ける**（引数・注入）。例外は暗号用途の `SecureRandom` のみ（スレッドセーフなので `private static final` で共有可。ゲーム乱数の生成器はトークン生成に使うと予測可能になる）
- テーブル定義書に無い列・テーブルが要るなら、実装で先行せず**基本設計へ差し戻す**

## 3. 記述

| # | 規約 |
|---|------|
| 1 | インデント半角スペース4（継続行8）、タブ禁止、1行120字目安、UTF-8 / LF |
| 2 | `import` は `java` → `javax` → `org` → `com` → その他の順、グループ間に空行1つ。ワイルドカード・未使用 import 禁止 |
| 3 | フィールドは原則 `private final`。可変が許されるのは ORM がマッピングする Entity のみ |
| 4 | 不変データは `record`、getter/setter を持つ class は Entity に限る |
| 5 | `null` を返しうるメソッドは Javadoc に明記。`Optional` は戻り値専用（フィールド・引数に使わない） |
| 6 | 日時は `java.time`（既定は `Instant`）。`java.util.Date`・`Calendar` 禁止 |
| 7 | 整数値は `long` を既定にし、通貨・カウンタを浮動小数で持たない |
| 8 | **マジックナンバー禁止**。技術定数は `private static final` + Javadoc、運用値は設定ファイル、バランス値はマスターデータ |
| 9 | 早期 return でネストを浅く（3段以上ネストさせない）。ループ内の文字列 `+` 連結をしない |
| 10 | 可視性は最小に。`@Override` を省略せず、`@SuppressWarnings` には理由コメントを添える |

## 4. 例外・ログ・Javadoc

| 区分 | # | 規約 |
|------|---|------|
| 例外 | 1 | **3分類で扱う**（対処者で決める）: ①ビジネス例外（ルール違反の検知 / 利用者が再操作で解消 / 4xx + コード / WARN）②システム例外（あってはならない状態の検知 / 運用者が対処 / 500 / ERROR）③予期しないエラー（バグ・基盤障害 / 開発者が解析 / 500 / ERROR） |
| 例外 | 2 | ①は**コード付きの単一クラス**（コード体系はログ設計の仕様書が正）、②は専用クラスで**コードはログにだけ**出す。③は**投げない・捕まえない**。ライブラリ例外は捕捉して①〜③へ振り直す |
| 例外 | 3 | ①②とも非検査例外にする（検査例外を新設しない）。空の `catch` を書かない。到達しない `catch` は理由コメント + `IllegalStateException`（＝③扱い） |
| 例外 | 4 | 応答への変換は `@RestControllerAdvice` へ集約。②③の応答は同じ定型にし、内部情報（SQL・スタックトレース・スキーマ）を載せない。認証失敗の理由は出し分けない |
| 例外 | 5 | ロールバックさせたくない副作用は `@Transactional(noRollbackFor = ...)` を明示し、理由を Javadoc に書く |
| Tx | 5a | 境界は**サービスの public メソッド**。リポジトリ・コントローラ・フィルタに `@Transactional` を付けない。複数の更新は1メソッドに閉じる |
| Tx | 5b | 参照だけの境界は `readOnly = true`。呼び出し元の境界に必ず含めたい共有サービスは `MANDATORY`、独立させるなら `REQUIRES_NEW`（親を中断させるので理由を Javadoc に書く） |
| Tx | 5c | 同一クラス内の自己呼び出しはプロキシを通らず境界が効かない。境界の要るメソッドを内部から呼ばない |
| ログ | 6 | SLF4J。ロガーは**仕様のロガー名体系の名前**で取得する（`getLogger(Xxx.class)` にしない） |
| ログ | 7 | メッセージはプレースホルダ `{}` で組む（連結・`String.format` を使わない） |
| ログ | 8 | 資格情報・トークン生値・個人情報をそのまま出さない。横断項目は MDC に任せ、各所で詰め直さない |
| ログ | 9 | `System.out.println`・`printStackTrace` 禁止 |
| Javadoc | 10 | `public` のクラス・メソッドに日本語 Javadoc。1行目は「〜する。」の要約1文 |
| Javadoc | 11 | クラス Javadoc に**仕様書の参照先**（ファイル + 節番号）を書く |
| Javadoc | 12 | `@param`・`@return`・`@throws`（例外にはエラーコード）を書く。段落は `<p>`、識別子は `{@code ...}` |
| Javadoc | 13 | 未実装・仮実装は**理由と解消時期**を Javadoc に書く（`TODO` だけを残さない）。コメントは「なぜ」を書く |
