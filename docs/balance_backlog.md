# AFK GAME — バランス調整バックログ

> **仕様は確定済みだが、実装後のプレイテストで数値を見直す**項目の一覧。
> 未確定仕様（実装をブロックするもの）は `open_specs.md` で管理する。両者を混ぜないこと。
> `open_specs.md` は未確定仕様が生じたときだけ置く（**不在＝未確定ゼロ**）。全解消したらファイルごと削除する。

## 1. 本書の位置づけ

| | `open_specs.md` | 本書 |
|---|---|---|
| 対象 | **仕様が決まっていない**項目 | 仕様は決まっているが**数値の妥当性が未検証**の項目 |
| 実装への影響 | ブロックする（決まらないと作れない） | ブロックしない（仮置き値で作れる） |
| 解消条件 | 仕様を確定し仕様書へ反映 | プレイテストで実測し数値を確定 |
| 解消タイミング | 該当Phaseの詳細設計まで | 該当Phaseの結合テスト〜リリース後 |

- 本書の項目は**すべて仕様書に反映済み**。仕様書側には「仮置き」と明記してある（未着手Phaseで仮置き値をまだ置いていないものは「未設定」と書く）
- 調整が完了したら仕様書の数値を更新し「仮置き」表記を削除、本書から該当行を削除する
- すべての項目が解消されたら本書自体を削除する

## 3. 調整の進め方

1. 該当Phaseの結合テストで実測値を取得する（周回時間・獲得量・到達階など）
2. 設計時の想定値と比較し、乖離が大きいものから調整する
3. 数値を変更したら**仕様書とマスターデータの両方**を更新し、[changelog.md](changelog.md) に追記する
4. 本書の該当行を削除する

- 数値変更はセーブデータの互換性に影響しない範囲に留める（構造変更を伴う場合はデータ移行方針に従う）
