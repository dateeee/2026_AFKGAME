### ISSUE-001: tower.py の Request スキーマが CamelModel でなく BaseModel を直接使用

| 項目 | 値 |
|------|-----|
| カテゴリ | フロント・バック統合整合性 |
| 重要度 | 高 |
| 関連ファイル | backend/app/routers/tower.py, backend/app/schemas/\_\_init\_\_.py |
| 該当箇所 | tower.py 行21〜33 |

**問題の説明:**

`tower.py` 内で定義された3つのリクエストスキーマが `pydantic.BaseModel` を直接継承しており、プロジェクト標準の `CamelModel` を使用していない。

```python
# backend/app/routers/tower.py 行21〜33
from pydantic import BaseModel

class TowerSelectRequest(BaseModel):       # ← BaseModel
    tower_id: str
    target_floor: int
    mode: str = "auto_repeat"

class TowerModeRequest(BaseModel):          # ← BaseModel
    mode: str

class RetreatConditionsRequest(BaseModel):  # ← BaseModel
    hp_threshold: float
```

一方、他の全スキーマ（shop, equipment, battle, auth, player）は `CamelModel` を使用:

```python
# backend/app/schemas/shop.py
from app.schemas import CamelModel

class BuyRequest(CamelModel):    # ← CamelModel
    item_id: str
    quantity: int
```

`CamelModel` は `populate_by_name=True` で snake_case / camelCase 両方を受け付けるが、`BaseModel` は snake_case のみ受け付ける。現在フロントが snake_case で送信しているため動作するが、フロントを camelCase に統一した場合に tower 系 API だけが壊れる。

**修正案:**

`tower.py` のスキーマを `CamelModel` に変更し、スキーマを `schemas/` ディレクトリに移動する:

```python
# backend/app/schemas/tower.py（新規作成）
from app.schemas import CamelModel

class TowerSelectRequest(CamelModel):
    tower_id: str
    target_floor: int
    mode: str = "auto_repeat"

class TowerModeRequest(CamelModel):
    mode: str

class RetreatConditionsRequest(CamelModel):
    hp_threshold: float
```

### ISSUE-002: フロント→バック リクエストボディの命名規則が不統一

| 項目 | 値 |
|------|-----|
| カテゴリ | フロント・バック統合整合性 |
| 重要度 | 高 |
| 関連ファイル | frontend/src/api/client.ts, backend/app/routers/tower.py, backend/app/schemas/ 各ファイル |
| 該当箇所 | client.ts 行141〜218 |

**問題の説明:**

フロントエンドの API クライアントが、エンドポイントによって snake_case と camelCase を混在して送信している。

**snake_case で送信:**
```typescript
// client.ts 行143〜144 — postTowerSelect
body: JSON.stringify({ tower_id: towerId, target_floor: targetFloor, mode })

// client.ts 行166〜167 — putRetreatConditions
body: JSON.stringify({ hp_threshold: hpThreshold })
```

**camelCase で送信:**
```typescript
// client.ts 行188 — postShopBuy
body: JSON.stringify({ itemId, quantity })

// client.ts 行200 — postEquip
body: JSON.stringify({ characterId, slot, equipmentId })

// client.ts 行208 — postEquipmentSell
body: JSON.stringify({ equipmentIds })

// client.ts 行215 — postEquipmentLock
body: JSON.stringify({ equipmentId })
```

バックエンドの `CamelModel`（`populate_by_name=True`）は両方受け付けるため、shop/equipment 系は動作する。しかし tower 系は `BaseModel` のため camelCase を受け付けない（ISSUE-001 と連動）。

**修正案:**

ISSUE-001 の修正後、フロント側を camelCase に統一する:

```typescript
// client.ts — postTowerSelect
body: JSON.stringify({ towerId, targetFloor, mode })

// client.ts — putRetreatConditions
body: JSON.stringify({ hpThreshold })
```

### ISSUE-008: 戦闘ログエントリが snake_case のまま返却される（意図的設計）

| 項目 | 値 |
|------|-----|
| カテゴリ | フロント・バック統合整合性 |
| 重要度 | 低 |
| 関連ファイル | frontend/src/types/game.ts, backend/app/services/battle_service.py |
| 該当箇所 | game.ts 行71〜95 |

**問題の説明:**

戦闘ログエントリ（`BattleLogEntry`）のフィールドが snake_case のまま返却されている:

```typescript
// frontend/src/types/game.ts 行71
/**
 * 戦闘ログエントリー
 * NOTE: battle_logsはCamelModel変換対象外。バックエンドからsnake_caseのまま返却される
```

**修正案:**

現状維持で問題なし。将来的に camelCase に統一する場合は、バックエンドのログ生成箇所（`battle_service.py` 内の `dict` 構築）を camelCase に変更し、フロントの型定義も更新する。

### ISSUE-010: SettingsUpdate の autoSellRarity の null リセット設計

| 項目 | 値 |
|------|-----|
| カテゴリ | アーキテクチャ方針適合 |
| 重要度 | 低 |
| 関連ファイル | frontend/src/views/SettingsView.vue, backend/app/routers/game.py, backend/app/schemas/player.py |
| 該当箇所 | SettingsView.vue 行28〜33, game.py 行45〜52 |

**問題の説明:**

`SettingsUpdate` スキーマで `auto_sell_rarity: str | None = None` と定義されている。Pydantic では「フィールド未指定」と「明示的に null を送信」が区別できないケースがある。

フロント側の対処:
```typescript
// SettingsView.vue 行28〜33
async function updateAutoSellRarity(value: string) {
  const rarity = value || null
  gameStore.settings.autoSellRarity = rarity
  if (USE_API) {
    await putSettings({ autoSellRarity: value || '' })  // 空文字を送信
  }
}
```

バックエンド側の対処:
```python
# game.py 行52
if update.auto_sell_rarity is not None:
    settings.auto_sell_rarity = update.auto_sell_rarity if update.auto_sell_rarity != "" else None
```

**現状**: フロントが `""` (空文字) を送信し、バックエンドが `""` → `None` に変換するため**動作する**。ただし、API 仕様として `null` を直接送信した場合は更新されない（`is not None` チェックをパスしない）。

**修正案:**

現状の実装で動作はするが、API 設計として改善の余地がある。将来的には以下のいずれかを検討:
- Pydantic の `UNSET` sentinel パターンを使用して「未指定」と「null」を区別
- 現状のフロント実装（空文字→null変換）をAPI仕様として明文化
