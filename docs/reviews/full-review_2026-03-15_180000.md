### ISSUE-001: ポーション自動使用閾値のUI選択肢が仕様書と不一致

| 項目 | 値 |
|------|-----|
| カテゴリ | 仕様書-コード整合性 |
| 重要度 | 高 |
| 関連ファイル | frontend/src/views/SettingsView.vue, docs/glossary.md, docs/design/game_spec.md |
| 該当箇所 | SettingsView.vue 行44〜52 / glossary.md ポーション閾値の項 |

**問題の説明:**
仕様書（game_spec.md、master_data.md、ER図）は既に「10%〜50%、10%刻み、デフォルト30%」に統一済み。しかし**コードが仕様に追従していない**。

フロントエンドの設定画面は旧仕様のまま3択:

```html
<!-- SettingsView.vue 行49-51 -->
<option :value="0.3">30%</option>
<option :value="0.5">50%</option>
<option :value="0.7">70%</option>
```

- 10%、20%、40%の選択肢が欠落
- **70%は仕様上限の50%を超えている**（ゲームバランスへの影響あり）

また、`docs/glossary.md`のポーション閾値の記述も「10/30/50/70%」となっており、仕様書と不一致。

**修正案:**

1. `SettingsView.vue`の選択肢を仕様通りに変更:

```html
<option :value="0.1">10%</option>
<option :value="0.2">20%</option>
<option :value="0.3">30%</option>
<option :value="0.4">40%</option>
<option :value="0.5">50%</option>
```

2. `docs/glossary.md`のポーション閾値の記述を「10%〜50%、10%刻み」に修正

### ISSUE-012: battleStoreの戦闘ログが無制限に蓄積しメモリを圧迫

| 項目 | 値 |
|------|-----|
| カテゴリ | アーキテクチャ方針適合 |
| 重要度 | 中 |
| 関連ファイル | frontend/src/stores/battleStore.ts, frontend/src/composables/usePolling.ts |
| 該当箇所 | battleStore.ts 行9-11 / usePolling.ts 行28-30 |

**問題の説明:**
`battleStore`の`addBattleLogs()`は受信したログを無制限にpushし続ける:

```typescript
// battleStore.ts 行9-11
function addBattleLogs(logs: BattleLogEntry[][]) {
  battleLogs.value.push(...logs)  // 上限なし
}
```

仕様書では:
- DB保持ログ: 直近100件
- レスポンスあたり: 直近50件
- GameView表示: 最新10 tick分

長時間プレイ時にフロントのメモリが増加し続ける。

**修正案:**
`addBattleLogs()`に上限を設ける:

```typescript
const MAX_FRONTEND_LOGS = 100

function addBattleLogs(logs: BattleLogEntry[][]) {
  battleLogs.value.push(...logs)
  if (battleLogs.value.length > MAX_FRONTEND_LOGS) {
    battleLogs.value = battleLogs.value.slice(-MAX_FRONTEND_LOGS)
  }
}
```
