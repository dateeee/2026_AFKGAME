### ISSUE-001: ER図 User テーブルに仕様書にない `auth_type` が存在し、`is_guest` / `display_name` が欠落

| 項目 | 値 |
|------|-----|
| カテゴリ | 仕様書との整合性 |
| 重要度 | 高 |
| 関連ファイル | diagrams/er_diagram.md, docs/tech/tech_auth.md, backend/app/models/user.py |
| 該当箇所 | er_diagram.md 行14〜23 / tech_auth.md Users テーブル定義 |

**問題の説明:**
ER図の User テーブルには `enum auth_type "guest / email / google"` (行19) が定義されているが、tech_auth.md の仕様には `auth_type` カラムは存在しない。代わりに仕様では `is_guest: bool` と `display_name: str` が定義されている。

ER図:
```
User {
    uuid id PK
    string email UK "nullable (guest)"
    string password_hash "nullable (guest/OAuth)"
    string google_id UK "nullable"
    enum auth_type "guest / email / google"      ← 仕様にない
    boolean email_verified "default false"
    datetime created_at
    datetime last_login_at
    // is_guest が欠落
    // display_name が欠落
}
```

tech_auth.md 仕様:
```
| is_guest | bool | default: true | Guest marker |
| display_name | str | | User display name |
```

コード (`backend/app/models/user.py`) も仕様どおり `is_guest` と `display_name` を実装済み。

**修正案:**
`diagrams/er_diagram.md` の User エンティティから `auth_type` を削除し、`is_guest boolean "default true"` と `string display_name` を追加する。

### ISSUE-003: APIシーケンス図のゲスト作成レスポンスが実装と不一致

|------|-----|
| カテゴリ | コードとの整合性 |

| 該当箇所 | api_sequence.md 行24 / auth.py ゲストエンドポイント |

**問題の説明:**
シーケンス図「1. 初回アクセス（ゲスト作成）」のレスポンスが:
```
API-->>B: { guest_token: "uuid-v4" }
```
と記載されているが、実際のコードは `AuthResponse` を返す:
```python
# backend/app/schemas/auth.py
class AuthResponse(CamelModel):
    access_token: str
    refresh_token: str
    user: UserInfo
```

JWT認証ベースの実装であり、生の UUID トークンではない。また行26でも `B->>LS: guest_token を保存` となっているが、実際には `access_token` と `refresh_token` を別々に保存する。

**修正案:**
シーケンス図のレスポンスを以下に修正:
```
API-->>B: { access_token, refresh_token, user: {id, is_guest: true} }
B->>LS: refresh_token を保存
B->>B: access_token をメモリ(Pinia)に保持
```
