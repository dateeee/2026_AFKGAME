### ISSUE-1502: 64bit ゴールドが JSON 上で素の数値表現になっており、精度保持策が未定義

| 項目 | 値 |
|------|-----|
| カテゴリ | 整合性 |
| 重要度 | 中 |
| 関連ファイル | docs/tech/basic/tech_data/game_state.md, docs/tech/basic/tech_backend.md, docs/tech/basic/tech_data.md |
| 該当箇所 | game_state.md §1.1.1、tech_backend.md §4 |
| 検出可能工程 | 本レビュー |

**問題の説明:**

`tech_backend.md` §4 はゴールドを「`BIGINT`（64bit）カラムで管理」とし、設定値 `afkgame.max.gold` に `9223372036854775807`（`Long.MAX_VALUE`）を置いている。`game_spec.md` §5 も「ゴールド上限: 9,223,372,036,854,775,807」と同じ値を要件として定めている。

一方 `game_state.md` §1.1.1 の JSON 例は素の JSON 数値である。

```
"gold": 1500,
```

JavaScript の `Number` が精度を保てるのは 2^53-1（≈9.007×10^15）までであり、上限値はこれを 3桁上回る。文字列化などの精度保持策は `game_state.md`・`tech_data.md`・`tech_backend.md` のいずれにも定義されていない。

**修正案:**

- `docs/tech/basic/tech_data.md` に「64bit整数（ゴールド等）は JS Number の安全範囲（2^53-1）を超え得るため、JSON 上は文字列でシリアライズする」旨の規約を1行追記する
- `docs/tech/basic/tech_data/game_state.md` §1.1.1 の `"gold": 1500,` を `"gold": "1500",` へ変更する

**反証:** サーバー権威（`tech_architecture.md`「フロントは…テキストログとして表示するだけ」）と、表示が K/M/B/T/Qa/Qi の短縮表記へ丸められる設計により、実害が表示上の誤差に留まるため重要度を高→中へ下げた。あわせて、`player.md` の `characters.exp` も同じ `BIGINT` であるため、**ゴールドだけを文字列化すると型表現の不統一が新たに生じる**（修正時は対象列の範囲を決めること）。
