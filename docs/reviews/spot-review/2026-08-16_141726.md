### ISSUE-001: キャラクターレアリティ倍率をステータス計算のどの段階で乗じるかが定義されていない

| 項目 | 値 |
|------|-----|
| カテゴリ | 整合性 |
| 重要度 | 高 |
| 関連ファイル | docs/design/systems/battle.md, docs/design/systems/character.md |
| 該当箇所 | battle.md §2.2「ステータス計算の適用順序」95〜109行目, character.md §2.1「キャラクターレアリティ」34〜41行目 |
| 検出可能工程 | 基本設計（データモデル確定時のステータス計算経路の突合） |

**問題の説明:**

`battle.md` §2.2 は戦闘時ステータスの適用順序を①〜⑤で一意に定めている。

```
① 素ステータス = 基礎値 + (成長率 × (LV - 1))
② 強化後 = 素ステータス × (1 + 限界突破%) × (1 + 転生ボーナス%)
③ 装備込み = 強化後 + 装備値
④ パッシブ込み = 装備込み × (1 + パッシブスキル%)
⑤ 最終値 = パッシブ込み × (1 + バフ%) × (1 + デバフ%) × (1 + 環境効果%)
```

一方 `character.md` §2.1 は別の計算を定義している。

> - 計算: `実効ステータス = 基本ステータス × レアリティ倍率`

**①〜⑤のどこにもレアリティ倍率が現れない。** ①の「基礎値」に既に乗算済みなのか、①の直後（②の限界突破と同じ位置）なのか、⑤の後なのかで最終ステータスが変わる。加算である装備値（③）を挟むため、適用位置の違いは単なる交換法則では吸収されない。

同じ節の限界突破・転生ボーナスには「限界突破・転生ボーナスは恒久的な強化（**基礎に近い位置で乗算**）」という位置づけの注記があるのに対し、レアリティ倍率にはそれに相当する記述がどちらのファイルにもない。レアリティは Phase 3 の酒場ガチャ（コモン〜レジェンダリー）で全キャラに付くため、マスターデータのバランス設計（基礎ステータス・成長率）の前提そのものが適用位置に依存する。

**修正案:**

- `docs/design/systems/battle.md` §2.2「ステータス計算の適用順序」のコードブロックへレアリティ倍率を明示的に組み込む。レアリティは限界突破・転生と同じ「キャラクター固有の恒久強化」であり、`CHARACTERS_OVERVIEW.md` §2 の倍率がキャラ定義側の属性であることから、**①に含める**のが整合する:
  `① 素ステータス = (基礎値 + (成長率 × (LV - 1))) × レアリティ倍率`
  あわせて下の箇条書きへ1行足す: `- レアリティ倍率はキャラクター固有の恒久補正（成長後・強化前に乗算）`
- `docs/design/systems/character.md` §2.1「キャラクターレアリティ」の「計算: `実効ステータス = 基本ステータス × レアリティ倍率`」行を削除し、`battle.md` §2.2「ステータス計算の適用順序」①を正として参照する形へ改める（同節は既にレアリティ倍率の具体値を `CHARACTERS_OVERVIEW.md` §2 へ委譲済みで、計算式だけが二重定義になっている）。
- ①に含める案を採らない場合も、**どちらか一方のファイルにのみ適用段階を書く**こと。両ファイルに式を残すと再発する。
