### ISSUE-001: アプリケーションログ仕様が未定義

| 項目 | 値 |
|------|-----|
| カテゴリ | 網羅性 |
| 重要度 | 高 |
| 関連ファイル | docs/tech/tech_spec.md, docs/open_specs.md |
| 該当箇所 | tech_spec.md 全体 / open_specs.md 技術・インフラ |

**問題の説明:**
プロジェクト全体でアプリケーションログ（リクエストログ、エラーログ、デバッグログ）に関する仕様が一切定義されていない。現在のバックエンド実装ではUvicornのデフォルトアクセスログのみが出力され、以下の情報が欠落している:

- 401エラー時の詳細（トークン不正の種別: ヘッダー欠落/形式不正/プレイヤー未登録）
- リクエストボディ・レスポンスボディの内容
- 例外のスタックトレース
- ビジネスロジック内の処理経過（戦闘計算、オフライン計算等）
- 構造化ログ（JSON形式等）のフォーマット定義

**修正案:**
- tech_spec.md に「ログ設計」セクションを新設し、以下を定義:
  1. **ログレベル方針**: DEBUG / INFO / WARNING / ERROR の使い分け基準
  2. **ログフォーマット**: 構造化ログ（JSON）のスキーマ（timestamp, level, logger, message, request_id, player_id, extra）
  3. **出力先**: stdout（開発）/ ファイル or ログ収集サービス（本番）
  4. **リクエストログ**: HTTPメソッド, パス, ステータスコード, 処理時間, player_id
  5. **エラーログ**: 例外クラス, メッセージ, スタックトレース, リクエストコンテキスト
  6. **認証エラーログ**: 401/403時の失敗理由（header_missing / invalid_format / player_not_found / token_expired）
  7. **ビジネスロジックログ**: 戦闘tick処理, オフライン計算の要約（処理tick数, 結果）
  8. **機密情報の除外**: トークン値はマスク、パスワードは出力禁止
- open_specs.md の「技術・インフラ」セクションに未確定項目として追加

### ISSUE-002: エラーハンドリングミドルウェアの仕様不足

| 項目 | 値 |
|------|-----|
| カテゴリ | 網羅性 |
| 重要度 | 高 |
| 関連ファイル | docs/tech/tech_spec.md |
| 該当箇所 | tech_spec.md §6（エラーハンドリング） |

**問題の説明:**
tech_spec.md §6 ではフロントエンド側のエラーハンドリング（指数バックオフ3回リトライ）のみ記載されている。バックエンド側のエラーハンドリング戦略（グローバル例外ハンドラ、エラーレスポンス形式の統一、未捕捉例外の処理）が未定義。

現在の実装では各エンドポイントが個別にHTTPExceptionを投げるのみで:
- 統一されたエラーレスポンス形式がない
- 未捕捉例外が500として返る際のログ出力がない
- リクエストIDによるトレーサビリティがない

**修正案:**
- tech_spec.md §6 に「バックエンドエラーハンドリング」を追加:
  1. 統一エラーレスポンス形式: `{ "error": { "code": "PLAYER_NOT_FOUND", "message": "...", "request_id": "..." } }`
  2. グローバル例外ハンドラ: 未捕捉例外 → 500 + スタックトレースログ出力
  3. リクエストID: 各リクエストにUUIDを付与、レスポンスヘッダーとログに含める
  4. エラーコード体系: AUTH_*, BATTLE_*, GAME_*, SHOP_* 等のプレフィックス

### ISSUE-006: config.py のログ設定コメントが誤解を招く

| 項目 | 値 |
|------|-----|
| カテゴリ | 整合性 |
| 重要度 | 低 |
| 関連ファイル | backend/app/config.py |
| 該当箇所 | config.py 「# ログ設定」コメント |

**問題の説明:**
backend/app/config.py に `# ログ設定` というコメントがあるが、その下の定数 `MAX_BATTLE_LOG_RECORDS = 100` と `MAX_LOG_PER_RESPONSE = 50` はアプリケーションログではなく**戦闘ログ（ゲーム内データ）**の設定である。コメントが誤解を招く。

**修正案:**
- コメントを `# 戦闘ログ設定（ゲーム内データ）` に変更
