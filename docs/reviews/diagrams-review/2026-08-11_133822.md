### ISSUE-701: ボスラッシュのベスト記録更新が「全滅時」のまま図に残り、残HPが常に0になる

| 項目 | 値 |
|------|-----|
| カテゴリ | 仕様書との整合性 |
| 重要度 | 高 |
| 関連ファイル | docs/diagrams/battle_flow/bossrush.md, docs/design/systems/endgame.md, docs/tech/basic/tech_db/battle.md |
| 該当箇所 | bossrush.md 40〜44行目（`Wipe` → `UpdateBest` → `SaveBest`） |
| 検出可能工程 | 基本設計（ISSUE-1301 の修正時に図まで波及させる） |

**問題の説明:**

ISSUE-1301 の修正で仕様側は「突破時に記録」へ確定した。

`systems/endgame.md` 10行目:
> 記録（到達ウェーブ・タイブレーク用の残HP合計）は**ウェーブを突破した時点**で更新する。全滅したウェーブは突破していないため記録の対象外。

`tech_db/battle.md` §2 38行目:
> `best_wave_hp` … `best_wave` を更新したウェーブの**突破直後に同時更新**する（全滅したウェーブは突破していないため対象外）

一方 `bossrush.md` のフローは**全滅ブランチにしか記録更新を持たない**:

```
    Wipe["全滅!\n累積報酬は没収なし(確定取得)"]
    Wipe --> UpdateBest{"最高記録\n更新?"}
    UpdateBest -->|Yes| SaveBest["ベスト更新:\nbestWave = currentWave\nbestWaveHp = 残HP合計"]
```

この図のとおり実装すると、(1) `currentWave` は**全滅したウェーブ**＝未突破のウェーブが記録され、(2) `bestWaveHp` は全滅時の残HP合計＝**常に 0** になる。ISSUE-1301 が仕様側で潰した不具合が、図の側にそのまま残っている。

**修正案:**

- `docs\diagrams\battle_flow\bossrush.md` の記録更新を**ウェーブ突破後**へ移す。30〜44行目を次の構造へ改める:
  - `WaveReward`（ウェーブ報酬）の直後に記録更新を挟む:
    `WaveReward --> UpdateBest{"最高記録\n更新?\n(currentWave > bestWave)"}`
    `UpdateBest -->|Yes| SaveBest["ベスト更新:\nbestWave = currentWave\nbestWaveHp = 突破直後の残HP合計"]`
    `UpdateBest -->|No| Milestone`
    `SaveBest --> Milestone`
  - 全滅ブランチからは記録更新を外し、終了だけにする:
    `Wipe["全滅!\n累積報酬は没収なし(確定取得)\n※このウェーブは未突破のため記録対象外"]`
    `Wipe --> End([ボスラッシュ終了])`
- 併せて図の下へ1行の注記を足し、正の所在を示す: 「記録時点の正は [systems/endgame.md](../../design/systems/endgame.md) §2.11、列定義は [tech_db/battle.md](../../tech/basic/tech_db/battle.md) §2」

### ISSUE-702: APIシーケンス図の全滅ブランチが「ベスト記録更新判定」を終了時に行っている

| 検出可能工程 | 基本設計（ISSUE-1301 の修正時に図まで波及させる） |

**問題の説明:**

```

        Note over API: tick処理内で全滅検知
```

`ベスト記録更新判定` を**終了処理の中**に置いているが、`systems/endgame.md` 10行目・`tech_db/battle.md` §2 38行目は**ウェーブ突破直後**の更新と定めている。ISSUE-701 と別ファイルのため、片方だけ直すと図どうしが食い違う。

**修正案:**
