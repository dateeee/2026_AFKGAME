### ISSUE-101: クラス図 `DailyItem` にステータス・レベル属性が無く、ER図と一致しない

| 項目 | 値 |
|------|-----|
| カテゴリ | 設計図間の整合性 |
| 重要度 | 高 |
| 関連ファイル | diagrams/class_diagram/item.md, diagrams/er_diagram/item.md, docs/tech/tech_shop.md |
| 該当箇所 | class_diagram/item.md 行105〜112 `class DailyItem` |

**問題の説明:**

ER図 `ShopDailySlot` は `base_id` / `level` / `stat_atk` / `stat_def` / `stat_hp` / `stat_spd` を持つが、クラス図 `DailyItem` は次の6属性しか持たない。

```
class DailyItem {
    +int slotIndex  0-4
    +string itemId  装備マスターID
    +EquipSlot category  weapon/armor/accessory
    +Rarity rarity  common-rare
    +int price  固定価格テーブル
    +bool sold  購入済みか
}
```

差分（スクリプト出力）: ER図にあってクラス図に無い属性 = `base_id, level, stat_atk, stat_def, stat_hp, stat_spd`。

tech_shop.md §4 は「抽選結果（レアリティ・レベル・ステータス）は**生成時に確定して保存する**。表示した内容と購入結果を一致させるため、購入時に引き直さない」と定めている。クラス図のままでは品揃え表示にステータスを出せず、購入のたびに引き直す実装になる。加えて属性名 `itemId` はER図・tech_shop.md §4 の `base_id` と不一致（ISSUE-102 と同じ命名系統の問題）。

**修正案:**

- `diagrams/class_diagram/item.md` `class DailyItem`: 属性を次のとおり修正する
  - `+string itemId` → `+string baseId  装備マスターID`
  - 追加: `+int level  装備レベル (= 最高到達階層, 下限1)`
  - 追加: `+int statAtk  nullable`, `+int statDef  nullable`, `+int statHp  nullable`, `+int statSpd  nullable`

### ISSUE-102: クラス図 `DailyItem.category` の型が `EquipSlot` になっている

| 項目 | 値 |
|------|-----|
| カテゴリ | 設計図間の整合性 |
| 重要度 | 中 |
| 関連ファイル | diagrams/class_diagram/item.md, diagrams/er_diagram/item.md, docs/design/systems/equipment.md |
| 該当箇所 | class_diagram/item.md 行108 |

**問題の説明:**

クラス図は `+EquipSlot category  weapon/armor/accessory` と、装備スロット型（`EquipSlot`）にカテゴリ値を入れている。しかし systems/equipment.md §2.4「装備カテゴリ（9スロットの分類）」のとおり、スロット（weapon/shield/head/body/arms/waist/legs/ears/ring の9種）とカテゴリ（weapon/armor/accessory の3種）は別概念で、ER図も `enum category "weapon / armor / accessory"` と `enum slot "weapon/shield/head/..."` を区別している。型を誤ると `armor` や `accessory` が `EquipSlot` の値として実装される。

**修正案:**

- `diagrams/class_diagram/item.md` 行108: `+EquipSlot category` を `+EquipCategory category  weapon/armor/accessory` に修正する
- 同ファイル内に `EquipSlot` の enum クラス定義がある場合、`EquipCategory`（weapon / armor / accessory の3値）を新設して併記する

### ISSUE-106: APIシーケンス図に日替わり購入の失敗経路が無い

| 項目 | 値 |
|------|-----|

| 該当箇所 | api_sequence/gameplay.md §5 ショップ購入フロー（行92〜101） |

**問題の説明:**

tech_shop.md §3 は失敗経路を4つ定義している（範囲外 `422` / 売り切れ `400 SHOP_ITEM_SOLD_OUT` / ゴールド不足 `400 SHOP_INSUFFICIENT_GOLD` / トランザクション失敗時の全件ロールバック）。図は成功パスのみを描いており、エラーコードが1つも現れない。tech_logging.md のエラーコード体系には両コードが登録済みで、図だけが未反映。

**修正案:**

- `diagrams/api_sequence/gameplay.md` §5: 日替わり購入の `B->>API: POST /api/shop/buy` の直後に `alt` ブロックを追加する

  - `else ゴールド不足` → `API-->>B: 400 { code: "SHOP_INSUFFICIENT_GOLD" }`
  - `else 正常` → 現在の成功パス（gold減算・Equipment生成・sold=true）
  - `end`
