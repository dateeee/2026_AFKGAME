### ISSUE-704: 新設したログアウト手順が、`tech_auth.md` §7 のリフレッシュトークン保管方式と両立しない

| 項目 | 値 |
|------|-----|
| カテゴリ | 整合性 |
| 重要度 | 中 |
| 関連ファイル | docs/tech/tech_auth.md |
| 該当箇所 | tech_auth.md 行58（§3 ログアウト 2.）, 行173（§7 トークン管理） |
| 検出可能工程 | 本レビュー（詳細設計。§3 追記時に §7 との突合が漏れた） |

**問題の説明:**

ISSUE-602 の修正で追加された手順が、同一ファイル §7 の保管方式と整合しない。

- `tech_auth.md:58`（§3 ログアウト 2.）: 「フロントはメモリ上のアクセストークンと**保持中のリフレッシュトークンを破棄し**、ログイン画面へ戻る」
- `tech_auth.md:173`（§7 トークン管理）: 「リフレッシュトークン: \`httpOnly\` Cookie **または** LocalStorage に保持」

`httpOnly` Cookie を選んだ場合、JavaScript から Cookie を読み書きできないため、フロントは自力で破棄できない。サーバーが `POST /api/auth/logout` のレスポンスで失効させる（`Set-Cookie` に `Max-Age=0`）必要があり、ログアウト処理の責務がフロント側とサーバー側で分岐する。現行文はフロント単独で破棄できる前提になっている。

また §7 は「\`httpOnly\` Cookie または LocalStorage」と保管先を2択のまま残しており、どちらを採るかで §3 ログアウトの手順が変わる。

**修正案:**

- `docs/tech/tech_auth.md` §7「トークン管理」の該当行で保管先を1つに確定する。ゲストID（LocalStorage）と扱いを揃え、フロント完結でログアウトできる **LocalStorage** を採る。
  `- リフレッシュトークン: LocalStorage に保持（\`httpOnly\` Cookie は採らない。ログアウト・ゲストID破棄をフロント側で完結させるため）`
- `docs/tech/tech_auth.md` 行58（§3 ログアウト 2.）を保管先に合わせて明示する。
  `2. フロントはメモリ上のアクセストークンと LocalStorage のリフレッシュトークンを破棄し、ログイン画面へ戻る`
- 保管先を Cookie に寄せる判断をする場合は、代わりに §3 ログアウト 2. を「サーバーが \`Set-Cookie: Max-Age=0\` で失効させ、フロントはメモリ上のアクセストークンのみ破棄する」とし、`tech_api.md` §5 の `POST /api/auth/logout` 行にも Cookie 失効の責務を追記すること。
- 実装（`backend/app/routers/auth.py` / `frontend/src/stores/`）が既にどちらかを採っている場合の突合は `full-review` の担当。
