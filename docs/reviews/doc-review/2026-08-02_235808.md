### ISSUE-901: 工程区切りの既定（`/clear`）が CLAUDE.md のみ更新され、profile.md §6 が旧規律のまま

| 項目 | 値 |
|------|-----|
| カテゴリ | 整合性 |
| 重要度 | 中 |
| 関連ファイル | .claude/project/profile.md, CLAUDE.md |
| 該当箇所 | profile.md 行82（§6 コスト規律 #6） / CLAUDE.md 行56 |
| 検出可能工程 | 本レビュー（review-docs.md §6 ルール11〔本巡で追加〕を d35273a の時点で適用していれば検出できた） |

**問題の説明:**

コミット `d35273a` が CLAUDE.md の工程区切り規律を更新したが、同じ規律を重複して持つ `profile.md` §6 が旧文言のまま残った。

```
CLAUDE.md:56
  工程の区切り（レビュー完了・コミット後）では `/clear` を既定として提案する
  （同一タスクを続ける場合のみ `/compact`）。レビュー→修正適用（doc-review → fix-specs）は
  別セッションに分ける
.claude/project/profile.md:82
  | 6 | 工程の区切り（レビュー完了・コミット後）で `/compact` または `/clear` を提案する |
```

`profile.md` は「全スキルが最初に読む」共通プロファイルであり、スキルは §6 に従って `/compact` を無条件に提案しうる。CLAUDE.md の「`/clear` 既定・レビュー→修正適用は別セッション」という新規律がスキル動作に反映されない経路になる（ISSUE-802 の `dev.md` と同型: プロファイルは他スキルの判断根拠）。

**修正案:**

- `.claude/project/profile.md:82` を CLAUDE.md:56 と同内容へ更新する。

  ```
  | 6 | 工程の区切り（レビュー完了・コミット後）で `/clear` を既定として提案する（同一タスクを続ける場合のみ `/compact`）。レビュー→修正適用は別セッションに分ける |
  ```

- コスト規律は CLAUDE.md と profile.md §6 に同文で重複しており、今回のような片側更新が再発しうる。どちらを正とするかを決めて [spec_ownership.md](../../spec_ownership.md) へ登録すること（推奨: スキルが読む `profile.md` §6 を正とし、CLAUDE.md は要約 + リンク。ただし CLAUDE.md は常時読込のため全削除はしない判断もあり得る。境界の確定は fix-specs のルール9に従う）。
