# ドキュメント規約 — レビュー結果アーカイブの運用

> [documentation_rules.md](../documentation_rules.md) の子ファイル（索引側が正）。担当: §9。

## 9. レビュー結果アーカイブの運用

`docs/reviews/**` は文字数上限の対象外（[§2](../documentation_rules.md)）だが、**ファイル数は工程を回すたびに増え続ける**ため、一覧を開いたときの見通しが失われる。総量ではなく **一度に視界へ入る件数** を一定に保つことで対処する。

### 9.1 構成

```
docs/reviews/
├── doc-review/               # ディレクトリ名 = レビュースキル名
│   ├── 2026-08-02_162707.md  # 直下は最新10件まで
│   └── archive/              # 11件目以降。削除はしない
├── diagrams-review/
├── full-review/              # backend-review / frontend-review も同形
└── skill-improvement/        # スキル外の一回限りのレポート（ルール5）
```

| # | ルール |
|---|-------|
| 1 | 1スキル = 1ディレクトリ。ファイル名は `YYYY-MM-DD_HHMMSS.md`。種別はディレクトリ名が示すため**ファイル名に繰り返さない** |
| 2 | ディレクトリ直下は**最新10件**まで。超過分は `archive/` へ移す。**削除はしない**（過去の指摘を追える状態を保つ） |
| 3 | 退避は `python scripts/rotate_reviews.py --apply`。レビュー結果の保存直後に実行する（`--list` で全件、引数なしで退避対象の確認のみ） |
| 4 | 差分モードの起点として読むのは**直下の最新1件のみ**。`archive/` は通常の作業では読まない |
| 5 | スキルが出力しない一回限りのレポート（横断調査・改善記録）は `<テーマ名>/` へ置き、`rotate_reviews.py` の `SLOTS` へは登録しない（定期的に増えないため退避が要らない）。ファイル名は日付 + テーマでよい |
| 6 | レビュー結果**以外**のファイルを `docs/reviews/` へ置かない（作業用の台帳は `docs/backlog/`。[§10](directories.md)）。`rotate_reviews.py` が直下の `*.md` を WARN で検出する |
| 7 | 過去レポートの本文は**修正しない**（規約の適用対象外）。ディレクトリ再編前のリンク切れが残るが、`check_docs.py` の除外に登録済み |

### 9.2 ディレクトリ分割だけでは足りない理由

スキル別に分けると1ディレクトリあたりの件数は 1/5 になるが、**各ディレクトリはその後も同じ速度で増え続ける**ため、時間が経てば同じ状態に戻る。件数上限と退避先（`archive/`）をセットにして初めて、どのディレクトリを開いても見える件数が一定に保たれる。
