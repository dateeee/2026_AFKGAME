# ドキュメント規約 — docs/ のディレクトリ構成

> [documentation_rules.md](../documentation_rules.md) の子ファイル（索引側が正）。担当: §10。

## 10. docs/ のディレクトリ構成

置き場所は **性質（何のために読むか・どう更新されるか）** で決める。

| 分類 | ディレクトリ | 中身 | 更新のされ方 |
|------|------------|------|------------|
| 成果物 | `design/` `tech/` `data/` `diagrams/` | 仕様・設計・マスターデータ・設計図 | 工程の成果として確定する |
| 進め方 | `process/` | 工程定義・ドキュメント規約・正の所在マップ | 運用を変えるときだけ |
| 状態 | `backlog/` | 未確定仕様・見直す数値・実装の疑義・引き継ぎ・効率メモ | 工程を回すたびに増減し、解消したら消す |
| 記録 | `reviews/` | レビュー結果（[§9](reviews.md)） | 追記のみ（自動生成） |
| 横断 | `docs/` 直下 | `glossary.md`・`changelog.md` | — |

- **直下へ置いてよいのは全分類から参照される横断ファイルだけ**。1つの分類に属するものは該当ディレクトリへ入れる
- 成果物の3領域は同じ形をとる: **索引1件 + 分類ディレクトリ**（例: `design/game_spec.md` + `requirements/`・`systems/`）。索引と子ディレクトリは兄弟に置く（[§6.1](../documentation_rules.md)）
- `backlog/` は**ファイルが消えることが正常**（`open_specs.md` は全解消でファイルごと削除する）。ほかのファイルが残るためディレクトリは空にならない
