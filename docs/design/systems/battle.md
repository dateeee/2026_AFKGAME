# ゲーム仕様 — 戦闘・HP回復

> [game_spec.md](../game_spec.md) §2.2 / §2.3。実装アルゴリズムは [tech_battle.md](../../tech/detail/tech_battle.md)。

## 2.2 戦闘システム

### 処理方式 — ハイブリッドティック制
戦闘はバックエンド側で **一定間隔（tick）ごとに処理** する。
ブラウザを開いていてもいなくても、サーバー上でゲームが進行する。

| 状態 | 処理方式 | 間隔 |
|------|---------|------|
| オンライン | フロントが定期的にAPIをポーリング | 60秒ごと |
| オフライン | 復帰時にサーバーが経過時間分をまとめて計算 | — |

### 1 tick の流れ
```
[1 tick = 60秒]

1. 行動順決定（SPD順）
2. 各キャラクターが自動で行動（攻撃 / スキル）
3. ダメージ計算・HP更新
4. 敵撃破判定 → 報酬付与
5. 階クリア判定 → 撤退条件チェック → 次の階 or 撤退
6. 結果を保存 + 戦闘ログ生成
```

### 基本フロー
```
塔選択（目標階・撤退条件・周回モード設定）→ 1階から自動戦闘開始
→ 各階で1戦闘 → 勝利で次の階へ → tick ごとにオート戦闘
→ 撤退条件到達 or 目標階クリア → 報酬獲得
→ 周回モードに応じて 1階から再突入 or 停止
```

### 塔進行モード
塔選択時に以下のモードを選択できる:

| モード | 動作 |
|--------|------|
| **自動周回**（デフォルト） | 目標階クリア後、1階から自動で再突入する |
| **クリア後停止** | 目標階クリア後、戦闘を停止する（報酬確認・装備変更などに便利） |

- 進行中にいつでもモードを切り替え可能
- 進行中に **「リタイア」** を選択すると、現在の戦闘が終了した時点で撤退する（戦闘途中で即中断はしない）
- リタイア時、それまでに獲得した報酬は保持される（没収なし）
- オフライン中は選択中のモードに従って自動処理される

### 目標階設定
- 塔に挑戦する前に **目標階** を設定できる
- 選択可能範囲: 1階 〜 **その塔の到達済み最高階 + 1**（未挑戦の塔は1階のみ）
  - 「到達済み最高階」は**塔ごとに個別管理**する（他の塔での到達階は影響しない）
  - 上限が `+1` なのは、新しい階を1階ずつ開拓できるようにするため。上限を到達済み最高階そのものにすると次の階へ進む手段がなくなる
  - 塔の総階数を超える値は設定できない（上限は `min(到達済み最高階 + 1, 総階数)`）
- **上限追従**: 目標階が上限と一致している状態で新しい階をクリアすると、目標階を自動的に +1 する。放置中でも手動操作なしで開拓が進む
  - 目標階を上限より低く設定している場合は追従しない（プレイヤーの意図した周回階を維持する）
- 目標階に到達しクリアすると、進行モードに応じてループまたは停止する
- 未到達の階（到達済み最高階 + 2 以上）は目標に設定できない

### 撤退条件
塔選択時に以下の撤退条件を設定できる（複数同時に有効化可能）:

| 条件 | 動作 |
|------|------|
| **目標階到達**（デフォルト） | 目標階をクリアしたら撤退し、進行モードに従う |
| **HP閾値撤退** | パーティのHPが設定割合（例: 30%）以下になったら、次の階に進まず撤退する |

- **HP閾値のチェックタイミング**: 各階の戦闘が完了した後に判定する。閾値以下であれば次の階に進まず撤退する（その階の報酬は獲得済み）
- HP閾値撤退が発動した場合、それまでに獲得した報酬は保持される
- 撤退後、自動周回モードなら1階から再スタートする
- どの撤退条件も設定しない場合は、目標階到達のみが撤退トリガーとなる
- **全滅時は常に強制撤退**（撤退条件とは独立。詳細は「全滅時の処理」を参照）

### ターンとtickの関係
- **1ターン = 20秒**、**1 tick = 60秒** → 1 tick内に **3ターン** を処理
- tickごとに3ターン分の戦闘結果をまとめて計算し、ログとして返却

### 戦闘ルール
- ターン制（SPD順に行動）
- 各キャラクターは毎ターン自動で攻撃対象を選択し攻撃
- ダメージ計算: `damage = ATK * (1 + random(-0.1, 0.1)) - DEF * 0.5`
- クリティカル: 5%の確率で1.5倍ダメージ（パッシブスキルで上昇可能）。**DEF減算後に乗算**: `(ATK × rand - DEF × 0.5) × 1.5`

### 最低ダメージ保証
- **味方→敵**: 計算結果が1未満の場合、**最低1ダメージを保証**（詰み防止）
- **敵→味方**: **0ダメージを許容**（高DEFビルドに意味を持たせる）

### 確率・軽減率の上限（キャップ）
- **クリティカル率**: 上限**100%**（基礎5% + パッシブ + バフ + スキル固有の合算。超過分は切り捨て。確定クリティカルは到達可能）
- **被ダメージ軽減率**: 乗算合算後の実効軽減率の上限**80%**（最低20%はダメージが通る。完全無敵を構造的に防止）
- **状態異常付与率・挑発率**: 上限**80%**（挑発の既定上限80%と統一）。上限80%は確率ベースの付与・付与率上昇の合算に適用。基礎付与率100%（確定付与）と明記されたスキル効果は例外として確定適用
- **ステータス値（HP/ATK/DEF/SPD）**: 上限なし（64bit整数の範囲。§5参照）
- **回復量**: 上限なし（最大HPで自然に頭打ち）

### ステータス計算の適用順序
戦闘時のステータスは以下の順序で計算する:

```
① 素ステータス = 基礎値 + (成長率 × (LV - 1))
② 強化後 = 素ステータス × (1 + 限界突破%) × (1 + 転生ボーナス%)
③ 装備込み = 強化後 + 装備値
④ パッシブ込み = 装備込み × (1 + パッシブスキル%)
⑤ 最終値 = パッシブ込み × (1 + バフ%) × (1 + デバフ%) × (1 + 環境効果%)
```

- 限界突破・転生ボーナスは恒久的な強化（基礎に近い位置で乗算）
- 装備は加算（固定的な底上げ）
- パッシブスキルは恒久的な乗算強化（装備後・バフ前。バフとの相乗効果あり）
- バフ/デバフ・環境効果は最終値に乗算（一時的な増減）

### バフ/デバフの重複ルール
- **同一スキル**: 上書き（効果値・持続ターンともに新しい方で更新）
- **異なるスキル**: 共存（同一ステータスへの効果は加算）
  - 例: 「力の祝福」ATK+15% と「戦いの鼓舞」ATK+15% → 合計ATK+30%
- 持続ターンはスキルごとに個別管理
- **加算上限**: なし（将来バランス調整が必要な場合にキャップを後付け可能）
- **バフ延長パッシブ**: そのキャラクターが付与したバフの持続ターンのみ+1（他キャラのバフは延長しない）

### 状態異常
戦闘中にスキルで付与される状態異常。拡張性を持たせたテーブル設計とする。

| 状態異常 | 効果 | 持続 | 付与率目安 | 備考 |
|---------|------|------|-----------|------|
| 毒 | maxHP×5%/ターン（行動前に適用） | 3T | スキル依存 | DOT。行動前にダメージ処理 |
| スタン | 1ターン行動不能（確定） | 1T | 高め（40-50%） | 短い・確実 |
| 麻痺 | 毎ターン確率(30%)で行動不能 | 2-3T | 低め（25-35%） | 長い・確率 |
| 沈黙 | スキル使用不可（通常攻撃のみ） | 2-3T | 中程度（35-45%） | 敵スキル持ち前提 |

- 付与率・持続ターンの数値は仮置き（プレイテスト調整前提）
- 環境効果の毒霧（DOT）とスキル毒は**別系統**として独立処理し、**重複する**（毒霧2% + スキル毒5% = 毎ターン7%減少）

### 敵のスキル（段階的導入）
- Phase 1〜4では敵は通常攻撃のみ（ボス含む）
- Phase 5のボスラッシュ Wave 11+ で登場する強化版ボスから段階的にスキルを導入
- 敵スキルは4種: 強打（単体大ダメージ）、咆哮（ATKデバフ）、毒液（毒付与）、全体攻撃
- 敵スキルの詳細は [master_data.md §9A](../../data/master_data.md) を参照
- 沈黙はスキルを持つ敵に対して有効（スキルなしの敵には無効）

### 行動順ルール
- 味方・敵の区別なく、全キャラクターを**SPD降順**で並べて順に行動
- 同SPD時のタイブレーク: **キャラID順**（固定・安定した順序を保証）

### ターゲット選択ロジック（Phase 3〜）

| 行動 | ターゲット選択 |
|------|-------------|
| 通常攻撃 | 敵の中からランダム1体 |
| 単体攻撃スキル | 敵の中でHP割合が最も高い敵（各個撃破） |
| 範囲攻撃スキル | 敵全体 |
| 回復スキル | HP割合が最も低い味方 |
| バフスキル | 味方全体 or スキルごとの対象ルール |
| 敵の攻撃 | 味方の中からランダム1体 |

- ターゲット選択は各キャラの**行動直前にリアルタイム判定**（生存者のみが候補）
- 同ターン中にターゲットが死亡した場合、次に行動するキャラは残りの生存者から再選択
- 敵が全滅した場合、残りキャラの行動をスキップし階クリア判定へ進む

### 複数敵（Phase 3〜）
- 1階あたり最大**3体**の敵が出現
- **出現数は各階固定定義**方式: 塔マスターデータに階ごとの出現数（固定 or 範囲）を明記
  - 範囲指定（例: 1-2体）の場合は均等確率でランダム決定
  - ボス階は1体固定
- 各敵が独立にランダムターゲットで1回行動
- 敵は通常攻撃のみ（Phase 3時点。「敵のスキル（段階的導入）」参照）
- 範囲攻撃の威力: 単体攻撃の**0.7倍を目安にスキル倍率へ織り込んで設計**する（実行時の追加補正はしない。例: アイスストーム×1.2 ≒ 同Tier単体×1.8の0.7倍）

### 全滅時の処理
味方パーティが全滅（全員HP 0）した場合、**常に塔から強制撤退し、戦闘を停止** する（自動周回モードであっても再スタートしない）。
プレイヤーが手動で再出発する必要がある。

**全滅ペナルティ:**
1. **経験値ロスト** — 現在レベル内の蓄積経験値の **50%** を失う（レベルダウンはしない）
2. **ゴールドロスト** — 今回の塔探索中に取得したゴールドを **すべて失う**（塔に入る前の所持ゴールドは影響なし）
3. **アイテムロスト** — 今回の塔探索中に取得したドロップアイテムを **すべて失う**（塔に入る前の所持品は影響なし）

> **設計意図**: 全滅にリスクを持たせることで、目標階設定・撤退条件の戦略的な選択を促す。高い階を狙えば報酬は大きいが、全滅リスクも高まるリスク・リワードのバランス。

### オンライン時（テキストベース）
- フロントが **60秒ごとにAPIをポーリング** して最新の戦闘結果を取得
- サーバーから受け取った戦闘ログをテキストで順次表示
- ログが自動スクロールで流れ、戦闘経過をリアルタイムに確認可能
- 1 tick（3ターン分）の戦闘ログをまとめて表示

### オフライン時
- 離脱時の最終処理タイムスタンプを記録
- 復帰時にサーバーが経過時間を計算し、**未処理のtick数分をまとめて戦闘シミュレーション**
- 経過tickごとに正規の戦闘処理（ダメージ計算・敵撃破・報酬付与）を実行
- 未処理100tickまでは正規シミュレーション、101tick以上は期待値ベースの簡略計算に切り替える（結果が同等になるよう設計。詳細は `tech_battle.md` §2・§4 参照）
- **オフライン中の目標階は固定**（プレイヤーが設定した階を維持。変更は復帰後に手動で行う）
  - ただし**上限追従は適用する**（目標階が上限と一致している場合のみ +1 する）。これがないとオフライン中の開拓が1階で止まり、放置での進行が成立しない
- オフライン中も塔外待機時のHP自然回復は進行する
- オンライン・オフライン問わず報酬効率は **100%（同一）**
- オフライン報酬の上限: 最大24時間分
- 復帰時に **オフライン報酬サマリーモーダル** を表示
  - 経過時間、処理tick数、倒した敵数、獲得ゴールド、獲得経験値、レベルアップ回数、消費ポーション数
  - ※ドロップ装備はサマリーとは別に equipmentDrops として通知される

## 2.3 HP回復システム

### 塔外の自然回復
- 塔にいない間、**時間経過でHPが自然回復** する
- 回復量はステータス依存: `回復量/tick = maxHP * 0.02 + DEF * 0.5`
- 1 tick（60秒）ごとに回復判定
- maxHPに達したら回復停止
- オフライン中も自然回復は進行する（復帰時にまとめて計算）

### ポーションシステム（Phase 1〜）

戦闘中にHPが一定以下になると、所持しているポーションを **自動で使用** する。

| 項目 | 仕様 |
|------|------|
| 使用条件 | HPが **設定閾値以下** になった時に自動使用（デフォルト30%、10%〜50%の10%刻みで変更可能） |
| 使用タイミング | 各ターンの行動前に判定 |
| 所持上限 | 99個（種類ごと） |
| 入手方法 | ショップで購入（Phase 1〜） / 敵からドロップ（Phase 2〜） |

### ポーションの種類

HPポーション（Phase 1〜）／ハイポーション（Phase 2〜）／エリクサー（Phase 2〜）の3種。
**回復量・購入価格は [master/item.md §3.1](../../data/master/item.md) が正**（本書では定義しない）。

- Phase 1では **HPポーションのみ** 使用可能
- 使用優先度: 最も回復量の少ないポーションから使用（無駄を減らす）
- 所持ポーション数が0の場合、自動使用は発動しない

> **設計意図**: HP回復なし（周回またぎ含む）の厳しさをポーションで緩和する。ポーションの消費管理が戦略要素となり、ゴールドの使い道にもなる。
