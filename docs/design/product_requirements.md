# AFK GAME — プロダクト要件

> [game_spec.md](game_spec.md) が「何を作るか（機能）」を定義するのに対し、本書は **「誰のために作り、何を満たせば成功か」** を定義する。
> 非機能要件は [non_functional_requirements.md](non_functional_requirements.md)、運用・変更管理要件は [operation_requirements.md](operation_requirements.md) を参照。

---

## 1. 背景・目的

| 項目 | 内容 |
|------|------|
| 課題 | 常時操作を要求するRPGは、可処分時間の少ないプレイヤーが継続できない |
| 提供価値 | アプリを閉じている間も進行し、**1日数分の確認だけで成長を実感できる**ファンタジーRPG |
| 差別化 | ブラウザのみで完結（インストール不要）・完全無料・広告なし |
| 制作体制 | 個人開発／個人運用。運用コストを継続的に増やす機能（課金決済・リアルタイム通信・大規模インフラ）は採らない |

- [game_spec.md §5](game_spec.md) の「完全無料」「シングルプレイ専用」は、この制作体制から導かれる制約である

## 2. ターゲットプレイヤー

| 項目 | 内容 |
|------|------|
| 主対象 | 放置系RPG経験者。まとまったプレイ時間を確保しづらい社会人層 |
| 主デバイス | スマートフォン縦持ち（モバイルファースト。[systems/ui.md](systems/ui.md) 準拠） |
| プレイ文脈 | 通勤・休憩・就寝前などの短時間セッション |
| 求める体験 | ①成長の可視化 ②装備・キャラクターの収集 ③階層・塔という区切りの達成感 |
| 対象外 | 対人戦・協力プレイを求める層／秒単位の操作そのものを楽しみたい層 |

## 3. 想定プレイサイクル（バランス設計の基準）

マスターデータの数値調整は本節を基準に行う。**数値はすべて仮置き**（プレイテストで検証・確定）。

| 項目 | 想定値（仮置き） | 影響する仕様 |
|------|----------------|------------|
| 1日のログイン回数 | 2〜3回（朝・昼・夜） | オフライン報酬上限24時間の妥当性 |
| 1セッションの操作時間 | 3〜5分 | 画面遷移・操作ステップ数の上限 |
| 1セッションの標準操作 | 報酬確認 → 装備更新 → 目標階変更 → 再開 | [screen_transition.md](../../diagrams/screen_transition.md) |
| 1回あたりの放置時間 | 6〜10時間（就寝・就業） | オフライン簡略計算（101tick〜）が主経路になる |
| 初回起動〜初回達成 | 10分以内にLV5到達・1階層クリア | チュートリアル要件（[systems/ui.md](systems/ui.md)） |
| 塔1本の攻略期間 | 実日数で3〜7日 | 塔10本＝約3〜6ヶ月のコンテンツ量 |
| 進行停滞の許容 | 「24時間放置しても前進しない」状態が2日以上続かない | 難易度カーブ・塔解放条件 |

## 4. スコープ

| 区分 | 内容 |
|------|------|
| スコープ内 | Phase 1〜5（[game_spec.md §1](game_spec.md)） |
| スコープ外 | 課金・広告／ネイティブアプリ配信／リアルタイム対戦・協力／チャット・フレンド・ギフト／多言語対応（**日本語のみ**）／PWA・プッシュ通知（将来検討） |

### 4.1 「シングルプレイ専用」の境界

[game_spec.md §5](game_spec.md) は「マルチプレイ・ソーシャル要素は想定しない」とするが、ボスラッシュの**サーバーランキング**（[systems/endgame.md](systems/endgame.md) §2.11）はプレイヤー間の比較を含む。境界を次のとおり定義する。

| 許容する | 許容しない |
|---------|-----------|
| 非同期の記録比較（ランキング閲覧・自己ベスト登録） | プレイヤー間の同期通信・対戦・協力 |
| 表示名とスコアの公開 | チャット・フレンド・ギフト等の相互作用 |

- 公開されるのは **表示名（`display_name`）と記録のみ**。メールアドレス等は公開しない（[non_functional_requirements.md §5](non_functional_requirements.md)）

## 5. 成功基準（受入観点）

[development_process.md §4](../development_process.md) の Phase完了ゲートでは、機能の実装有無に加えて次を確認する。

| 観点 | 基準 |
|------|------|
| 体験 | §3 の標準操作が **5分以内・迷わず**完了できる |
| 放置価値 | 8時間放置後の復帰で、獲得内容がサマリーで即座に把握できる |
| 継続 | 初回起動から7日間、毎日「新しい前進」（新装備・新階層・新塔・レベルアップ）がある |
| 停滞なし | §3「進行停滞の許容」を満たす |
| 公平性 | クライアント操作・端末時計の変更によって報酬が変動しない |
| 完結性 | 対象Phaseで追加した機能が、そのPhaseの画面だけで完結して使える |
