# AFK GAME — 数値・丸め規約

> 技術仕様の索引は [tech_spec.md](../tech_spec.md)。ステータス計算式は [tech_battle.md §3.1.1](tech_battle.md)、上限値のゲーム仕様は [game_spec.md](../../design/game_spec.md) §2.2、画面表示フォーマットは [ui.md](../../design/systems/ui.md)。
> 本書は「どこで整数へ丸めるか」「どこで頭打ちにするか」をプロジェクト全体で一意に定める。個別の計算式は各仕様書が正であり、本書は丸めとキャップのみを扱う。

---

## 1. 基本原則

1. **計算中は浮動小数、確定時に1回だけ丸める**。中間結果を丸めて次の計算へ渡さない
2. **DBに保存する値・APIで返す値は整数**（HP・ATK・DEF・SPD・ゴールド・EXP・個数）
3. 割合（確率・倍率・閾値）は浮動小数のまま保持し、丸めない
4. 丸めた結果が下限を割る場合は **丸め → クランプ** の順で適用する
5. **四捨五入（`round`）は使用しない**。丸め方式（四捨五入か偶数丸めか）は言語・ライブラリによって実装が異なり、環境間や手計算との差異を生むため、常に `floor`（必要に応じて `ceil`）を用いる

## 2. 丸め規則一覧

| 対象 | 丸め | 下限 / 上限 | 定義元 |
|------|------|-----------|-------|
| 最終ステータス（HP/ATK/DEF/SPD） | `floor` | 下限1 | tech_battle §3.1.1 |
| 与ダメージ（味方→敵） | `floor` | 下限1 | tech_battle §3.1 |
| 与ダメージ（敵→味方） | `floor` | 下限0 | tech_battle §3.1 |
| 範囲攻撃の各対象ダメージ | `floor`（スキル倍率適用後。範囲補正は倍率に織り込み済み） | 上と同じ | tech_battle §3.1 |
| DOT（毒・環境毒霧） | `floor` | 下限1 | [tech_data.md §1.5](../basic/tech_data.md) |
| 回復量（スキル・リジェネ・ポーション） | `floor` | 下限1 / HPは maxHP まで | tech_battle §3.1 |
| 獲得ゴールド・EXP | `floor` | 下限0 | — |
| レベルアップ必要EXP（しきい値） | `round` | 下限1 | [master/character.md §1.4](../../data/master/character.md) |
| 報酬倍率適用後の報酬 | `floor`（倍率適用後に1回） | 下限0 | tech_data §1.5 `bonus` |
| 装備ステータス | `floor` | 下限1 | [master/equipment.md](../../data/master/equipment.md) |

| 撃破ターン数・必要tick数 | `ceil` | 下限1 | [tech_offline.md §4.1](tech_offline.md) |

| 転生ポイント・SP | 整数演算のみ（丸め発生せず） | 下限0 | [master/endgame.md](../../data/master/endgame.md) |

## 3. キャップ・下限一覧

| 対象 | 下限 | 上限 | 超過時の挙動 |
|------|------|------|-------------|
| キャラLV | 1 | 9999 | 超過EXPは切り捨て（`tech_offline.md` §4） |
| HP | 0 | maxHP | クランプ。0で戦闘不能 |
| クリティカル率 | 0 | 1.0 | 超過分を切り捨て（game_spec §2.2） |
| 被ダメ軽減率（実効） | 0 | 0.8 | 最終ダメージ倍率の下限0.2（tech_battle §3.1） |
| 挑発率（合算） | 0 | — | 100%超は挑発者間で按分（tech_battle §3.1.3） |
| バフ／デバフの加算 | — | なし | 上限を設けない（tech_battle §3.1.2） |
| ゴールド | 0 | `MAX_GOLD`（2^63−1） | **飽和**（上限で止め、例外を送出しない） |
| アイテム所持数 | 0 | 倉庫LVによる上限 | 上限超過分は取得しない・INFOログに記録 |
| ポーション自動使用閾値 | 0.1 | 0.5 | 0.1刻み（`tech_data.md` §1.1） |
| 撤退HP閾値 | 0.0 | 1.0 | 範囲外は `422` |
| 目標階 | 1 | `min(塔別 highestFloor + 1, 総階数)` | 範囲外は `400`（`tech_api/gameplay.md`「操作系」） |

- ゴールドを**飽和**とするのは、加算のたびに上限超過を例外扱いするより実装が単純で、上限到達時にプレイが停止しないため

## 4. 適用順序

丸めとキャップの適用位置を、ダメージ計算を例に示す。

```
1. 最終ステータス算出      → floor（tech_battle §3.1.1 の ⑤ の後で1回だけ）
2. ダメージ素値 = ATK×(1+分散) − DEF×0.5    → 丸めない
3. クリティカル倍率を乗算                     → 丸めない
4. 被ダメ軽減を乗算（実効軽減率は0.8でクランプ済み） → 丸めない
5. floor                                      → ここで初めて整数化
6. 下限クランプ（味方→敵は1、敵→味方は0）
7. HPから減算 → HPを [0, maxHP] にクランプ
```

- ステップ2〜4の途中で丸めると多段の乗算で誤差が蓄積し、「装備やバフが表示どおりに効かない」不具合になる
- 確率のクランプ（クリティカル率・軽減率）は**乱数判定の前**に済ませる（[tech_rng.md §1](tech_rng.md) の `r < p` 規約が成立する前提）

## 5. 分岐一覧（丸め・クランプ・飽和）

計算結果を確定させる側の分岐。**入力値の検証は §6**、アイテム所持枠の上限は [tech_base.md §8](tech_base.md) #14・#15、撤退HP閾値の入力検証は [tech_tower/control.md §12](tech_tower/control.md) #7・#8、レベルアップ時のSP付与は [tech_party.md §6](tech_party.md)、周回中のレベルアップ反映は [tech_offline.md §5](tech_offline.md) #7・#8 が持つ（本表へ再掲しない）。

| # | 分岐点 | 条件 | 期待する振る舞い |
|---|-------|------|----------------|
| 1 | ダメージの下限 | 素値が負（味方→敵） | 1 へクランプ |
| 2 | ダメージの下限 | 素値が負（敵→味方） | 0 へクランプ |
| 3 | ダメージの丸め | 素値が 0.9（味方→敵） | `floor` で0 → 下限クランプで1 |
| 4 | ダメージの丸め | 素値が 2.9（味方→敵） | `floor` で2（下限クランプは働かない） |
| 5 | 回復量の上限 | 回復後のHPが maxHP を超える | maxHP でクランプ |
| 6 | 回復量の上限 | 回復後のHPが maxHP 以下 | 回復量をそのまま加算 |
| 7 | 確率・軽減率の上限 | クリティカル率の合算が1.2 | 実効値 1.0（乱数判定へ渡す前に切り捨て。§4） |
| 8 | 確率・軽減率の上限 | 被ダメ軽減の合算が0.95 | 実効値 0.8（最終ダメージ倍率0.2） |
| 9 | ゴールドの飽和 | 加算後が `MAX_GOLD` を超える | `MAX_GOLD` で飽和（例外を送出しない） |
| 10 | ゴールドの飽和 | 加算後が `MAX_GOLD` 以下 | そのまま加算する |
| 11 | LV上限 | LV上限（9999）でEXPを獲得 | LVは増えず、EXPも加算しない |
| 12 | LV上限 | LV上限未満でEXPを獲得 | EXPを加算する（しきい値未満ならLVは変わらない） |
| 13 | 回復量の下限 | `floor` した回復量が0（例 素値 0.9） | 1 へクランプして加算する（§2「回復量」の下限1） |
| 14 | 回復量の下限 | `floor` した回復量が1以上 | `floor` した値をそのまま加算する |
| 15 | LV到達判定 | 加算後EXPが次LVの必要EXPちょうど | レベルアップし、必要EXPを差し引く（`>=` で判定） |
| 16 | LV到達判定 | 加算後EXPが必要EXPに1足りない | レベルアップせずEXPだけ加算する |
| 17 | LV到達判定 | 加算後EXPが2レベル分の必要EXPに届く | 到達しなくなるまで繰り返しレベルアップする |
| 18 | LV到達判定 | 連鎖の途中でLV上限に達した | 上限で止め、余剰EXPは手元に残す（以降は #11 で加算しない） |
| 19 | 必要EXPの丸め | しきい値が整数にならない（LV2 は 282.84…） | `round` した値をしきい値にする（283。§2） |
| 20 | 必要EXPの丸め | しきい値が整数になる（LV1 は 100） | そのままの値をしきい値にする |
| 21 | 必要EXPの算出 | LV上限未満 | しきい値から現在レベル内の累積EXPを引いた残りを返す |
| 22 | 必要EXPの算出 | LV上限に到達済み | 到達しない値（`Long.MAX_VALUE`）を返す |
| 23 | LVアップ時の再計算 | 成長率が小数のタイプ（holy の SPD +1.5/LV） | `floor(base + growth × (LV−1))` で求め直す（LVごとの増分加算にしない） |
| 24 | LVアップ時の再計算 | 成長率が整数のタイプ（melee の HP +20/LV） | 同じ式で求め、丸めは働かない |
| 25 | LVアップ時の再計算 | maxHP が上昇した | 上昇分を現在HPへも加算する（HP欠損量を維持する） |

## 6. 分岐一覧（入力値の検証）

`PUT /api/game/settings` のポーション自動使用閾値。範囲・刻みの値は [systems/ui.md](../../design/systems/ui.md)「設定項目」が正で、キャップとしての再掲は §3。Web層の Bean Validation で検証する。

| # | 分岐点 | 条件 | 期待する振る舞い |
|---|-------|------|----------------|
| 1 | ポーション閾値の入力 | 刻みに合わない（例 `0.25`）・範囲外 | `422`（保存しない） |
| 2 | ポーション閾値の入力 | 範囲内かつ刻みに適合（例 `0.3`） | 保存して `200` |
