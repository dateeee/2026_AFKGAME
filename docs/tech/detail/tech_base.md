# AFK GAME — 拠点・施設処理

> Phase 4。施設の建設・レベルアップと、施設レベルから効果値を解決する規則を定める。
> 効果値・コストの**数値の正**は [economy.md](../../design/systems/economy.md) §2.9 と [master/base.md](../../data/master/base.md) §11。本書は**処理**のみを持つ。
> 酒場スカウト（`POST /api/base/scout`）は [tech_scout.md](tech_scout.md)、鍛冶屋の各操作（`/api/forge/*`）は [tech_forge.md](tech_forge.md)。どちらも本書の対象外。

## 1. 適用範囲と方針

| 項目 | 内容 |
|------|------|
| 対象 | `POST /api/base/build`・`POST /api/base/upgrade`・施設レベルからの効果値解決 |
| 施設 | `tavern` / `forge` / `training_ground` / `warehouse` / `market` の5種（[tech_data.md §1.6](../basic/tech_data.md)） |
| レベル | LV0（未建設）〜LV10。1リクエストで**1レベルのみ**進む（複数レベルの一括購入はしない） |
| 完了 | 建設・レベルアップとも**即時完了**（待ち時間・建設キューを持たない） |
| 進行状態 | 全状態で許可（[tech_state.md §4](tech_state.md)） |
| 永続化 | `facilities` テーブル（[tech_db/item.md §6](../basic/tech_db/item.md)）。行が無いプレイヤーは LV0 とみなす |

## 2. 施設レベルから効果値を解決する

### 2.1 効果表の読み方

`economy.md` §2.9 の効果表は、**5施設すべてが LV1〜LV10 を全レベル列挙する**。解決は施設LVと同じ行を引くだけで、補間・しきい値検索は行わない。

1. 施設LVが1以上なら、その施設の表から**施設LVと一致する行**の値を採用する
2. 施設LVが0（未建設）の場合は §2.2 に従う

- 5施設のいずれも**レベルアップで必ず効果が向上する**（据え置きのLVを作らない）。酒場は「スカウト可能レアリティ」が同じLVでも排出率が上がり（[CHARACTERS_OVERVIEW.md §4.1](../../data/characters/CHARACTERS_OVERVIEW.md)）、鍛冶屋は「強化上限 = 施設LV」なので毎LV +1 される
- 表の値をコードへ展開せず、マスターデータとして読む（[profile.md](../../../.claude/project/profile.md) §5 不変条件「データ駆動」）

### 2.2 LV0（未建設）の効果値

| 施設 | LV0 の扱い |
|------|-----------|
| 酒場 | スカウト不可（`400 BASE_NOT_BUILT`） |
| 鍛冶屋 | 強化・製作・分解のいずれも不可（`400 BASE_NOT_BUILT`） |
| 訓練場 | 控えキャラのEXP獲得率 **0%**（付与処理そのものを行わない） |
| 倉庫 | 所持枠 **50枠**（economy.md「倉庫」の「なし」列。Phase 2 から適用済み） |
| 市場 | ゴールドボーナス **+0%**（倍率1.0） |

- 倉庫だけは LV0 に**既定値がある**。他の4施設は「効果なし」であり、未建設と LV1 を同一視しない

### 2.3 効果の適用点

| 施設 | 効果値 | 適用点と式 |
|------|-------|-----------|
| 市場 | ゴールドボーナス率 `m` | 敵撃破時のゴールド報酬を `floor(base × (1 + m + e))` とする。`e` は環境効果の `bonus`（`tech_data.md` §1.5）。**加算で合算**し、乗算後に1回だけ `floor`（[tech_numeric.md §2](tech_numeric.md)）。換金アイテムの売却価格には適用しない |
| 訓練場 | EXP獲得率 `t` | tick でパーティがEXPを得た時、**パーティ外の全キャラ**へ `floor(gainedExp × t)`（下限0）を加算する。パーティ内キャラには二重付与しない |
| 倉庫 | 所持枠上限 | 装備・素材・換金アイテムの**合計**枠。ポーションは対象外。**装備1件＝1枠、素材・換金アイテムは1種類＝1枠**（数量はスタック上限まで1枠に収まる。数量0の行は数えない）。判定箇所は [tech_shop/buy.md §4](tech_shop/buy.md) 手順5・戦闘ドロップ・鍛冶屋の製作／分解（[tech_forge/disassemble.md §6](tech_forge/disassemble.md)） |
| 酒場 | スカウト可能レアリティ・費用 | `POST /api/base/scout`（処理は `tech_scout.md`、排出率は `characters/CHARACTERS_OVERVIEW.md` §4.1） |
| 鍛冶屋 | 強化上限・製作可能レアリティ・強化コスト倍率 | `/api/forge/*`（処理は `tech_forge.md`、コストは [master/equipment.md §12〜§14](../../data/master/equipment.md)） |

- 市場・訓練場の効果値は economy.md の表で `LV × 5%` と一致するが、**参照は表**とする。式に置き換えない（不変条件「データ駆動」）

## 3. 建設処理（`POST /api/base/build`）

入口条件: 認証済みで `facilityId` を指定していること。進行状態は問わない。

1. `facilityId` が §1 の5種のいずれでもない → `422`
2. プレイヤーの `players` 行を**行ロック**して取得する（ゴールド消費の競合を防ぐ。[tech_tick.md §3.1](tech_tick.md) と同じ方式）
3. 対象施設の現在LVを取得する（`facilities` に行が無ければ LV0）
4. 現在LV が **1以上** → `400 BASE_ALREADY_BUILT`（状態は変更しない）
5. `master/base.md` §11 の **LV1 行**を建設コストとして引く
6. 所持ゴールドがコストに満たない → `400 BASE_INSUFFICIENT_GOLD`（状態は変更しない）
7. 必要素材のいずれか1種でも所持数が不足 → `400 BASE_INSUFFICIENT_MATERIALS`（状態は変更しない）
8. 所持ゴールドからコストを引く
9. 必要素材を所持数から引く
10. 対象施設を **LV1** にする（`facilities` 行が無ければ作成、あれば更新）
11. 手順8〜10を1トランザクションでコミットする。途中で失敗した場合は全件ロールバックする

出口条件: ゴールド減算・素材減算・LV更新の3つがすべて成立しているか、いずれも起きていないかのどちらか。

- 検証（手順4・6・7）は**すべて消費の前**に行う。部分消費は発生しない
- 素材の不足判定は §11 の列順（強化石 → 魔法の結晶 → 希少鉱石 → 古代の欠片）で走査し、**不足しているものを全件** `details` に列挙する
- コスト行の「-」は必要数0として扱い、検証も消費も行わない

## 4. レベルアップ処理（`POST /api/base/upgrade`）

入口条件: §3 と同じ。

1. `facilityId` が5種のいずれでもない → `422`
2. `players` 行を行ロックして取得する
3. 対象施設の現在LVを取得する（行が無ければ LV0）
4. 現在LV が **0** → `400 BASE_NOT_BUILT`（先に `build` が要る）
5. 現在LV が **10** → `400 BASE_MAX_LEVEL`
6. 目標LV = 現在LV + 1。§11 の**目標LV行**をコストとして引く
7. 所持ゴールドが不足 → `400 BASE_INSUFFICIENT_GOLD`
8. 必要素材が不足 → `400 BASE_INSUFFICIENT_MATERIALS`
9. 所持ゴールドからコストを引く
10. 必要素材を所持数から引く
11. 対象施設を目標LVに更新する
12. 手順9〜11を1トランザクションでコミットする。途中で失敗した場合は全件ロールバックする

出口条件: §3 と同じ（3点すべて成立、またはいずれも起きない）。

- 手順4・5は**この順**で判定する（LV0 は `BASE_NOT_BUILT` を優先する）
- 素材の走査順・「-」の扱い・検証の位置は §3 と同じ
- 効果値の変化はコミット後の読み取りから反映される。進行中の探索セッションには**次tickから**反映される

## 5. API

`POST /api/base/build` と `POST /api/base/upgrade` はリクエスト・レスポンスとも同形。

| 項目 | 内容 |
|------|------|
| リクエスト | `{ "facilityId": "market" }`（必須。5種のいずれか） |
| 成功 | `200`。`facilityId`・`level`・`gold`・`materials` を**更新後の値**で返す |
| 失敗 | §6 のコード。形式は [tech_error_handling.md](../basic/tech_error_handling.md)「統一エラーレスポンス形式」 |

## 6. `BASE_` エラーコード一覧

| コード | HTTP | 発生条件 |
|--------|------|---------|
| `BASE_ALREADY_BUILT` | 400 | `build` で対象施設が既に LV1 以上 |
| `BASE_NOT_BUILT` | 400 | `upgrade`・スカウト・鍛冶屋操作で対象施設が LV0 |
| `BASE_MAX_LEVEL` | 400 | `upgrade` で対象施設が既に LV10 |
| `BASE_INSUFFICIENT_GOLD` | 400 | 所持ゴールドがコストに満たない |
| `BASE_INSUFFICIENT_MATERIALS` | 400 | 必要素材のいずれかが不足（`details` に不足分を全件列挙） |

- `facilityId` が未知・欠落の場合は Bean Validation の `422` とし、`BASE_` コードは使わない

## 7. 分岐一覧（建設・レベルアップ）

| # | 分岐点 | 条件 | 期待する振る舞い |
|---|-------|------|----------------|
| 1 | 施設ID | 5種のいずれか | 処理を続行する |
| 2 | 施設ID | 5種のいずれでもない（未知ID・欠落） | `422` を返し状態を変更しない |
| 3 | 施設行の有無 | `facilities` に行がある | その行のLVを現在LVとする |
| 4 | 施設行の有無 | `facilities` に行が無い | 現在LVを0とみなす |
| 5 | 建設可否 | 建設要求で未建設 | 建設を続行する |
| 6 | 建設可否 | 建設要求で建設済み | `400 BASE_ALREADY_BUILT`。状態を変更しない |
| 7 | 建設前提 | レベルアップ要求で建設済み | レベルアップを続行する |
| 8 | 建設前提 | レベルアップ要求で未建設 | `400 BASE_NOT_BUILT`。状態を変更しない |
| 9 | レベル上限 | レベルアップ要求で上限未満 | 目標LVのコスト行を引く |
| 10 | レベル上限 | レベルアップ要求で上限に達している | `400 BASE_MAX_LEVEL`。状態を変更しない |
| 11 | ゴールド | 所持ゴールドが足りる | 素材の判定へ進む |
| 12 | ゴールド | 所持ゴールドがちょうど足りる | 素材の判定へ進む（境界は購入可） |
| 13 | ゴールド | 所持ゴールドが足りない | `400 BASE_INSUFFICIENT_GOLD`。状態を変更しない |
| 14 | 素材の走査 | 必要素材が0種（コスト行がすべて「-」） | 素材の検証・消費を行わず消費処理へ進む |
| 15 | 素材の走査 | 必要素材が1種 | その素材のみ検証・消費する |
| 16 | 素材の走査 | 必要素材が2種以上 | すべての素材を検証・消費する |
| 17 | 素材 | 必要素材がすべて足りる | 消費処理へ進む |
| 18 | 素材 | 必要素材の1種が不足 | `400 BASE_INSUFFICIENT_MATERIALS`。その1種を返し状態を変更しない |
| 19 | 素材 | 必要素材の2種以上が不足 | `400 BASE_INSUFFICIENT_MATERIALS`。不足分を全件返し状態を変更しない |
| 20 | トランザクション | 消費・更新がすべて成功 | コミットし更新後の値を返す |
| 21 | トランザクション | 消費・更新の途中で失敗 | 全件ロールバックし状態を変更しない |

> WARN許容 #14: 現行のコスト表（§11）に素材0種の行は無く、マスターデータを差し替えた場合にのみ到達する。ローダが受理する以上は経路として定義しておく必要があるため残す。

## 8. 分岐一覧（効果値の解決）

| # | 分岐点 | 条件 | 期待する振る舞い |
|---|-------|------|----------------|
| 1 | 効果表の解決 | 施設LVが1以上 | 施設LVと一致する行の値を採用する |
| 2 | 効果表の解決 | 施設LVが0（酒場・鍛冶屋） | 該当行なしとし、その施設の機能を使用不可にする |
| 3 | 効果表の解決 | 施設LVが0（訓練場・倉庫・市場） | 倉庫は50枠、訓練場・市場は効果なしとする |
| 4 | 効果表の解決 | 施設LVが表の最大LV（10）を超える | 到達しない（`BASE_MAX_LEVEL` で拒否。§4） |
| 5 | 市場ボーナス | 市場LVが1以上 | ゴールド報酬を `floor(base × (1 + m + e))` にする |
| 6 | 市場ボーナス | 市場LVが0 | 環境効果 `e` のみで計算する（`m = 0`） |
| 7 | 訓練場の付与 | 訓練場LVが1以上 | パーティ外キャラへEXPを付与する |
| 8 | 訓練場の付与 | 訓練場LVが0 | EXP付与を行わない |
| 9 | 訓練場の対象 | パーティ外キャラが0体 | 付与せずに終了する |
| 10 | 訓練場の対象 | パーティ外キャラが1体 | その1体へ `floor(gainedExp × t)` を加算する |
| 11 | 訓練場の対象 | パーティ外キャラが2体以上 | 全員へそれぞれ加算する |
| 12 | 訓練場の丸め | `floor(gainedExp × t)` が1以上 | その値を加算する |
| 13 | 訓練場の丸め | `floor(gainedExp × t)` が0 | 0を加算する（下限0。負にしない） |
| 14 | 所持枠 | 所持数が倉庫上限に満たない | 取得を許可する |
| 15 | 所持枠 | 所持数が倉庫上限に達している | 入手経路ごとの扱いに従う（購入は `400`、戦闘ドロップは破棄） |
