# オフライン簡略計算（101tick以上）

> [tech_bossrush.md](../tech_bossrush.md) の子ファイル（§9・§10）。1tickずつの正規シミュレーションは [wave.md §7](wave.md)、終了処理は [control.md §11](control.md)。
> 処理方式の切り替え境界（100 / 101 tick）は [tech_offline.md §2](../tech_offline.md) が正。本書は**ボスラッシュ中のプレイヤー**の簡略計算だけを定義する（塔の周回簡略計算は tech_offline.md §4 が持つ）。

## 9. ウェーブ単位の簡略計算

塔の簡略計算が「周回」を単位にするのに対し、ボスラッシュは**ウェーブ**を単位に確定計算する。強化倍率が `1.1 ^ (wave − 10)` で発散するため、どんな編成でも有限ウェーブで全滅し、ループ回数は有界になる。

```
入力: pending_ticks, party_stats[], potion_count, current_wave, 進行中の敵HP
出力: accumulated_gold/exp の増分, 更新後ステータス, 終了したか

1. remaining_ticks = pending_ticks
2. WHILE remaining_ticks > 0 かつ active:
   a. current_wave の敵構成・強化倍率を解決する（tech_bossrush.md §2）
   b. tech_offline.md §4.1 の期待値式で、そのウェーブを解決する:
        撃破ターン数 = ceil(敵HP合計 ÷ Σ味方 E_dmg)
        被ダメ合計   = Σ味方 E_taken × 撃破ターン数
        純被ダメ     = 被ダメ合計 − 回復期待値 × 撃破ターン数   # 負なら0。ポーション消費モデルも §4.1 に従う
   c. 純被ダメ >= Σ味方 現在HP なら全滅 → control.md §11 の終了処理（全滅）→ BREAK
   d. 必要tick数 = ceil(撃破ターン数 ÷ 1tickのターン数)
   e. 必要tick数 > remaining_ticks なら:
        HPから「remaining_ticks 分の被ダメ」を減算し、そのウェーブは未突破のまま remaining_ticks = 0 → ループ終了
   f. remaining_ticks -= 必要tick数、HPから純被ダメを減算
   g. wave.md §7 手順4（a〜e）の突破処理をそのまま適用する
3. RETURN
```

- **レベルアップを扱わない**のが塔の簡略計算との最大の差。ゴールド・EXPは `accumulated_*` に積むだけで挑戦中は付与されないため、ステータスは挑戦を通じて不変であり、tech_offline.md §4 手順3-b〜3-g（次レベルまでのEXP算出・ステータス再計算）に相当する処理が要らない
- 手順2-b の丸め（`ceil` / `floor`）は [tech_numeric.md §2](../tech_numeric.md) に従う。撃破ターン数・必要tick数は `ceil`・下限1
- 手順2-e で未突破のまま打ち切った場合、次回のtickは同じウェーブを削りかけのHPから再開する。累積報酬・マイルストーン・自己ベストは**突破していないので更新しない**
- 全滅で打ち切った残tickは破棄する。終了処理でHPを全回復する（control.md §11）ため、塔外待機のHP自然回復（tech_offline.md §4 手順4）は適用しない
- 個別の戦闘ログは生成せずサマリーのみ返す（tech_offline.md §2 と同じ）

## 10. 分岐一覧（オフライン簡略計算）

| # | 分岐点 | 条件 | 期待する振る舞い |
|---|-------|------|----------------|
| 1 | 処理方式 | 未処理tickが100以下 | 正規シミュレーション（wave.md §7）を1tickずつ実行する |
| 2 | 処理方式 | 未処理tickが101以上 | 本節のウェーブ単位の簡略計算で一括処理する |
| 3 | 全滅判定 | 純被ダメが味方の合計HP以上 | 全滅として終了処理し、残tickを破棄する |
| 4 | 全滅判定 | 味方の合計HP未満 | そのウェーブを突破したものとして続行する |
| 5 | tick充足 | 必要tick数が残tick以下（同数を含む） | 突破処理を適用し、残tickから必要tick数を減算する |
| 6 | tick充足 | 必要tick数が残tickを超える | 未突破のまま打ち切り、HP減少だけ反映して同一ウェーブで再開できるようにする |
| 7 | ポーション | 在庫が残っている | 消費数を減算して回復に算入する |
| 8 | ポーション | 在庫が尽きた | 以降のウェーブは回復なしで全滅判定する |
| 9 | ウェーブループ | 消化すべきtickがない（0周） | 簡略計算を呼び出さない（処理方式の選択で除外済み） |
| 10 | ウェーブループ | 1ウェーブで全滅または消化しきる（1周） | そのウェーブの結果だけを反映する |
| 11 | ウェーブループ | 2ウェーブ以上進む（2周以上） | ウェーブごとに突破処理を繰り返し、報酬・記録を都度確定する |
| 12 | 挑戦中の成長 | 累積EXPが次レベルのしきい値を超える | レベルアップせず `accumulated_exp` に積むだけにする（ステータスを再計算しない） |
| 13 | 挑戦中の成長 | しきい値未満 | 同じく `accumulated_exp` に積む（挑戦中はステータス不変） |
| 14 | 残tick | 全滅で打ち切った | 残tickを破棄する（HPは終了処理で全回復するため自然回復を適用しない） |
| 15 | 残tick | 全tickを消化しきった | 進行中のウェーブ・HPを保存して終了する |
