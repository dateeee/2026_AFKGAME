# AFK GAME — 鍛冶屋: 装備製作

> [tech_forge.md](../tech_forge.md) の子ファイル（§4・§10）。`POST /api/forge/craft` の処理を定める。
> 共通の適用範囲・鍛冶屋LVからの効果解決（§2）・API・エラーコードは索引側にある。
> **数値の正**: ランダム製作のレシピは [master/equipment.md §13](../../../data/master/equipment.md)、固定レシピは同 §5.5.3、製作可能レアリティは [economy.md §2.9](../../../design/systems/economy.md)。

## 4. 製作処理（`POST /api/forge/craft`）

`rank`（ランダム製作）と `recipeId`（固定レシピ製作）の**どちらか一方のみ**を指定する。両方指定・両方未指定は `422`。

### 4.1 ランダム製作（`rank`）

| # | 項目 | 規則 |
|---|------|------|
| 1 | 要求レアリティ | `rank` 1〜5 を `master/equipment.md` §13 の行順（コモン→レジェンダリー）で引く |
| 2 | 可否 | 要求レアリティが `tech_forge.md` §2 の製作可能レアリティを**上回る**なら `400 FORGE_LEVEL_TOO_LOW`（同じなら可） |
| 3 | 必要素材・ゴールド | §13 の該当行。**鍛冶屋LVによる割引はない**（コスト倍率は強化のみ） |
| 4 | 装備レベル `L` | `max(1, 最高到達階層)`（[tech_shop/lineup.md §3.1](../tech_shop/lineup.md) 手順1 と同一） |
| 5 | ベース装備 | `master/equipment.md` §6.0 の15種全体からベースID昇順・離散一様で1件。スロットと持ち手はベースから引く |
| 6 | ステータス | `tech_shop/lineup.md` §3.1 手順3〜6 と同じ手順。ただし**ショップ性能係数 `0.7` を掛けない**（`max(1, floor(B × レアリティ倍率 × ステータス補正))`） |
| 7 | HP吸収 | 付与しない（`lifesteal` は `null`）。吸収装備はドロップと §4.2 でのみ得られる |

- レアリティの序列は [systems/equipment.md §2.4](../../../design/systems/equipment.md)「レアリティ」表の行順。可否判定はこの序列の比較で行う
- 乱数は**ベース → 付与数 → ステータス種**の順に消費する（[tech_rng.md §3](../tech_rng.md) の消費順序固定）。付与数の範囲の下限と上限が等しいレアリティでは付与数の抽選を行わない
- ショップと違いカテゴリ枠を持たないため、候補からの除外（`tech_shop/lineup.md` §2.4 手順2）は行わない

### 4.2 固定レシピ製作（`recipeId`）

`master/equipment.md` §5.5.3 の吸収装備6件を、**結果を固定して**製作する。

| # | 項目 | 規則 |
|---|------|------|
| 1 | レシピ | `recipeId` で §5.5.3 の行を引く。一覧に無いIDは `422` |
| 2 | 可否 | §5.5.3 のレアリティが製作可能レアリティを上回るなら `400 FORGE_LEVEL_TOO_LOW` |
| 3 | 必要素材・ゴールド | §5.5.3 の該当行 |
| 4 | 生成値 | `base_id`・スロット・持ち手・レアリティ・基礎ステータス・`lifesteal`（吸収率）を §5.5.3 の定義値どおりに入れる |
| 5 | 装備レベル | §4.1 手順4 と同じ。**ステータスには影響しない**（記録用の値） |
| 6 | 強化段階 | 0 |

- 結果が固定であるため**乱数を1回も消費しない**
- §5.5.3 のレアリティは鍛冶屋LV要件（レア=LV5・エピック=LV7・レジェンダリー=LV10）に対応するので、可否判定は §4.1 手順2 と同じ比較で足りる（レシピごとの鍛冶屋LV判定を別に持たない）

### 4.3 処理フロー

入口条件: 認証済みで、`rank` と `recipeId` のどちらか一方があること。

1. `players` 行を行ロックして取得する
2. 鍛冶屋の現在LVを取得する。**0** なら `400 BASE_NOT_BUILT`
3. §4.1／§4.2 の手順1〜2 で製作方式とレシピを決め、可否を判定する
4. 必要素材が不足なら `400 FORGE_INSUFFICIENT_MATERIALS`（`details` に不足分を全件列挙）、ゴールドが不足なら `400 BASE_INSUFFICIENT_GOLD`
5. 所持枠に空きがなければ `400 FORGE_INVENTORY_FULL`（[disassemble.md §6](disassemble.md)）
6. §4.1／§4.2 の生成規則で装備1件を組み立てる
7. 素材とゴールドを減算し、`equipment` へ1行追加する
8. 手順7を1トランザクションでコミットする。途中で失敗した場合は全件ロールバックする

出口条件: 素材・ゴールドの減算と装備1行の追加が**ともに成立**しているか、**いずれも起きていない**かのどちらか。

- 生成（手順6）は検証（手順3〜5）をすべて通過した後に行う。乱数を消費したのに装備を得られない経路を持たない
- 製作した装備を自動装備しない（所持へ加えるだけ）

## 10. 分岐一覧（製作）

| # | 分岐点 | 条件 | 期待する振る舞い |
|---|-------|------|----------------|
| 1 | 鍛冶屋LV | LV1以上 | 製作方式の判定へ進む |
| 2 | 鍛冶屋LV | LV0（未建設） | `400 BASE_NOT_BUILT`。乱数を消費せず状態を変更しない |
| 3 | パラメータの排他 | `rank` と `recipeId` のどちらか一方だけを指定 | 対応する製作方式へ進む |
| 4 | パラメータの排他 | 両方を指定、または両方とも未指定 | `422`。`FORGE_` コードを使わない |
| 5 | 製作方式 | `rank` を指定 | ランダム製作として扱う |
| 6 | 製作方式 | `recipeId` を指定 | 固定レシピ製作として扱う |
| 7 | `rank` の範囲 | 1〜5 | 対応するレアリティを引く |
| 8 | `rank` の範囲 | 範囲外 | `422` |
| 9 | `recipeId` の実在 | 吸収装備レシピに実在する | そのレシピを採用する |
| 10 | `recipeId` の実在 | 一覧に無い | `422` |
| 11 | 製作可能レアリティ | 要求レアリティが製作可能レアリティを下回る | 素材の判定へ進む |
| 12 | 製作可能レアリティ | 要求レアリティが製作可能レアリティと同じ | 素材の判定へ進む（境界は実行可） |
| 13 | 製作可能レアリティ | 要求レアリティが製作可能レアリティを上回る | `400 FORGE_LEVEL_TOO_LOW`。乱数を消費しない |
| 14 | 所持素材 | 必要素材をすべて満たす | ゴールドの判定へ進む |
| 15 | 所持素材 | いずれかの素材が不足（未所持を含む） | `400 FORGE_INSUFFICIENT_MATERIALS`。不足分を全件列挙する |
| 16 | 所持ゴールド | 所持ゴールドが費用以上 | 所持枠の判定へ進む |
| 17 | 所持ゴールド | 所持ゴールドが費用に満たない | `400 BASE_INSUFFICIENT_GOLD` |
| 18 | 所持枠 | 装備1件を追加しても上限以内 | 生成へ進む |
| 19 | 所持枠 | 上限に達している（残り0枠） | `400 FORGE_INVENTORY_FULL`。素材もゴールドも消費しない |
| 20 | 装備レベル | 最高到達階層が1以上 | その値を装備レベルとする |
| 21 | 装備レベル | 最高到達階層が0 | 装備レベルを1とする |
| 22 | 付与ステータス数 | レアリティの付与数の下限と上限が異なる | 離散一様で決める |
| 23 | 付与ステータス数 | 付与数の下限と上限が等しい | 抽選せずその値を採る（乱数を消費しない） |
| 24 | HP吸収 | ランダム製作 | `lifesteal` を付与しない |
| 25 | HP吸収 | 固定レシピ製作 | レシピの吸収率を付与する |
| 26 | 乱数消費 | ランダム製作が生成に到達した | ベース → 付与数 → ステータス種 の順に消費する |
| 27 | 乱数消費 | 固定レシピ製作が生成に到達した | 乱数を1回も消費しない |
| 28 | 乱数消費 | 検証で弾かれた | 乱数を1回も消費しない |
| 29 | トランザクション | 素材・ゴールド減算と装備追加がともに成功 | コミットし生成物と更新後の値を返す |
| 30 | トランザクション | 途中で失敗 | 全件ロールバックし状態を変更しない |
