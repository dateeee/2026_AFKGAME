## 11.1 脅威と実現方式の対応

非機能要件 §4 の各脅威に対し、本書のどの節が実現方式を定めるかを示す。要件そのものは再掲しない。

| 脅威（要件 §4） | 実現方式 |
|----------------|---------|
| 戦闘結果の偽装 | §11.4 サーバー権威の徹底 |
| 端末時計の改ざん | §11.4（時刻はサーバーUTCのみ）＋ [tech_tick.md](tech_tick.md) §1 |
| tick連打・多重タブによる多重取得 | [tech_tick.md](tech_tick.md) §3 排他ロック／§11.6 レート制限 |
| API直接呼び出し | §11.5 認可（オーナーシップ検証） |
| 入力値の改ざん | §11.3 入力バリデーション方針 |
| 認証情報への攻撃 | §11.6 レート制限 ＋ [tech_auth.md](tech_auth.md) |
| 秘密情報の露出 | §11.8 ＋ [tech_operations.md](tech_operations.md) §12.2（起動時バリデーション） |
| ログからの漏洩 | [tech_logging.md](tech_logging.md) 機密情報のマスク規則 |

要件に明示がないが本書で扱う脅威:

| 脅威 | 実現方式 |
|------|---------|
| XSS | §11.7（Vue の自動エスケープ・`v-html` 禁止・CSP） |
| CSRF | §11.2（Cookie を使わず `Authorization: Bearer` のみ。構造上対象外） |
| SQLインジェクション | §11.3（SQLAlchemy のパラメータバインドのみ） |
| ゲストアカウントの大量生成 | §11.6（`/api/auth/guest` のIP単位レート制限） |
| 依存ライブラリの脆弱性 | §11.8（`pip-audit` / `npm audit`） |

## 11.2 通信・CORS

| 項目 | 仕様 |
|------|------|
| プロトコル | 本番は **HTTPS必須**（HTTPアクセスは 301 でHTTPSへリダイレクト）。ローカル開発のみ HTTP を許容 |
| HSTS | 本番で `Strict-Transport-Security: max-age=31536000` を付与 |
| CORS 許可オリジン | 環境変数 `CORS_ORIGINS`（カンマ区切り）で明示。**ワイルドカード `*` は本番で禁止** |
| CORS 資格情報 | `allow_credentials=False`（Cookie を使わないため） |
| 許可メソッド | `GET, POST, PUT, OPTIONS`（`DELETE` は未使用） |
| 許可ヘッダ | `Authorization, Content-Type` |
| 公開ヘッダ | `X-Request-ID`（クライアントの問い合わせ時にログと突合するため） |

- フロントとバックエンドは別オリジンでのデプロイを前提とする（本番構成は [tech_operations.md](tech_operations.md) §12.1）

## 11.3 入力バリデーション方針

- **サーバー側の検証が唯一の防御線**。フロントの入力検証は UX 目的であり、セキュリティ上は存在しないものとして扱う
- 全リクエストボディを Pydantic v2 で型・範囲検証する。スキーマは `extra="forbid"`（未知フィールドは 422 で拒否）
- 文字列連結によるSQL構築を禁止（SQLAlchemy のパラメータバインドのみ）

| 対象 | 制約 |
|------|------|
| `quantity`（購入・売却） | 1〜99 の整数 |
| `targetFloor` | `1 <= targetFloor <= min(塔別 highestFloor + 1, 総階数)`（[tech_api.md](tech_api.md)「操作系」が正） |
| `hpThreshold` / `potionThreshold` | 0〜1 の小数（刻みは仕様どおり） |
| `memberIds` | 配列長 ≤ 4、重複禁止 |
| `activeSlots` | 配列長 ≤ 2 |
| `equipmentIds`（一括売却） | 配列長 ≤ 100 |
| `points`（転生投資） | 1以上、保有ポイント以下 |
| リクエストボディ最大サイズ | 64KB（超過は 413） |
| 文字列長 | メール 254文字、パスワード 8〜128文字 |

## 11.4 サーバー権威の徹底（チート対策）

クライアントから受け取ってはならない値を明示する。**受け取った場合は無視するのではなく 422 で拒否**する（`extra="forbid"` により自動的に拒否される）。

| 受け取らない値 | 理由 |
|--------------|------|
| ダメージ量・戦闘結果・撃破数 | 戦闘計算はサーバーのみ（アーキテクチャ不変条件） |
| 獲得ゴールド・EXP・ドロップ品 | 報酬付与は tick 処理内のみ |
| 経過時間・タイムスタンプ | 時刻はサーバーの UTC のみを基準にする（[tech_architecture.md](tech_architecture.md) 同時実行制御） |
| プレイヤーLV・ステータス値 | すべて派生値としてサーバーで再計算する |
| 価格・必要素材数 | マスターデータをサーバー側で参照する |

- 開発時フォールバック（`useBattleLocal.ts`）は**本番ビルドで必ず無効化**する。`api/client.ts` の `USE_API` は `import.meta.env.PROD` が真のとき強制的に `true` とし、環境変数で上書きできないようにする
- 上記フォールバックはフロント内の表示にのみ影響し、サーバーの状態を書き換える経路を持たない

## 11.5 認可（オーナーシップ検証）

| 項目 | 仕様 |
|------|------|
| 既定 | ID を引数に取る全APIで「そのリソースが認証ユーザーのものか」を検証する |
| 対象ID | `equipmentId`, `characterId`, `itemId`, `facilityId`, `materialCharacterId` |
| 他人のリソース指定時 | **404 を返す**（403 だと「存在すること」を漏らすため） |
| 状態依存の拒否 | ロック中装備の売却・分解、パーティ編成中キャラの限界突破素材化は 400 で拒否 |
| 認証必須の既定 | 全エンドポイントで認証必須。例外は [tech_api.md](tech_api.md) の共通仕様に一覧化する |

- 検証は `dependencies.py` の共通依存で行い、各ルーターに実装を散らさない

## 11.6 レート制限

| 対象 | 制限 | 単位 |
|------|------|------|
| `POST /api/auth/login` | 5回/分 かつ 10回/時 | IP + 対象アカウント |
| `POST /api/auth/register` | 3回/時 | IP |
| `POST /api/auth/password-reset/request` | 3回/時 | IP + メールアドレス |
| `POST /api/auth/guest` | 5回/時 | IP |
| `POST /api/battle/tick` | 20回/分 | ユーザー |
| その他の認証済みAPI | 60回/分 | ユーザー |

- 超過時は **429** + エラーコード `RATE_LIMIT_EXCEEDED` + `Retry-After` ヘッダ（秒）
- ログイン失敗はアカウントロックではなく**遅延（レート制限）で対処**する。ロックアウトは第三者による意図的なロックに悪用されうるため採用しない
- カウンタはプロセス内メモリで保持する（単一インスタンス前提。水平分割時は Redis 等が必要になる旨を明記）
- `/api/battle/tick` の制限は正常系のポーリング（1回/分）に対して十分な余裕があり、多重タブでも到達しない

## 11.7 クライアント側の保護

| 項目 | 仕様 |
|------|------|
| アクセストークン | メモリ（Pinia）保持のみ。永続化しない |
| リフレッシュトークン | LocalStorage 保存。**XSS で窃取されうるリスクを受容**する（Cookie + CSRF対策よりも実装が単純で、被害範囲がゲームデータに限定されるため） |
| リスク緩和 | ローテーション + 不正検知（revoked トークン使用で全トークン失効）により、窃取後の悪用期間を短縮する |
| XSS 対策 | Vue のテキスト補間（自動エスケープ）のみを使用。`v-html` の使用を禁止する |
| CSP | `default-src 'self'` を基本とし、インラインスクリプトを使わない |
| 外部スクリプト | 解析タグ・広告等の第三者スクリプトを読み込まない |

## 11.8 秘密情報・依存関係の管理

| 項目 | 仕様 |
|------|------|
| 保存場所 | すべて環境変数。`.env` は **Git 管理外**（`.env.example` に変数名と説明のみをコミット） |
| 対象 | `JWT_SECRET`, `GOOGLE_CLIENT_SECRET`, SMTP認証情報, `DATABASE_URL` |
| `JWT_SECRET` | 32バイト以上のランダム値。環境ごとに別値 |
| 秘密鍵のローテーション | ローテーション時は既存の全アクセストークンが無効化される（利用者は再ログインが必要）。実施は計画メンテナンス扱い |
| ソースへの直書き | 禁止（既定値を持つのは非機密の設定値のみ） |
| 依存脆弱性 | `pip-audit`（backend）・`npm audit`（frontend）を製造完了ゲートで実行し、High 以上は対応する |
