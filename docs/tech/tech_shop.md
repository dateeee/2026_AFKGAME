# AFK GAME — 日替わりショップ処理

> [tech_spec.md](tech_spec.md) 配下の詳細設計。ゲーム仕様は [systems/economy.md §2.5](../design/systems/economy.md)、装備カテゴリは [systems/equipment.md §2.4](../design/systems/equipment.md)、乱数規約は [tech_rng.md](tech_rng.md)、丸め規約は [tech_numeric.md](tech_numeric.md)。
> 本書は Phase 2 の日替わりショップ（品揃えの生成・24時間更新・購入）を定める。常設商品（ポーション）の購入は本書の対象外。

---

## 1. 適用範囲と方針

| 項目 | 仕様 |
|------|------|
| 更新方式 | **遅延評価**。定期ジョブを持たず、`GET /api/shop/lineup` と `POST /api/shop/buy` の入口で鮮度を判定する（[tech_operations.md §12.6](tech_operations.md)） |
| 更新境界 | UTC日付の変わり目（00:00 UTC） |
| 枠数 | 5枠固定（武器2・防具2・アクセサリー1） |
| 在庫 | 各枠1個。購入すると次の更新まで売り切れ |
| 永続化 | 生成結果をDBへ保存する。RNGの内部状態は保存しない（[tech_rng.md §2](tech_rng.md)） |
| RNG | `random.Random` のインスタンスを引数で受け取る（グローバル `random.*` の直呼び禁止） |
| HP吸収 | 付与しない（ショップ販売なし。[systems/equipment.md §2.4](../design/systems/equipment.md)） |
| 強化値 | 常に 0 |

## 2. 品揃えの生成

### 2.1 鮮度判定（入口条件）

1. プレイヤーの日替わりショップ状態（`ShopDailyState`）を読む
2. 次のいずれかに当たれば**再生成**する
   - 状態が無い（未生成）
   - 現在時刻が保存されているリセット時刻**以降**（`now >= reset_at`）
3. 再生成では既存の5枠を全件削除してから作り直し、リセット時刻を更新する。売り切れ状態も解除される
4. 現在時刻がリセット時刻より前なら、保存済みの枠をそのまま使う

- リセット時刻は生成時に「**現在のUTC日付の翌日 00:00:00Z**」として確定させる。24時間以上あいた場合も再生成は1回で済み、次のリセットは常に直近の 00:00 UTC になる
- 判定は `>=`（リセット時刻ちょうどは再生成する側）

### 2.2 枠とカテゴリ

| 枠番号 | カテゴリ | 候補スロット |
|-------|---------|------------|
| 0・1 | 武器 | 武器 |
| 2・3 | 防具 | 盾・頭・胴体・腕・腰・足 |
| 4 | アクセサリー | 耳・指輪 |

枠番号は固定で、購入時の `dailySlotIndex` に対応する。生成は枠番号の昇順に行う。

### 2.3 レアリティ抽選

解放帯は到達階層で決まる（[economy.md §2.5](../design/systems/economy.md)）。帯の中の出現率を次のとおり定める（**仮置き**。調整は [balance_backlog.md](../balance_backlog.md)）。

| 最高到達階層 | コモン | アンコモン | レア |
|------------|-------|----------|------|
| 5F未満（未到達の0Fを含む） | 100% | — | — |
| 5F〜14F | 70% | 30% | — |
| 15F以上 | 55% | 30% | 15% |

抽選手順（枠ごとに1回）:

1. プレイヤーの最高到達階層（塔をまたいだ最大値）から行を選ぶ
2. `r = rng.random()`（`[0,1)`）を1回引く
3. **レア → アンコモン → コモン**の順に確率を累積し、`r < 累積値` を満たした最初のレアリティを採る（[tech_rng.md §1](tech_rng.md) の `r < p` 規約）
4. どれにも該当しなかった場合はコモンとする（浮動小数誤差の受け皿）

### 2.4 ベース装備の抽選

1. 枠のカテゴリに属する全ベース装備を候補にする
2. **同一カテゴリの先行枠で選ばれたベースを候補から除く**（同じカテゴリ内に同じ品が並ばない）
3. 候補をベースID昇順に並べ、離散一様で1件選ぶ
4. 選ばれたベースのスロットを、その枠のスロットとする

- 候補数はカテゴリごとに 武器7・防具6・アクセサリー2 で、いずれも枠数（2・2・1）を上回るため候補が尽きることはない
- 両手武器も抽選対象に含む（盾との排他は購入後の装備時に判定する）

### 2.5 ステータス算出

| # | 項目 | 式・規則 |
|---|------|---------|
| 1 | 装備レベル `L` | `max(1, 最高到達階層)` |
| 2 | 基礎値 `B` | `floor(L × 1.5 + 2)` |
| 3 | 付与ステータス数 `N` | レアリティ別の付与数の範囲から離散一様で決める |
| 4 | 付与するステータス種 | `ATK → DEF → HP → SPD` の順に並べた候補から `N` 種を非復元で抽選する |
| 5 | 各ステータス値 | `max(1, floor(B × レアリティ倍率 × ステータス補正 × 0.7))` |
| 6 | 非付与のステータス | `null` |

- レアリティ倍率と付与ステータス数の範囲は [systems/equipment.md §2.4](../design/systems/equipment.md) の「レアリティ」表、ステータス補正（ATK／DEF／HP／SPD）は [master/equipment.md §6.1](../data/master/equipment.md) が正。本書では値を再掲しない
- `0.7` は**ショップ性能係数**。「ドロップ品の約70%の性能」（economy.md §2.5）を数値化したもの
- 丸めは最後に1回だけ行う（[tech_numeric.md §1](tech_numeric.md)）。中間結果を丸めない

### 2.6 価格

レアリティ×カテゴリの固定価格（[economy.md §2.5](../design/systems/economy.md) の価格テーブルが正）。装備レベル・到達階層には依存しない。価格は生成時に確定して枠へ保存する。

## 3. 購入処理

入口条件: 認証済みで `dailySlotIndex` を指定していること。進行状態は問わない（[tech_state.md §4](tech_state.md)）。

1. 鮮度判定（§2.1）を行う。日付を跨いでいれば再生成し、**再生成後の品揃え**に対して以降を処理する
2. `dailySlotIndex` が 0〜4 の範囲外 → `422`
3. 該当枠が売り切れ → `400 SHOP_ITEM_SOLD_OUT`
4. 所持ゴールドが価格に満たない → `400 SHOP_INSUFFICIENT_GOLD`（状態は変更しない）
5. 所持ゴールドから価格を引く
6. 枠の内容（ベース・スロット・レアリティ・レベル・各ステータス）で装備を1件作成し、プレイヤーの所持装備に加える。強化値0・ロックなし・HP吸収なし
7. 枠を売り切れにする
8. 手順5〜7を1トランザクションでコミットする。途中で失敗した場合は全件ロールバックする

出口条件: ゴールド減算・装備付与・売り切れ化の3つがすべて成立しているか、いずれも起きていないかのどちらか。

**リクエストの排他**:

| `itemId` | `dailySlotIndex` | 扱い |
|---------|-----------------|------|
| あり | なし | 常設商品の購入（既存フロー） |
| なし | あり | 日替わり商品の購入（本節） |
| あり | あり | `422` |
| なし | なし | `422` |

## 4. データ構造

親（更新サイクル）と子（5枠）の2テーブルで保存する（ER図: [er_diagram/item.md](../../diagrams/er_diagram/item.md)）。

**`ShopDailyState`** — プレイヤーごとに1件

| カラム | 型 | 内容 |
|-------|-----|------|
| `id` | UUID | 主キー |
| `player_id` | FK | 所有プレイヤー |
| `reset_at` | 日時 | 次回リセット時刻（UTC・翌日 00:00:00Z） |

**`ShopDailySlot`** — 状態1件につき5件

| カラム | 型 | 内容 |
|-------|-----|------|
| `id` | UUID | 主キー |
| `shop_daily_state_id` | FK | 親の状態 |
| `slot_index` | 整数 | 枠番号 0〜4 |
| `base_id` | 文字列 | ベース装備ID |
| `category` | 文字列 | `weapon` / `armor` / `accessory` |
| `rarity` | 文字列 | レアリティ |
| `level` | 整数 | 装備レベル |
| `stat_atk` `stat_def` `stat_hp` `stat_spd` | 整数 / NULL | 付与ステータス |
| `price` | 整数 | 価格 |
| `sold` | 真偽 | 購入済みフラグ |

- 抽選結果（レアリティ・レベル・ステータス）は**生成時に確定して保存する**。表示した内容と購入結果を一致させるため、購入時に引き直さない
- 装備スロットと両手武器フラグは `base_id` からマスターデータで一意に定まるため保存しない
- `(shop_daily_state_id, slot_index)` の組で一意

## 5. API

### GET /api/shop/lineup

常設（既存の `lineup`）に加えて日替わり枠と次回更新時刻を返す。

```json
{
  "lineup": [ /* 常設商品（既存） */ ],
  "daily": [
    {
      "slotIndex": 0, "category": "weapon", "baseId": "sword", "name": "剣",
      "slot": "weapon", "rarity": "uncommon", "level": 20,
      "statAtk": 22, "statDef": null, "statHp": null, "statSpd": null,
      "price": 1500, "soldOut": false
    }
  ],
  "dailyResetAt": "2026-08-03T00:00:00Z"
}
```

- `daily` は常に5件（売り切れの枠も残す。フロントは `soldOut` で「売り切れ」表示に切り替える）
- 残り時間はフロント側で `dailyResetAt` との差から求める（サーバーは秒数を返さない）

### POST /api/shop/buy

`dailySlotIndex`（整数 0〜4）を追加する。日替わり購入時のレスポンスは購入後のゴールドと、付与した装備を返す。

```json
{ "status": "ok", "gold": 8500, "equipment": { /* 付与した装備1件 */ } }
```

## 6. 分岐一覧（品揃えの生成）

| # | 分岐点 | 条件 | 期待する振る舞い |
|---|-------|------|----------------|
| 1 | 鮮度判定 | 状態が未生成 | 5枠を新規生成し、リセット時刻を保存する |
| 2 | 鮮度判定 | 現在時刻がリセット時刻より前 | 保存済みの5枠をそのまま使う |
| 3 | 鮮度判定 | 現在時刻がリセット時刻を過ぎている | 既存枠を全件削除して5枠を再生成し、リセット時刻を更新する（売り切れも解除される） |
| 4 | 鮮度判定 | 現在時刻がリセット時刻ちょうど | 再生成する（境界は再生成側） |
| 5 | 解放帯 | 最高到達階層が5F未満 | コモンのみから抽選する |
| 6 | 解放帯 | 最高到達階層が5F以上15F未満 | コモン・アンコモンから抽選する |
| 7 | 解放帯 | 最高到達階層が15F以上 | コモン・アンコモン・レアから抽選する |
| 8 | レアリティ抽選 | 乱数が最上位レアリティの確率未満 | 最上位のレアリティを採る |
| 9 | レアリティ抽選 | 乱数が中位の累積確率未満 | 中位のレアリティを採る |
| 10 | レアリティ抽選 | 乱数がどの累積確率にも該当しない | コモンを採る |
| 11 | ベース抽選 | 同一カテゴリの先行枠が未確定（各カテゴリの1枠目） | 候補を除外せずに抽選する |
| 12 | ベース抽選 | 同一カテゴリの先行枠が確定済み（2枠目） | 先行枠のベースを候補から除いて抽選する |
| 13 | 装備レベル | 最高到達階層が0 | 装備レベル1として算出する |
| 14 | 装備レベル | 最高到達階層が1以上 | 到達階層をそのまま装備レベルにする |
| 15 | 付与数 | レアリティの下限を引いた（例: コモン） | 下限の種数だけ付与し、残りは `null` にする |
| 16 | 付与数 | レアリティの上限を引いた（例: レア） | 上限の種数だけ付与し、残りは `null` にする |
| 17 | ステータス値 | 算出値が1未満 | 1に切り上げる |
| 18 | ステータス値 | 算出値が1以上 | `floor` した値をそのまま採る |
| 19 | HP吸収 | 生成時（常に） | 付与しない（`null`） |
| 20 | 枠の生成ループ | 5枠すべて | 武器2・防具2・アクセサリー1の内訳で生成する |
| 21 | 価格決定 | カテゴリとレアリティの組 | 価格テーブルの該当値を枠に保存する（レベル・到達階層では変えない） |

## 7. 分岐一覧（購入・取得）

| # | 分岐点 | 条件 | 期待する振る舞い |
|---|-------|------|----------------|
| 1 | リクエスト種別 | `itemId` のみ指定 | 常設購入として既存フローで処理する |
| 2 | リクエスト種別 | `dailySlotIndex` のみ指定 | 日替わり購入として処理する |
| 3 | リクエスト種別 | 両方を指定 | `422` を返す |
| 4 | リクエスト種別 | どちらも未指定 | `422` を返す |
| 5 | 枠番号 | 0〜4の範囲内 | 購入処理を続行する |
| 6 | 枠番号 | 範囲外 | `422` を返す |
| 7 | 在庫 | 未購入 | 購入処理を続行する |
| 8 | 在庫 | 売り切れ | `400 SHOP_ITEM_SOLD_OUT` を返す |
| 9 | 所持ゴールド | 価格以上 | 減算して装備を付与し、枠を売り切れにする |
| 10 | 所持ゴールド | 価格未満 | `400 SHOP_INSUFFICIENT_GOLD` を返し、状態を変更しない |
| 11 | 購入時の鮮度 | リセット時刻を過ぎていない | 保存済みの枠に対して購入する |
| 12 | 購入時の鮮度 | リセット時刻を過ぎている | 再生成した枠に対して購入する |
| 13 | 品揃え取得 | 全枠が未購入 | 5件すべてを `soldOut=false` で返す |
| 14 | 品揃え取得 | 一部が購入済み | 該当枠のみ `soldOut=true` で返す |
| 15 | 品揃え取得 | 全枠が購入済み | 5件すべてを `soldOut=true` で返す（枠は消さない） |
| 16 | 次回更新時刻 | 取得時（常に） | 現在のUTC日付の翌日 00:00:00Z を返す |
| 17 | 購入の永続化 | 装備付与・ゴールド減算・売り切れ化の途中で失敗 | 全件をロールバックし、いずれの変更も残さない |
